Robot Learning 的知识框架

Encoder、decoder、latent space、token、transformer、distillation、diffusion、VLA。这些词看起来各自很深，其实背后只有很少几个想法，而且大部分能对应到你在控制、估计和线性代数里已经会的东西。这一页不把任何一种方法讲完，只做一件事：给出一个框架，让每个词都有固定的位置，每个 robot learning 系统都能用同一套问题拆开。

读完应该能做到三件事。看到一个新词，能说出它在回答四个问题里的哪一个。看到一个系统（locomotion policy、Diffusion Policy、VLA），能画出数据怎么流、loss 是什么、数据从哪来。知道哪些结论有数学支撑，哪些只是经验上好用。

一句话版本Learning 的所有方法共用一个模板：选一个带参数的函数，定义什么叫"好"，喂数据，用梯度下降调参数。术语之间的差别只出现在四个地方：函数的形状、"好"的定义、数据的来源、输入输出的格式。

01总图：四个问题

这一节回答：那么多术语，有没有一张图能把它们全部放进去？

几乎所有 deep learning 方法都在解同一个优化问题：

\[ \theta^\star = \arg\min_\theta \; \mathbb{E}_{(x,\,y)\sim \mathcal{D}} \Big[\, \mathcal{L}\big(f_\theta(x),\; y\big) \Big] \]
\(f_\theta\)带参数的函数，也就是神经网络；\(\theta\) 是它的全部参数（weights） \(x,\ y\)输入，以及希望的输出（target） \(\mathcal{D}\)数据的分布；实际中用采到的有限个样本代替 \(\mathcal{L}\)loss，衡量输出和目标差多少

这个式子里有四样东西可以选。每个术语都是其中一个选择的名字：

Q1 · ARCHITECTURE

函数 \(f_\theta\) 长什么样

MLP、CNN、Transformer。Encoder、decoder、backbone、head 是函数内部各部分的角色名。→ Part C

Q2 · OBJECTIVE

"好"怎么定义

Supervised、self-supervised、contrastive、generative、imitation、RL、distillation。区别在于 \(y\) 从哪来、\(\mathcal{L}\) 怎么写。→ Part D

Q3 · DATA

数据 \(\mathcal{D}\) 从哪来

人工标注、互联网、simulation、teleoperation、机器人自己的经验。对机器人来说这通常是最紧的约束。→ Part E

Q4 · INTERFACE

\(x\) 和 \(y\) 是什么格式

Token、patch、embedding、latent、action chunk。把图像、语言、动作变成网络能处理的统一格式。→ Part B

第五件事所有方法都一样，所以不算一个选择：怎么解这个优化问题。答案永远是 backpropagation 算梯度，SGD 或 Adam 更新参数（Part A）。

PART A

First principles

所有范式共用的地基：拟合、梯度、likelihood、信息量、泛化。数学上需要的只有链式法则、高斯分布和三个信息论的量。

02Learning 就是拟合函数

这一节回答："训练一个网络"到底在做什么，和我做过的参数辨识有什么不同？

你其实已经做过 learning。Camera calibration 是：选一个带参数的模型（pinhole model 的内参和畸变系数），定义误差（reprojection error），找让误差最小的参数。System identification 是同一件事，模型换成了动力学方程，参数换成了质量、惯量和摩擦。

Deep learning 只改了一处：模型不再从物理推出来，而是换成一个非常灵活的通用函数，参数从几个变成几十万到几十亿个。这一处改动带来三个后果：

  • 没有 closed-form 解。线性的 least squares 可以用 SVD 一步解出来，因为误差对参数是二次的。Calibration 这类 nonlinear least squares 其实已经要迭代了，用的是 Gauss–Newton 或 Levenberg–Marquardt。神经网络的 loss 对参数高度非凸，参数又多到用不起二阶方法，只能从一个初值出发沿梯度迭代，也就是 gradient descent。
  • 参数没有物理含义。你不能检查"质量估得对不对"，只能看输出对不对。这是 learning 方法难以解释、难以给保证的根源。
  • 函数灵活到能拟合任何东西，包括噪声。所以"在没见过的数据上还行不行"（generalization）成了核心问题，这在参数辨识里几乎不用担心。

最简单的通用函数：MLP

MLP（multilayer perceptron）就是线性变换和 nonlinearity 交替叠起来：

\[ h_{l} = \sigma\big(W_l\, h_{l-1} + b_l\big),\qquad h_0 = x,\qquad f_\theta(x) = W_L\, h_{L-1} + b_L \]
\(W_l,\ b_l\)第 \(l\) 层的 weight 矩阵和 bias 向量；所有层的 \(W, b\) 合起来就是 \(\theta\) \(h_l\)第 \(l\) 层的输出，叫 hidden activation，也就是后面说的 feature \(\sigma\)逐元素的 nonlinearity，例如 ReLU \(\max(0,\cdot)\)、tanh、GELU

Nonlinearity 不能省：没有它，多层矩阵相乘还是一个矩阵，整个网络退化成线性回归。

Universal approximation theorem 说：只有一个 hidden layer、但足够宽的 MLP，可以在有界的区域上把任何连续函数逼近到任意精度（要求 nonlinearity 不是多项式，ReLU 和 tanh 都满足）。这句话经常被过度解读。它只说"存在这样一组参数"，没有说需要多宽，没有说 gradient descent 能找到它，也没有说找到的函数在训练点之外是对的。这三件事要分开看：

问题名字由什么决定
函数族里有没有足够好的函数Capacity / expressivity网络的大小和结构
优化能不能找到它Optimization初始化、learning rate、normalization、residual connection（第 03 节）
找到的函数在新数据上对不对Generalization数据量和覆盖范围、inductive bias、regularization（第 06 节）

试试看：① "网络太小"：只有 13 个参数，train loss 停在噪声方差的两倍左右就不动了，曲线弯不过来。这是 capacity 不够（underfitting）。② "网络大、数据少"：1153 个参数拟合 10 个带噪声的点，train loss 一路降到接近 0，曲线穿过每一个点；validation loss 却停在噪声方差的三四倍。这是 overfitting。③ 最后一个预设：同一个网络、同样的噪声，数据从 10 个加到 200 个，两条曲线都贴着 σ²。数据是最有效的 regularizer。④ 回到"大小合适"，把 hidden width 改成 16 再训练：到后期 validation loss 会掉头向上。Capacity 够、训练够久，小数据集里的噪声迟早会被记住，所以实际训练要盯着 validation loss，在它最低的时候停下（early stopping）。

绿色虚线是噪声的方差 \(\sigma^2\)。它是 validation loss 的理论下限：就算网络学到了完全正确的函数，新样本上的平均误差也有这么大。Train loss 掉到这条线以下，唯一的解释是网络记住了训练样本里的噪声。

记住这三句Loss 降不下去，先怀疑 capacity 或 optimization。Train loss 低而 validation loss 高，是 generalization 的问题，先加数据。这两种病的药方相反，所以每次训练都要同时看两条曲线。

03Gradient descent 与 backpropagation

这一节回答：几十亿个参数的梯度是怎么算出来的，为什么深的网络曾经训不动？

Gradient descent 和它的两个变体

\[ \theta \leftarrow \theta - \eta\, \nabla_\theta \mathcal{L}(\theta) \]

沿着 loss 下降最快的方向走一小步，\(\eta\) 是 learning rate，是最重要的一个超参数。实际用的是两个变体：

  • SGD（stochastic gradient descent）：每一步只用一小批样本（minibatch）估计梯度。便宜得多，估计带噪声，但期望是对的。
  • Adam：给每个参数维护梯度的滑动平均和梯度平方的滑动平均，用后者归一化步长。效果是每个参数有自己的有效 learning rate，对梯度尺度不敏感。Transformer 几乎都用它的变体 AdamW。

Backpropagation 就是链式法则，按一个特定的顺序算

把网络写成一串函数的复合：\(h_l = f_l(h_{l-1};\theta_l)\)，最后 \(\mathcal{L} = \ell(h_L, y)\)。链式法则给出：

\[ \frac{\partial \mathcal{L}}{\partial \theta_l} \;=\; \underbrace{\frac{\partial \mathcal{L}}{\partial h_L}\, J_L\, J_{L-1} \cdots J_{l+1}}_{\delta_l \;=\; \partial \mathcal{L}/\partial h_l}\; \frac{\partial h_l}{\partial \theta_l}, \qquad J_k = \frac{\partial h_k}{\partial h_{k-1}} \]
\(J_k\)第 \(k\) 层的 Jacobian：这一层的输出对输入的导数 \(\delta_l\)loss 对第 \(l\) 层输出的梯度，一个 row vector

关键在计算顺序。从右往左算，每一步都是"一个 row vector 乘一个矩阵"：\(\delta_{l-1} = \delta_l\, J_l\)。整个过程从不需要把 Jacobian 矩阵显式写出来，只需要每一层会算 vector-Jacobian product。

为什么这个顺序重要：loss 是一个数，参数有几十亿个。从输出端往回传（reverse mode），一趟就拿到全部梯度。如果从输入端往前推（forward mode），每个参数都要单独推一趟。Deep learning 在计算上可行，靠的就是这个不对称。

对应到你熟悉的东西

  • 机械臂的 Jacobian。\(\dot{x} = J(q)\,\dot{q}\) 是 forward mode：把输入端的扰动推到输出端。\(\tau = J(q)^\top F\) 是 reverse mode：把输出端的量拉回输入端。Backprop 就是一连串的 \(J^\top\)。
  • Optimal control 的 costate。把时间步当成层，backward 递推 \(\lambda_t = \partial \ell/\partial x_t + (\partial f/\partial x_t)^\top \lambda_{t+1}\) 和 backprop 是同一个算法。控制领域在 1960 年代初就在用它（Kelley、Bryson），比它在神经网络里流行早二十多年。iLQR 的 backward pass 也是这个结构。
  • BPTT（backpropagation through time）。对 RNN 或对一段 dynamics rollout 求导，就是把网络层和时间步串成一条更长的链。Differentiable simulation 和 SuperMimic 里对 world model 求导都是这件事。

为什么深网络曾经训不动：一长串 Jacobian 的乘积

\(\delta_0 = \delta_L\, J_L J_{L-1}\cdots J_1\)。这和线性系统 \(x_{t+1} = A x_t\) 是同一个问题：如果每个 \(J\) 都把向量缩小一点，乘几十次以后梯度趋近于零（vanishing gradient），前面的层学不动；如果都放大一点，梯度爆炸（exploding gradient）。现代网络能做到上百层，靠的是三个专门控制这个乘积的设计：

设计做了什么为什么有用
Residual connection\(h_l = h_{l-1} + g_l(h_{l-1})\)Jacobian 变成 \(I + \partial g_l/\partial h\)，梯度始终有一条 identity 的直通路径。ResNet（2015）让上百层的网络变得容易训练；Transformer 的每个 block 都是这个结构。
Normalization把每层的输出重新缩放到固定的尺度（BatchNorm、LayerNorm）阻止 activation 的尺度逐层漂移，间接控制 Jacobian 的增益。
Initialization按层的宽度选初始 weight 的方差（Xavier、He）让训练开始时每层的增益接近 1。

LSTM 和 GRU 里的 gate 是同一个想法在时间方向上的版本。BPTT 的 horizon 不能随便加长也是同一类原因：SuperMimic 里 imagination horizon 从 32 加到 64、128，训练反而更慢、return 更低。

深一层：非凸优化为什么能行 Loss 对参数是非凸的，gradient descent 理论上只能保证找到一个 stationary point。但实践中，足够大的网络几乎总能把 train loss 降到很低，而且不同随机种子找到的解性能相近。目前的解释都是部分的：高维空间里的 stationary point 大多是 saddle point，SGD 的噪声能离开它们；overparameterized 的网络有大量等价的好解。这是一个"工程上可靠、理论上没讲完"的地方，坦率接受就行。

04Loss 从哪来：maximum likelihood

这一节回答：MSE、cross-entropy 这些 loss 是随手选的吗？选错了会怎样？

不是随手选的。几乎所有 loss 都来自同一个原则：让网络输出一个概率分布 \(p_\theta(y\mid x)\)，然后选参数，使得真实数据在这个分布下出现的概率最大（maximum likelihood estimation，MLE）。取负对数把连乘变成求和，就得到要最小化的 loss：

\[ \theta^\star = \arg\max_\theta \prod_i p_\theta(y_i\mid x_i) \;=\; \arg\min_\theta \sum_i -\log p_\theta(y_i\mid x_i) \]

你假设输出服从什么分布，就得到什么 loss：

假设的分布网络输出什么\(-\log p\) 化简后最优解是数据的机器人里出现在
Gaussian，方差固定均值 \(\mu_\theta(x)\)\(\lVert y-\mu_\theta(x)\rVert^2\)，即 MSE条件均值 \(\mathbb{E}[y\mid x]\)早期的 behavior cloning；world model 预测下一个 state；distillation
Laplace中位数\(\lvert y-\mu_\theta(x)\rvert\)，即 L1条件中位数ACT
Categorical（离散）每个类别的 logit，过 softmax\(-\log p_\theta(y\mid x)\)，即 cross-entropy给定 \(x\) 时各类别的真实频率LLM 预测下一个 token；RT-2、OpenVLA 预测 action token
Gaussian，均值和方差都学\(\mu_\theta(x),\ \sigma_\theta\)带方差权重的平方误差加 \(\log\sigma\)均值和不确定度PPO 的 stochastic policy

Softmax 把任意一组实数（logits）\(z\) 变成概率：\(p_i = e^{z_i}/\sum_j e^{z_j}\)。它是"离散分布的输出层"，后面在 attention 和 contrastive learning 里会反复出现。

对应到你熟悉的东西 State estimation 里"Gaussian 噪声下的 MLE 等于 weighted least squares"是同一个推导。再进一步：给参数加一个 Gaussian prior 做 MAP，就多出一项 \(\lambda\lVert\theta\rVert^2\)，这就是 L2 regularization，也是 weight decay 的来源（两者在普通 SGD 下等价，在 Adam 下不等价，所以才有 AdamW）。

选错分布的后果：MSE 会把多个答案平均掉

MSE 背后的假设是"给定输入，正确输出只有一个，其余是 Gaussian 噪声"。当数据里同一个输入对应多个都正确的输出时，这个假设就错了。经典例子：机械臂要绕过正前方的障碍物，示范里一半从左绕，一半从右绕。MSE 的最优解是两者的平均，也就是直直撞上去。

这叫 mode averaging，是 2022 到 2023 年起 robot policy 的输出端从"回归一个向量"换成 diffusion、flow matching 和离散 token 的直接原因。第 14 节的实验 5 会让你亲眼看到它，以及 generative model 是怎么避开它的。

记住这一句选 loss 就是在选"我假设输出的分布长什么样"。看到一个 policy 的输出头（Gaussian、256 个 bin、diffusion），先问它假设的 action 分布是单峰还是多峰。

05信息论与压缩

这一节回答：为什么大家说 learning 和压缩有关？Entropy、cross-entropy、KL 各自在量什么？

你的直觉是对的，而且这个联系可以说得很精确。需要的只有三个量。先定义"意外程度"：一个概率为 \(p(x)\) 的事件发生了，它带来的信息量是 \(-\log_2 p(x)\) bit。概率越小越意外，信息量越大。

\[ H(p) = -\sum_x p(x)\log p(x) \qquad H(p,q) = -\sum_x p(x)\log q(x) \qquad D_{\mathrm{KL}}(p\,\Vert\, q) = \sum_x p(x)\log\frac{p(x)}{q(x)} \]
\(H(p)\)Entropy：按真实分布 \(p\) 取样，平均的意外程度。也是给这些样本编码所需的最少平均 bit 数。 \(H(p,q)\)Cross-entropy：数据来自 \(p\)，但你按模型 \(q\) 来编码，平均要用多少 bit。 \(D_{\mathrm{KL}}(p\Vert q)\)KL divergence：因为用了错的分布 \(q\) 而多花的 bit。恒 \(\ge 0\)，当且仅当 \(q=p\) 时为 0。

三者的关系只有一条：\(H(p,q) = H(p) + D_{\mathrm{KL}}(p\Vert q)\)。训练时 \(p\) 是数据，\(q_\theta\) 是模型，\(H(p)\) 和 \(\theta\) 无关，所以：

最小化 cross-entropy ＝ 最小化 KL(数据 ‖ 模型) ＝ maximum likelihood。三个名字，同一件事。

实验 2：拖动分布，看三个量怎么变

设想模型要预测 "pick up the red ___" 的下一个词。蓝色是数据里的真实分布 \(p\)，橙色是模型的预测 \(q\)。上下拖动任意一根柱子。

预设：

p：数据的真实分布　q：模型的预测

Entropy \(H(p)\) Cross-entropy \(H(p,q)\) \(D_{\mathrm{KL}}(p\Vert q)\) \(D_{\mathrm{KL}}(q\Vert p)\)

试试看：① "让 q = p"：KL 变成 0，但 cross-entropy 不是 0，剩下的就是 \(H(p)\)，数据本身的不确定性，任何模型都消不掉。② "q 很自信但错了"：模型给真实答案的概率接近 0，cross-entropy 急剧变大。Cross-entropy 对"自信的错误"惩罚极重。③ "one-hot label"：\(H(p)=0\)，cross-entropy 退化成 \(-\log q(\text{正确答案})\)，这就是分类任务里你看到的 loss。④ 两个方向的 KL 不相等。

Prediction 就是 compression

Shannon 的 source coding theorem 给出无损压缩的下限 \(H(p)\)。而任何一个概率模型 \(q\) 配上 arithmetic coding 就是一个无损压缩器，平均码长约等于 cross-entropy \(H(p,q)\)。所以：

  • 语言模型的 training loss 可以直接读成"平均每个 token 要多少 bit"。训练语言模型，字面意义上就是在找能把文本压得最短的编码方式。
  • 想压得更短，模型必须利用数据里的规律：语法、事实、因果。对视频来说是物体的持续存在和运动规律。这是"预测得好就必须在某种程度上理解"这个说法的精确版本。

无损压缩有下限 \(H(p)\)。如果允许丢信息（lossy compression），问题变成 rate–distortion：给定只能用多少 bit（rate），重建误差（distortion）最小能到多少。Autoencoder 的 bottleneck 就是在限制 rate，第 08 节会看到 VAE 的 loss 正好是"distortion 加 rate"两项。

深一层：压缩得好，不等于对控制有用 压缩衡量的是"对整个数据分布建模得多好"。但对控制有用的信息只占输入的极小一部分：一张 224×224 的图有 15 万个数，而抓方块只需要它的位姿，6 个数。像素级的重建会把模型的 capacity 花在桌面纹理和光照上。这是 self-supervised learning 里一条长期的分歧：重建像素（MAE、video generation）还是只在 latent space 里预测（JEPA、contrastive）。它也解释了为什么很多 robot policy 的 vision encoder 最终要用 action loss 来 fine-tune：只有任务本身知道哪些信息该留。

KL 是不对称的，两个方向行为不同

假设真实分布 \(p\) 有两个峰，而模型 \(q\) 只能是一个单峰的 Gaussian：

Forward KL：\(D_{\mathrm{KL}}(p\Vert q)\)

\(p\) 有质量的地方 \(q\) 必须也有，否则惩罚无穷大。结果 \(q\) 变得很宽，盖住两个峰，均值落在中间。叫 mode-covering。Maximum likelihood 和 behavior cloning 做的是这个，这也是 mode averaging 的另一种说法。

Reverse KL：\(D_{\mathrm{KL}}(q\Vert p)\)

\(q\) 只需要待在 \(p\) 高的地方，漏掉一个峰不受罚。结果 \(q\) 选一个峰贴上去。叫 mode-seeking。Variational inference 和一部分 RL 算法做的是这个。

KL 之后会出现在这些地方：VAE 把 latent 的分布拉向 prior（第 08 节）；TRPO 和 PPO 限制每次 policy 更新不能离旧 policy 太远（第 15 节）；distillation 让 student 的输出分布靠近 teacher（第 16 节）。

06Generalization 与 distribution shift

这一节回答：训练好的模型在什么条件下可以信？为什么机器人上这个问题特别严重？

Supervised learning 的全部理论保证都建立在一个假设上：测试时的数据和训练数据来自同一个分布，而且样本之间相互独立（i.i.d.）。在这个假设下，训练样本越多，train loss 和真实误差就越接近。

一个经验上很可靠的说法是：网络在训练数据覆盖到的范围内表现可预期，在范围之外的行为没有任何保证。它擅长在见过的样本之间插值，不擅长外推。所以 robot learning 的大部分工程实践，都可以理解成同一个动作：想办法把训练分布扩大到能盖住部署时会遇到的情况。

Inductive bias：数据之外的知识从哪来

深一层：为什么参数比数据还多的网络不 overfit 经典的统计学习理论说，参数太多一定 overfit。实验 1 也确实展示了这一点。但现代大模型的参数量远超数据量，泛化却很好；甚至存在 double descent 现象：模型继续变大，test error 先升后降。目前的解释包括 SGD 的 implicit regularization（在所有能拟合数据的解里偏好"简单"的那些）和 overparameterization 让优化变容易。这仍然是活跃的研究问题，没有完整的理论。实用的结论是：现在很少靠缩小网络来防 overfit，而是靠增加数据的量和多样性。

Representation

Encoder、latent、feature、embedding、token 都在回答同一个问题：把原始输入变成什么样的向量，后面的计算才好做。

07Representation 是什么

这一节回答：Feature、embedding、latent 到底是不是一回事？什么叫"好的" representation？

它们是一回事：网络中间的一个向量，用来概括输入。下游的计算只能通过这个向量看到输入。不同的名字只反映它出现的场合：

名字通常在什么场合用
Feature感知网络中间层的输出。"image feature"指 vision backbone 输出的向量或向量网格。
Embedding一个离散对象（一个 token、一张图、一段文字）对应的向量。也指"查表得到向量"这个操作。
Latent生成模型或 autoencoder 里那个没有被直接观测到的变量，通常是 bottleneck 处的向量。
Hidden stateRNN 沿时间传递的向量；也泛指任意中间层的 activation。
Representation上面所有东西的统称。
Latent space / embedding space这些向量所在的空间。说"两个东西在 latent space 里很近"，就是它们的向量距离小。

好的 representation：让后面的问题变简单

判断标准很实用：在这个表示上，下游任务用很简单的函数就能解决。常用的度量叫 linear probe：把 encoder 冻住，只在它输出的 feature 上训练一个线性分类器，看能做到多好。原始像素上线性分类器几乎没用，好的 feature 上它能接近完整网络的水平。Deep learning 可以整体理解为：前面所有层负责把输入一步步变形，直到最后一层只需要做线性运算。

对应到你熟悉的东西：state 控制里的 state 有一个精确的定义：它是历史的 sufficient statistic，知道了它，过去的输入输出对预测未来就不再提供额外信息。好的 representation 是同一个意思的推广：保留对任务有用的一切，丢掉其余的。

Kalman filter 把全部历史观测压缩成均值和协方差，这就是一个人工设计的 encoder。机器人只能拿到 observation（POMDP）时，policy 需要从历史里估计出它需要的 state。RNN 的 hidden state、把过去 50 帧 proprioception 喂给一个小网络得到的向量，都是学出来的 state estimator，只是输出的不是有物理含义的量，而是一个只有下游网络看得懂的 latent。

为什么能压缩：manifold hypothesis

一张 224×224 的 RGB 图是 150,528 维空间里的一个点。但随机取一个点，得到的几乎一定是噪声。真实的图像只占这个空间里极小的一部分，而且这一部分可以用少得多的坐标来描述：对一个桌面场景，就是相机位姿、每个物体的位姿、光照等几十到几百个量。这个猜想叫 manifold hypothesis：高维的真实数据集中在一个低维 manifold 附近。

用机器人的话说：图像是 configuration \(q\) 和环境参数的一个非线性函数，encoder 在学这个函数的近似逆映射。Latent space 就是这个 manifold 上的一套坐标。下一节的实验 3 会把这句话画出来。

Embedding space 的几何

训练好的 embedding space 里，距离对应语义相似度，常用 cosine similarity 来量。这不是设计出来的，而是训练目标的副产品：如果两个输入在任务里可以互相替换，把它们映射到相近的向量就能降低 loss。CLIP 训练完以后，一张图片和描述它的文字的向量夹角很小，所以可以把"分类"做成"找最近的文字向量"，不需要任何分类数据（zero-shot）。

深一层：representation 不一定更小 "Encoder 就是压缩"这个说法不完全对。ViT-B/16 把一张 224×224 的图变成 196 个 768 维的 token，一共 150,528 个数，和输入的数值个数（224×224×3）完全相同（没算额外的 [CLS] token）。它没有降维，但信息被重新组织了：原来分散在像素里的"这是一个杯子"变成了可以被线性读出的方向。是否丢信息由训练目标决定，不由维度决定。真正的 bottleneck（故意限制信息量）是下一节的内容。

08Autoencoder 家族：从 PCA 到 VAE 到 VQ

这一节回答：Encoder–decoder–bottleneck 这个结构为什么能学到有用的东西？VAE、VQ-VAE 各加了什么？

起点是你已经会的 PCA

PCA 取数据协方差最大的 \(k\) 个方向 \(U_k\)，把（减去均值之后的）数据投影上去再乘回来：

\[ \underbrace{z = U_k^\top x}_{\text{encoder}} \qquad \underbrace{\hat{x} = U_k\, z}_{\text{decoder}} \qquad \min \sum_i \lVert x_i - \hat{x}_i\rVert^2 \]

这已经是一个完整的 autoencoder：encoder 和 decoder 都是线性的，loss 是重建误差，\(k\) 小于输入维度就是 bottleneck。Eckart–Young 定理保证 SVD 给出的是最优的线性解。反过来也成立：一个线性的 autoencoder 用 MSE 训练，学到的子空间就是 PCA 的子空间。

Autoencoder 是把这两个线性映射换成神经网络：\(z = E_\phi(x)\)，\(\hat{x} = D_\theta(z)\)，仍然最小化重建误差。PCA 只能用一个平面去贴数据；nonlinear autoencoder 可以用一个弯曲的面。

没有约束的 autoencoder 什么都学不到

如果 \(z\) 的维度不比 \(x\) 小，网络可以直接把输入原样抄过去，重建误差为零，representation 毫无用处。所以每一种 autoencoder 都要加一个约束，逼它不能照抄。整个家族的区别就在于用什么约束：

VAE：给 latent space 加一个概率结构

普通 autoencoder 的 latent space 可能有很多"空洞"：两个训练样本的 \(z\) 之间的点，decoder 从没见过，解出来可能是垃圾。VAE（variational autoencoder）的目的是让 latent space 处处可用，于是能从中采样来生成新数据。做法是两处改动：encoder 输出的不是一个点，而是一个 Gaussian 的均值和方差；loss 多一项，把这个 Gaussian 拉向标准正态分布 \(\mathcal{N}(0,I)\)。

\[ \mathcal{L}_{\text{VAE}} = \underbrace{\mathbb{E}_{z\sim q_\phi(z\mid x)}\big[-\log p_\theta(x\mid z)\big]}_{\text{重建误差（distortion）}} \;+\; \beta\,\underbrace{D_{\mathrm{KL}}\big(q_\phi(z\mid x)\,\Vert\, \mathcal{N}(0,I)\big)}_{\text{latent 携带的信息量（rate）}} \]
\(q_\phi(z\mid x)\)encoder：给定输入，输出 \(z\) 的分布 \(\mathcal{N}(\mu_\phi(x), \sigma_\phi(x)^2)\) \(p_\theta(x\mid z)\)decoder：给定 \(z\)，输出 \(x\) 的分布；取 Gaussian 时第一项就是 MSE \(\beta\)两项的权重；\(\beta=1\) 时这个 loss 是 \(-\log p_\theta(x)\) 的上界，它的相反数叫 ELBO

这两项正好是第 05 节说的 rate–distortion：第二项限制 \(z\) 能携带多少关于 \(x\) 的信息，第一项要求在这个限制下重建得尽量好。\(\beta\) 越大，压缩越狠，latent 越规整，重建越模糊。

一个技术细节：从 \(q_\phi\) 里采样这个操作不可导。Reparameterization trick 把采样写成 \(z = \mu + \sigma\odot\epsilon\)，\(\epsilon\sim\mathcal{N}(0,I)\)，随机性被移到了输入端，梯度就能通过 \(\mu\) 和 \(\sigma\) 传回 encoder。

VQ-VAE 和 FSQ：离散的 latent

VQ-VAE 维护一个 codebook，里面有 \(K\) 个向量。Encoder 的输出被替换成 codebook 里离它最近的那个，编号就是一个 token：

\[ k = \arg\min_j \lVert z_e - e_j \rVert, \qquad z_q = e_k \]

取最近邻不可导，训练时用 straight-through estimator：forward 用 \(z_q\)，backward 把梯度当作直接传给 \(z_e\)。FSQ（finite scalar quantization）更简单：不学 codebook，直接把 latent 的每一维四舍五入到少数几个固定的值，避免了 VQ 训练中一部分 code 永远用不上的问题。

离散化的意义在下一节：一旦图像、声音、动作都能变成编号，就能用训练语言模型的那一套方法来处理它们。

Bottleneck 的三种"货币"限制 latent 信息量有三种办法：降低维度（autoencoder）、加噪声并用 KL 约束（VAE）、离散化（VQ）。第三种最容易数清楚：codebook 有 1024 个 code，一个 token 就是 10 bit。把一张 256×256 的图编码成 16×16 个这样的 token，总共 2560 bit，也就是 320 字节，而原图是约 19.7 万字节。

在 policy 里：latent 是上下层之间的接口 SuperMimic 的 policy 是"每种命令接口一个 goal encoder，加一个共享的 decoder"，中间的 \(z\) 是 32 维并经过 tanh。这是一个 bottleneck：不管上层给的是 reference motion 还是 velocity command，都必须先变成这 32 个有界的数，decoder 只根据它和 proprioception 出动作。可以这样理解它的作用：tanh 把 \(z\) 限制在一个有界的范围里，不同的 encoder 更容易落在 decoder 训练时见过的区域内。RMA 里那个 8 维的 extrinsics 向量是同一类东西，它概括的是环境参数（第 18 节）。

09Token 与 tokenizer：把一切变成序列

这一节回答：为什么所有东西都要变成 token？图像和动作是怎么变的？

原因很实际：Transformer 处理的是一串向量。只要把图像、文字、关节状态、动作都变成一串向量，同一个网络就能处理所有模态，还能把它们拼在一个序列里。Tokenizer 就是做这个转换的模块，它回答的是第 01 节的 Q4。

两个经常被混在一起的区别

Token 这个词有两个意思

有时指那个离散的编号（"这句话有 5 个 token"），有时指序列里某个位置上的向量（"196 个 image token"）。图像 patch 的 token 是后者：它是连续向量，根本没有编号。

输入可以连续，自回归的输出必须离散

作为输入，任何向量都能当 token。但如果要用 cross-entropy 让模型"预测下一个 token"，输出必须来自一个有限的词表。所以想让 LLM 直接吐出动作，就必须把动作离散化；否则就得换一种输出头（diffusion、flow matching、回归）。

Action tokenization：VLA 的关键设计选择

做法怎么做优点代价代表
逐维 binning每个 action 维度在取值范围内均匀分成 256 份，取编号最简单，直接复用 LLM 的训练方式有量化误差；每个时间步要多个 token，高频控制时序列很长，推理慢RT-1、RT-2、OpenVLA
VQ 类用 VQ-VAE 把一小段 action 压成几个 code一个 token 表示一段动作要先训练 tokenizer；重建有损VQ-BeT
频域压缩对一段 action 做 DCT，量化系数，再用 BPE 压缩高频、灵巧的数据也能用离散 token 学好解码多一步FAST（π0-FAST）
不离散Action 保持连续，用 diffusion 或 flow matching 的 head 生成没有量化误差；一次生成一整段多了一个新的模块和迭代采样Diffusion Policy、π0、GR00T N1

深一层：为什么逐维 binning 在高频数据上会失效 FAST 论文给的解释和第 05 节直接相关。控制频率高（例如 50 Hz）时，相邻时间步的 action 几乎一样，于是"下一个 token"几乎总是等于上一个。模型只要学会照抄就能把 cross-entropy 降得很低，但没学到任何关于任务的东西。问题不在离散化本身，而在这种表示里每个 token 携带的新信息太少。DCT 把一段平滑的轨迹变成少数几个低频系数，去掉了冗余，每个 token 才重新变得"难预测、有信息"。Tokenizer 设计的本质是压缩。

Tokenizer 还决定了序列长度 \(n\)，而 Transformer 的计算量按 \(n^2\) 增长（第 11 节）。三个相机、每个 256 个 token，再加语言和动作，序列轻易上千。这是 VLA 推理慢的直接原因之一。

PART C

Architecture

函数的形状。不同的网络结构是对数据做了不同的假设；Transformer 胜出是因为它假设得最少。

10Inductive bias：每种结构假设了什么

这一节回答：MLP、CNN、RNN、Transformer 的本质区别是什么？为什么 locomotion policy 还在用 MLP？

每一种 architecture 都是把一条关于数据的假设写进了网络的连接方式里。假设对了，同样的数据能学得更好；假设错了，它就成了限制。

结构写进去的假设怎么实现的适合
MLP没有。输入就是一个固定长度的向量，各维之间没有已知的结构。全连接低维、定长的输入：proprioception、物理状态
CNN相邻的像素相关（locality）；同一个图案出现在哪里都是同一个东西（translation equivariance）。小的卷积核在整张图上滑动，所有位置共用同一组 weight图像、深度图、height map
RNN、LSTM、GRU信息沿时间一步步传递；每一步用同样的更新规则。一个 hidden state 反复被同一个函数更新序列；现在主要在需要小而快的 policy 里用
GNN数据是一张图；节点的编号顺序无关紧要。节点沿着边交换信息多物体、多机器人、关节结构
Transformer几乎没有。输入是一组 token，任意两个都可能相关，相关程度从数据里学。Attention（下一节）任意序列和多模态，前提是数据够多

假设和数据之间的交换

这就是 Sutton 所说的 bitter lesson：长期来看，能利用更多计算和数据的通用方法，总会胜过把人的知识写进模型的方法。但要注意前提是数据足够多。机器人领域的数据比语言少好几个数量级，所以写进去的结构（simulator 里的物理、3D 几何、action chunking、分层控制）现在仍然非常值钱。这是理解 robot learning 现状最重要的一个判断。

为什么 locomotion policy 用的是三层 MLP 输入只有几十维，长度固定，没有空间结构可以利用，所以 CNN 和 Transformer 的假设帮不上忙。Policy 要在机载 CPU 上以 50 Hz 以上运行，网络必须小。用 PPO 训练时，更大的网络通常也不会更好。需要用到历史时，常见做法是把过去若干帧拼起来直接喂给 MLP，或者用一个小的 1D CNN 或 GRU 先把历史压成一个 latent。一旦输入里有图像，或者要一个 policy 覆盖大量动作和任务，结构就会换成 CNN、Transformer。

11Attention 与 Transformer

这一节回答：Attention 具体算了什么？Transformer 的 encoder 和 decoder 和 autoencoder 的是一回事吗？

Attention：一个可微的、按内容查找的操作

普通的查表是：拿一个 key 去找，命中哪一条就返回哪一条的 value。Attention 是它的"软"版本：拿一个 query 和所有的 key 比相似度，按相似度把所有 value 加权平均。

\[ \alpha_i = \frac{\exp(q^\top k_i)}{\sum_j \exp(q^\top k_j)}, \qquad \text{output} = \sum_i \alpha_i\, v_i \]
\(q\)query：我在找什么 \(k_i\)第 \(i\) 个 token 的 key：我这里有什么 \(v_i\)第 \(i\) 个 token 的 value：如果你选了我，我给你什么 \(\alpha_i\)attention weight：内积相似度过 softmax，非负，加起来等于 1

实验 4：拖动 query，看 attention 怎么分配

四个 token 各有一个 key（灰色箭头）和一个 value（用颜色表示它携带的信息）。紫色箭头是 query，拖动它的端点，或者选中后用方向键。这里的向量是手工设定的二维向量，只为了让几何关系看得见；真实模型里它们是几十到上千维，由训练得到。

预设：

每个 token：内积 \(q^\top k_i\)，以及 softmax 之后的权重 \(\alpha_i\)

输出 \(=\sum_i \alpha_i v_i\)：按权重混合的 value

试试看：① 把 query 转向某个 key：那个 token 的权重变大，输出的颜色靠近它的 value。② 把 query 拉长：内积整体变大，softmax 变尖锐，几乎只选一个 token，接近普通的查表。③ 把 query 缩短：权重趋于均匀，输出接近所有 value 的平均。所以 attention 能在"精确查找"和"求平均"之间连续变化，而且用哪一种是学出来的。

三个要点：整个操作只有内积、softmax 和加权求和，处处可导，所以"该看谁"可以用梯度学。相似度由内容决定，不由位置决定，所以第 1 个 token 可以直接看第 500 个。输出是 value 的加权平均，所以每一层 attention 做的事是在 token 之间搬运信息。

Self-attention：每个 token 同时是 query、key 和 value

把 \(n\) 个 token 的向量排成矩阵 \(X\in\mathbb{R}^{n\times d}\)。每个 token 用三个可学习的线性映射分别产生自己的 query、key、value，然后所有 token 同时做一次上面的操作：

\[ \mathrm{Attention}(X) = \mathrm{softmax}\!\left(\frac{(XW_Q)(XW_K)^\top}{\sqrt{d_k}}\right) XW_V \]

中间那个 \(n\times n\) 的矩阵就是"谁看谁、看多少"。除以 \(\sqrt{d_k}\) 是为了数值稳定：维度越高内积的方差越大，不缩放的话 softmax 一开始就饱和，梯度很小。Multi-head attention 是把这件事并行做几遍，每一遍用不同的 \(W_Q, W_K, W_V\)，让模型能同时关注几种不同的关系。计算量按 \(n^2\) 增长（朴素实现的内存也是），这是 Transformer 最主要的代价。

Attention 本身不知道顺序：把输入的 token 打乱，输出只是跟着打乱。所以必须把位置信息加进 token 里，叫 position embedding（可学习的向量、正弦函数，或者现在常用的 rotary 形式 RoPE）。

Transformer block 和三种用法

一个 block 里的两个部件分工明确：attention 负责 token 之间的通信，MLP 负责每个 token 内部的计算。大部分参数其实在 MLP 里。

"Encoder / decoder"有两套含义，不要混 在 autoencoder 里，encoder 是"压缩"，decoder 是"重建"。在 Transformer 里，encoder 指"每个 token 能看到所有 token"的那种堆叠，decoder 指"只能看到过去、用来逐个生成"的那种。两套说法有历史渊源，但不等价：GPT 是 decoder-only，却完全没有压缩和重建；ViT 是 encoder-only，后面也不一定接 decoder。读论文时先分清作者用的是哪一套。

怎么让网络"以某个东西为条件"

Policy 要根据图像和语言来决定动作，生成模型要根据 observation 来生成动作。把条件信息送进网络，常见的只有四种办法，它们在论文的结构图里反复出现：

办法怎么做出现在
Concatenation把条件直接拼到输入向量上MLP policy：把 command 拼到 proprioception 后面
Prefix token把条件变成 token，放在序列前面，让 self-attention 去看VLM、VLA：image token 和语言 token 放在最前面
Cross-attention主序列的 token 作为 query，去看条件序列的 key 和 valueACT 的 decoder；transformer 版的 Diffusion Policy

Transformer 为什么胜出，代价是什么

优势

  • 训练时整个序列并行计算；RNN 必须一步一步算。
  • 任意两个 token 之间只隔一层 attention，梯度不用穿过很多时间步。
  • 假设少，数据和算力越多效果越好，目前没有看到明显的上限。
  • 只认 token，不认模态。图像、语言、动作可以放进同一个模型。

代价

  • 计算量按序列长度的平方增长。
  • 数据少的时候不如带强假设的结构。
  • 逐个生成 token 时每个 token 都要一次 forward，推理慢。
  • 没有内部状态，"记忆"只有 context window 里的东西。

右边一列正是 Transformer 用在机器人上的难点：控制要求低延迟和高频率，而大的 Transformer 做不到。后面会看到这直接导致了 action chunking 和"慢的大模型加快的小模型"的分层设计（第 19、20 节）。

12范式的三条轴

这一节回答：Supervised、self-supervised、generative、imitation、RL 这些词是并列的吗？

不是并列的，这是很多困惑的来源。Diffusion Policy 同时是 imitation learning、generative model、supervised regression，三个说法都对，因为它们在描述三件不同的事。把它们拆成三条独立的轴：

轴 1 · 信号来源

目标 \(y\) 是谁给的

人工 label → supervised。数据自身的一部分 → self-supervised。配对关系 → contrastive。专家的动作 → imitation。另一个模型的输出 → distillation。只有一个打分 → RL。

轴 2 · 建模对象

输出一个值，还是一个分布

只输出最可能的那个答案 → regression、classification（有时叫 discriminative）。输出一个可以采样的分布 → generative。

轴 3 · 数据和 policy 的关系

数据是固定的，还是自己产生的

在一个固定的数据集上训练 → offline。模型的输出会影响接下来采到的数据 → online、interactive（RL、DAgger）。

Self-supervised数据自身被遮住的部分，或未来的部分同上大量无标注数据LLM；MAE、DINO；world model 预测下一个 state
Contrastive哪些样本是一对InfoNCE成对的数据CLIP、SigLIP 的 vision encoder

13Self-supervised 与 contrastive：没有标签怎么学

这一节回答：没有人标注，监督信号从哪来？CLIP、DINO、MAE 学到的 feature 有什么不同？

办法是从数据本身造出一个预测任务。标注是瓶颈，而无标注的数据几乎无限，所以这是过去几年最重要的变化，也是 foundation model 这个词的来源：先用 self-supervised 的方式在海量数据上训练一个大模型，再把它适配到各种下游任务。三类做法：

做法造出来的任务代表
预测被遮住的部分遮住一部分输入，用剩下的预测它GPT（预测下一个 token）；BERT（预测被遮住的词）；MAE（遮住 75% 的 image patch，重建像素）
Contrastive判断哪两个样本是"一对"：配对的 embedding 拉近，不配对的推远CLIP、SigLIP（图片和它的文字说明）；SimCLR（同一张图的两种裁剪）
Self-distillation同一张图的两种不同裁剪，让 student 网络的输出去匹配 teacher 网络的输出；teacher 是 student 参数的滑动平均DINO、DINOv2

CLIP：contrastive learning 的标准例子

一个 batch 里有 \(N\) 对"图片和文字"。图片过 image encoder 得到 \(u_i\)，文字过 text encoder 得到 \(v_j\)，算出所有 \(N\times N\) 个相似度。训练目标是让对角线上的（真正配对的）相似度高，其余的低：

\[ \mathcal{L}_i = -\log \frac{\exp\big(\mathrm{sim}(u_i, v_i)/\tau\big)}{\sum_{j=1}^{N}\exp\big(\mathrm{sim}(u_i, v_j)/\tau\big)} \]

这个 loss 叫 InfoNCE，就是第 04 节的 softmax 加 cross-entropy，只是"类别"换成了 batch 里的其他样本。SigLIP 把它换成对每一对独立做二分类的 sigmoid loss，不再依赖很大的 batch。

Collapse：所有 self-supervised 方法都要防的捷径

"让两个相关样本的 embedding 靠近"有一个平凡解：把所有输入都映射到同一个向量。这叫 representation collapse。每种方法的不同之处，很大程度上就是用什么办法堵住它：contrastive 靠 negatives 把不相关的推开；DINO 靠 teacher 的滑动平均、centering 和 sharpening；MAE 的目标是具体的像素，天然不会 collapse。

预训练方式决定了 feature 擅长什么

这对机器人很重要，因为机器人自己的数据太少，vision encoder 几乎都借用在互联网数据上预训练的模型。Policy 能"看见"什么，由这个 encoder 的训练目标决定。

DINOv2只用图像的 self-distillation，加上 masked patch 预测几何和局部对应关系强，适合 depth、分割、keypoint；没有和语言对齐和 SigLIP 拼在一起用（OpenVLA）；dense 的感知任务

深一层：预测像素，还是预测 latent MAE 和 video generation 在像素空间里预测，好处是目标明确，不会 collapse；坏处是模型要花力气预测无法预测也无关紧要的细节（每片树叶的位置）。JEPA 一类的方法（I-JEPA、V-JEPA）主张只在 latent space 里预测，让模型自己决定丢掉哪些细节。DINO 的 self-distillation 也可以归入这个思路。目前没有定论，两条路线都有很强的结果。对机器人来说这个问题很具体：world model 应该生成未来的视频，还是只预测未来的 latent（第 22 节）。

14Generative model：学一个分布，而不是一个答案

这一节回答：Diffusion 和 flow matching 到底在做什么？为什么 robot policy 需要它们？

Generative model 学的是数据的分布 \(p(x)\) 或条件分布 \(p(x\mid c)\)，并且能从中采样。机器人需要它，是因为第 04 节的那个问题：同一个 observation 下合理的 action 常常不止一种，只输出一个"平均答案"的网络会给出一个谁都没示范过的动作。

难点在于：怎么用一个神经网络表示一个任意形状、高维、多峰的分布？各个家族给了不同的答案：

家族核心想法优点缺点机器人里
Autoregressive把 \(x\) 拆成一串离散 token，用概率的链式法则 \(p(x)=\prod_i p(x_i\mid x_{\lt i})\)，每次预测一个Loss 就是 cross-entropy；能表示任意离散分布必须先离散化；一个一个生成，慢RT-2、OpenVLA、π0-FAST 输出 action token
VAE先采一个 latent \(z\)，再由 decoder 生成（第 08 节）采样只要一次 forward样本偏模糊ACT 用 conditional VAE
GANGenerator 生成样本，discriminator 分辨真假，两者对抗样本清晰，一次 forward训练不稳定，容易只学到部分 modeGAIL；AMP 用 discriminator 的输出当 style reward
Diffusion学会给加了噪声的数据去噪；采样时从纯噪声出发一步步去噪训练稳定，能表示复杂的多峰分布采样要迭代多步Diffusion Policy；motion generation

Diffusion：把"生成"变成一连串的"去噪"

训练时不需要真的一步步加噪声，直接按下面的式子造一个带噪声的样本，让网络猜加进去的噪声是什么：

\[ x_t = \sqrt{\bar\alpha_t}\, x_0 + \sqrt{1-\bar\alpha_t}\;\epsilon, \qquad \mathcal{L} = \mathbb{E}_{x_0,\,\epsilon,\,t}\,\big\lVert \epsilon - \epsilon_\theta(x_t, t)\big\rVert^2 \]
\(x_0\)一个干净的数据样本；对 policy 来说是一段专家的 action \(\epsilon\)标准 Gaussian 噪声 \(t,\ \bar\alpha_t\)噪声等级及其对应的系数；\(t\) 越大，\(\bar\alpha_t\) 越接近 0，样本越接近纯噪声 \(\epsilon_\theta\)网络：输入带噪声的样本和噪声等级，输出对噪声的估计

这个 loss 是一个普通的 MSE regression。采样时从 \(x_T\sim\mathcal{N}(0,I)\) 出发，反复用网络估计噪声并去掉一部分，几步到上百步之后得到 \(x_0\)。为什么这样可行：可以证明，最优的噪声预测和 \(\nabla_x \log p_t(x)\)（叫 score，指向数据密度变大的方向）只差一个系数。所以每一步去噪，都是沿着"数据更可能出现"的方向走一小步；噪声等级从大到小，对应先定大致形状、再补细节。

Flow matching：直接学一个速度场

取一个噪声样本 \(x_0\sim\mathcal{N}(0,I)\) 和一个数据样本 \(x_1\)，用直线把它们连起来，让网络在线上的任意一点预测这条线的方向：

\[ x_t = (1-t)\,x_0 + t\,x_1, \qquad \mathcal{L} = \mathbb{E}_{x_0,\,x_1,\,t}\,\big\lVert v_\theta(x_t, t) - (x_1 - x_0)\big\rVert^2 \]

采样时从噪声出发，积分一个 ODE：\(\dot{x} = v_\theta(x, t)\)，从 \(t=0\) 到 \(t=1\)。用你熟悉的话说：网络学的是一个时变的向量场，生成就是从一个随机初值出发做一次数值积分。当噪声是 Gaussian、路径是这种线性插值时，diffusion 和 flow matching 的训练目标可以互相转换，差别只在参数化、噪声的时间安排和 loss 的权重。

实验 5：MSE 的平均化，和多步积分怎么把它解开

这个实验把第 04 节的 mode averaging 和上面的 flow matching 接在一起。设想一个一维的 action：示范数据集中在两个值附近（比如"从左绕"和"从右绕"）。左边 \(t=0\) 是噪声，右边 \(t=1\) 是数据分布，每条细线是一个样本沿速度场走过的轨迹。因为目标分布是已知的 Gaussian mixture，这里的速度场是解析算出来的精确解；真实训练中由网络 \(v_\theta\) 来近似它。

Euler 积分步数：
积分步数 落在上方 mode 落在下方 mode 落在两个 mode 之间 数据的均值

两个实用的旋钮：采样步数和 guidance

步数。训练时的噪声等级可以有上百个，采样时不必每一级都走。DDIM 把采样改成确定性的、可以跳步的更新：Diffusion Policy 训练时用 100 个噪声等级，真机推理时用 DDIM 只走 10 步左右。Flow matching 的路径更接近直线，π0 用 10 步 Euler 积分。想压到一两步，要靠 distillation：训练一个 student，一步走完 teacher 多步才走完的路（consistency model 一类，机器人上有 Consistency Policy）。步数直接决定控制延迟，所以它是 generative policy 上真机时第一个要调的量。

Classifier-free guidance（CFG）。训练时以一定概率把条件 \(c\)（语言、goal）换成空条件 \(\varnothing\)，同一个网络就同时学会了有条件和无条件的预测。采样时把两者的差放大：

\[ \hat\epsilon = \epsilon_\theta(x_t, \varnothing) + w\,\big[\epsilon_\theta(x_t, c) - \epsilon_\theta(x_t, \varnothing)\big] \]

\(w=1\) 是普通的条件采样，\(w\gt 1\) 让样本更"听"条件的话，代价是多样性下降。它是图像生成的标配；在 policy 里用来调节 action 跟 goal 或语言贴得多紧。

15Reinforcement learning：只有 reward，没有标签

这一节回答：RL 的梯度是怎么来的？它为什么需要那么多样本，又为什么在 locomotion 上行得通？

设定是 Markov decision process：在 state \(s_t\) 下，policy \(\pi_\theta\) 选一个 action \(a_t\)，环境返回 reward \(r_t\) 并转移到 \(s_{t+1}\)。目标是让长期累计的 reward 最大：

\[ J(\theta) = \mathbb{E}_{\tau\sim\pi_\theta}\Big[\sum_{t} \gamma^t\, r(s_t, a_t)\Big] \]

和前面所有范式相比，这里有两个根本的困难：

  • 不能直接对目标求导。Reward 通过环境的 dynamics 依赖于 action，而环境是个黑盒，有 contact 时还不光滑。链式法则在这里断了。
  • 数据分布由 policy 自己决定。Policy 一更新，它访问的状态就变了，之前的数据就不再代表现在的 policy。训练目标在不断移动。

Policy gradient：不对环境求导，只对"选这个动作的概率"求导

\[ \nabla_\theta J(\theta) = \mathbb{E}_{\tau\sim\pi_\theta}\Big[\sum_t \nabla_\theta \log \pi_\theta(a_t\mid s_t)\; A(s_t, a_t)\Big] \]
\(\pi_\theta(a\mid s)\)stochastic policy，通常是一个 Gaussian：网络输出均值，另外学一个方差 \(A(s,a)\)advantage：在 \(s\) 下做 \(a\)，比这个状态下的平均水平好多少

读法很直白：带着噪声去试；比预期好的动作，提高它的概率；比预期差的，降低。这个式子只需要能采样、能拿到 reward，完全不需要知道环境的 dynamics。代价是它本质上是用随机扰动来估计方向，方差很大，action 维度越高、任务越长越严重。所以需要大量样本，这就是为什么要在 GPU 上同时跑几千个仿真环境。

降低方差靠 critic：再训练一个网络 \(V(s)\) 来预测"从这个状态开始，按当前 policy 走下去能拿多少 reward"，用它来算 advantage。Policy 叫 actor，合起来叫 actor–critic。Critic 的训练是一个普通的 regression。

对应到你熟悉的东西 \(V(s)\) 满足 Bellman equation：\(V(s) = \mathbb{E}[\,r + \gamma V(s')\,]\)，就是 dynamic programming。LQR 是它的特例：dynamics 线性、cost 二次时，value function 正好是二次型 \(x^\top P x\)，把它代入 Bellman equation，得到的就是 \(P\) 要满足的 Riccati equation。RL 里的 critic 是在没有模型、非线性的情况下，用神经网络和样本去近似同一个东西。

Critic 的目标怎么造：Monte Carlo、TD 和 GAE

Critic 要回归的"未来能拿多少 reward"有两种极端的算法，policy gradient 里的 advantage 也跟着有两种：

  • Monte Carlo。直接用这条轨迹后面实际拿到的 return \(G_t=\sum_{k\ge 0}\gamma^k r_{t+k}\)。没有偏差，但后面每一步的随机性都算在里面，方差大。
  • Temporal difference（TD）。只看一步，剩下的用 critic 自己的估计补上：目标是 \(r_t+\gamma V(s_{t+1})\)。方差小，但 critic 不准时目标本身就是偏的。用自己的估计当目标，叫 bootstrapping。
\[ \delta_t = r_t + \gamma V(s_{t+1}) - V(s_t), \qquad \hat{A}_t^{\,\text{GAE}} = \sum_{l=0}^{\infty} (\gamma\lambda)^l\, \delta_{t+l} \]
\(\delta_t\)TD error：这一步的实际结果比 critic 预期的好多少 \(\lambda\)在两个极端之间插值：\(\lambda=0\) 只信一步的 TD，\(\lambda=1\) 等于 Monte Carlo \(\gamma\)discount factor：有效的 horizon 约为 \(1/(1-\gamma)\) 步

这就是 generalized advantage estimation（GAE），PPO 默认用它算 advantage，常见取值是 \(\gamma=0.99\)、\(\lambda=0.95\)。\(\gamma=0.99\) 配 50 Hz 的 policy，相当于往前看大约 2 秒：对保持平衡够了，对"走到房间另一头"不够，后者要靠上层给命令。

PPO：为什么它是 legged robot 的默认算法

Policy gradient 的一步如果迈得太大，policy 会突然变差，接下来采到的数据也跟着变差，很难恢复。PPO 的做法是限制每次更新后 policy 不能离采数据时的旧 policy 太远：

\[ L^{\text{CLIP}}(\theta) = \mathbb{E}_t\Big[\min\big(\rho_t(\theta)\,\hat{A}_t,\ \ \mathrm{clip}(\rho_t(\theta),\,1-\varepsilon,\,1+\varepsilon)\,\hat{A}_t\big)\Big], \qquad \rho_t(\theta) = \frac{\pi_\theta(a_t\mid s_t)}{\pi_{\theta_{\text{old}}}(a_t\mid s_t)} \]

\(\rho_t\) 是新旧 policy 给同一个动作的概率之比。把它 clip 在 1 附近，相当于一个便宜的 trust region。PPO 的样本效率不高，但相对稳健、容易大规模并行。在仿真里样本几乎免费，所以这个取舍很划算。

Q-learning：off-policy 方法的地基

\(V(s)\) 评价的是当前 policy。换一个问法：\(Q^\star(s,a)\) 是"在 \(s\) 下做 \(a\)，之后一直按最优方式走"能拿到的 return。它满足 Bellman optimality equation：

\[ Q^\star(s,a) = \mathbb{E}\Big[\, r + \gamma \max_{a'} Q^\star(s', a') \Big] \]

Q-learning 把等号两边的差当作 loss 来做 regression（这个差也叫 TD error）。式子里没有出现"数据是哪个 policy 采的"，所以任何旧数据都能拿来用。这就是 off-policy：经验存进 replay buffer，反复采样。DQN 让它在神经网络上稳定下来靠两件事：replay buffer 打散相邻样本之间的相关性；target network，算目标时用一份更新得慢的参数拷贝，否则目标会跟着自己一起动。

连续的 action 上 \(\max_{a'}\) 没法枚举，所以再训练一个 actor 去输出让 \(Q\) 最大的 action，这就是 DDPG、TD3、SAC 这一支。取 max 会系统性地高估 \(Q\)，TD3 和 SAC 用两个 \(Q\) 网络取较小的那个来压。

深一层：为什么 off-policy 省样本但难调 Function approximation、bootstrapping、off-policy 三者同时出现时，训练可能发散，Sutton 和 Barto 把它叫 deadly triad。PPO 的数据是当前 policy 新采的，避开了第三个，所以稳；SAC 三个都占，所以需要 target network、双 \(Q\) 这些补丁。Offline RL 是最极端的情况：数据完全不是自己采的，\(\max\) 会挑中数据里从没出现过、\(Q\) 值被估高了的动作，所以 CQL、IQL 的核心都是不让 policy 离开数据覆盖的范围。

Behavior cloning：对 action 做 supervised learning

收集专家的 (observation, action) 对，训练 policy 在同样的 observation 下输出同样的 action：\(\min_\theta \mathbb{E}_{(o,a)\sim\mathcal{D}}[-\log \pi_\theta(a\mid o)]\)。没有 reward，没有 simulator，没有探索。它简单到让人怀疑，而且确实有三个固有的问题，现代方法的大部分设计都是在对付它们：

问题原因现在怎么处理

Multimodality同一个 observation 下，不同示范做了不同的动作（第 04 节）Generative 的输出头：diffusion、flow matching、离散 token、CVAE（第 14 节）
学到错误的因果关系（causal confusion）把历史喂给 policy 时，它可能学会"照抄上一步的动作"，因为这在训练集上几乎总是对的限制历史长度；预测一整段而不是下一步

Action chunking 值得单独记住：policy 不是每一步输出一个动作，而是一次输出未来 \(H\) 步的一整段。它对上面三个问题都有不同程度的帮助：决策次数变少，等效的任务长度变短；一段动作内部是连贯的，不会在两个 mode 之间来回跳；要预测的是未来一整段，"照抄上一步"这条捷径也没那么好走了。

DAgger：让专家给 policy 自己走到的状态打标签

  1. 用当前的 policy 去执行，记录它走到的状态。
  2. 对这些状态，问专家"你在这里会怎么做"，得到标签。
  3. 把新数据并入数据集，重新训练。重复。

这样训练分布就逐渐覆盖了 policy 自己会到达的状态，包括它犯错之后的状态。DAgger 的前提是专家可以被随时查询。对人来说这很难（没法在机器人自己乱动的时候给出标签），但如果专家本身是一个 policy，就毫无困难。这就引出了 distillation。

Distillation 没有新的数学：它就是 supervised learning，只是标签由另一个模型（teacher）提供。它有用是因为 teacher 和 student 的处境不同。在机器人里最常见的形式是 privileged teacher–student：

只知道"动作该是什么样"：inverse RL 与 adversarial imitation

Behavior cloning 需要专家的 action。如果只有 state 的轨迹（mocap、视频），或者想学的是专家的意图而不是逐帧照抄，就换一个问法：什么样的 reward 能解释专家的行为？先从 demonstration 里学出 reward，再用 RL 优化它，这叫 inverse RL。GAIL 把它做成了 GAN 的形式：discriminator 分辨一段行为来自专家还是来自 policy，它的输出就是 policy 的 reward。AMP 是这个想法在 humanoid 上最常用的版本：discriminator 只管动作像不像 mocap（style reward），任务另有一项 reward。它和 motion tracking 的区别在于，tracking 要求逐帧跟上某一条 reference，AMP 只要求动作的分布像数据。

两条线在哪里汇合

  • Distillation 是桥。先在仿真里用 state 训练一个 RL teacher，再蒸馏成只看图像的 student（第 16 节）。Parkour 和一部分灵巧手工作这样做，它把 RL 的"reward 驱动、能超过示范"和视觉的"真机可部署"接了起来。
  • 分层是另一座桥。Humanoid 上，底层是 state-based RL 训练的 whole-body controller，上层是 vision-based 的 VLA 或 teleoperation，中间通过 keypoint、速度命令或 latent 连接。两条线各自做擅长的部分。
  • 互相借数据。用仿真生成带图像的 manipulation 数据；反过来用真机数据修正仿真（system identification、real-to-sim）。
  • Imitation 打底，RL 提高。先用 demonstration 得到一个能用的 policy，再用真机或仿真里的 RL 把成功率和速度推上去（第 16 节）。

Humanoid 的 loco-manipulation 之所以是现在最难的问题，正是因为它同时需要两条线：腿和平衡需要 RL 的鲁棒性，手和任务需要视觉和 demonstration。

Motion tracking 加了什么

Humanoid 的全身控制现在主流是 motion tracking：输入里多了一段 reference motion（未来几帧的目标关节角或 keypoint），reward 是"跟得有多准"。从 learning 的角度看，它把手写的 reward 换成了由数据定义的 reward，本质上是用 RL 来解一个 imitation 的问题：数据只给了"身体应该怎么动"，没给"电机该出多少力"，后者要靠 RL 在仿真里试出来。

一个 policy 跟踪的动作越多，它就越像一个通用的底层接口。这时前面的概念集中出现：把各种形式的命令压成一个 latent（encoder 加 bottleneck），用一个共享的 decoder 出动作；用 world model 预测下一个 state 来提供梯度（self-supervised 的 dynamics 学习）；用 diffusion model 在 reference 或 latent 这一层做规划（generative model）。它们都是第 08、14、15 节里的东西，换了个输入输出而已。

Action chunk 怎么执行：其实是 receding horizon

以 Diffusion Policy 为例：看最近 2 帧 observation，预测未来 16 步 action，执行其中前 8 步，然后重新预测。这和 MPC 的 receding horizon 是同一个结构，取舍也一样：执行得长，动作连贯但反应慢；执行得短，反应快但前后两次预测可能选了不同的 mode，动作会抖。ACT 的做法是每一步都重新预测一整段，然后把多次预测中对同一时刻的结果加权平均（temporal ensembling）。

大模型推理一次要几十到上百毫秒，机器人在这段时间里还在动，所以新的一段 action 算出来时，它的开头已经过时了。怎么在两段之间平滑衔接，是 VLA 上真机时一个很实际的工程问题。

一个代表做法是 real-time chunking（RTC）：新的一段不等旧的执行完就开始算（asynchronous inference）。推理期间必然会被执行掉的那几步直接沿用旧的 chunk，当作已知条件，让 flow matching 把剩下的部分补全成和它们连贯的轨迹，思路和图像的 inpainting 一样。

20VLA：vision、language、action

这一节回答：VLA 这个词拆开是什么？为什么要把 LLM 放进机器人，它带来了什么、没带来什么？

先有 VLM：让语言模型看图

VLM（vision-language model）的结构只有三块：一个预训练的 vision encoder（ViT）把图像变成一串 patch feature；一个小的 projector（通常是 MLP）把它们映射到 LLM 的 embedding space；然后这些 visual token 和文字的 token 拼在一起，喂给 LLM。对 LLM 来说，图像就是一段用"外语"写的前缀，projector 是翻译。训练数据是互联网上的图文对和视觉问答。

再加 action：两条路线

VLA 就是让这个 VLM 的输出里包含机器人的 action，然后在 robot demonstration 上 fine-tune。区别在于 action 怎么输出：

路线一：action 也是 token

把 action 离散成编号（第 09 节），当成词表里的新词，模型像生成文字一样逐个生成。训练仍然是 cross-entropy，和原来的 VLM 完全兼容，可以和图文数据混在一起训练。缺点是逐个生成慢，精度受量化限制。
RT-2、OpenVLA、π0-FAST。

路线二：接一个连续的 action head

VLM 负责理解，输出的中间 feature 作为条件，交给一个专门的网络用 flow matching 或 diffusion 生成一整段连续的 action（第 14 节）。没有量化误差，一次出一段，适合高频和灵巧的任务。缺点是多了一个从零开始训练的模块。
π0、GR00T N1。

Cross-embodiment：一个模型怎么驱动不同的机器人

不同机器人的 state 和 action 维度、含义、控制频率都不一样。常见的处理有三种：

  • 统一到一个公共的 action 空间。都用 end-effector 的位姿增量加夹爪开合（RT-X、OpenVLA）。简单，但双臂、灵巧手、移动底盘放不进去。
  • Padding。取所有机器人里最大的维度，不足的补零（π0）。
  • 每种 embodiment 一组小的输入输出层。共享一个大的 backbone，前后各接一组 embodiment 专用的 state encoder 和 action decoder（Octo、GR00T N1）。

Cross-embodiment 的收益主要落在 backbone 学到的"看图、理解任务"上；动作的细节仍然依赖目标机器人自己的数据，所以换一台新机器人通常还要 fine-tune。

先想再动：embodied reasoning

直接从图像和指令映射到 action，要求模型在一次 forward 里同时理解任务、找到物体、决定下一步、算出动作。让它先把中间结论写出来，再出 action，在长任务和没见过的指令上更稳：

  • Embodied chain-of-thought（ECoT）。训练 VLA 在 action token 之前先生成一段文字：任务计划、当前的子任务、相关物体的 bounding box、夹爪的位置。
  • 先预测子任务，再预测 action。π0.5 用同一个模型先输出高层的子任务（"拿起盘子"），再以它为条件生成 action chunk；Hi Robot 用上下两个模型做同样的事。
  • Thinking before acting。Gemini Robotics 1.5 在动作之前用自然语言写出自己的推理。

代价是延迟，所以"想"的部分通常比出 action 的部分跑得慢，这又回到了下面的分层。再往上走一步，让语言模型只负责想、完全不出 action，就是第 21 节的内容。

VLM 带来了什么，没带来什么

带来的

  • 认识物体和场景：没在 robot 数据里出现过的东西，VLM 在互联网上见过。
  • 理解指令：同义的说法、组合的指令、一定程度的常识推理。
  • 一个强的初始化：比从头训练需要的 robot 数据少。

没带来的

  • 动作本身。互联网上没有"关节该怎么动"的数据，这部分只能来自 robot 数据。
  • 精细的空间和接触信息。VLM 的 vision encoder 是为语义训练的。
  • 速度。几十亿参数的模型每秒只能跑几次。

分层：用频率来划分工

最后一条直接导致了现在最常见的结构，通常叫 dual-system 或 System 1 / System 2：

层做什么典型频率怎么训练的

慢的大模型（VLM）看图、理解指令、决定现在该做哪一步每秒 1 到 10 次互联网预训练，加 robot 数据 fine-tune

每两层之间的接口都是一个 Q4 的设计选择：语言的子任务描述、一个 latent 向量、手和头的 keypoint、速度命令。这和 Whole-Body Control 范式全景 里"分层没有消失，接口在变"是同一个观察，只是这次从上往下看。

深一层：新模块的梯度会不会破坏预训练的知识 路线二里，action head 是随机初始化的，训练初期它传回 VLM 的梯度很大也很乱，可能把 VLM 原本的语义知识冲掉；只用 robot 数据 fine-tune 也会让模型逐渐忘记它在互联网上学到的东西。常见的对策有三类：和图文数据一起训练（co-training）；让 VLM 的主干用离散 action token 的 loss 学习，同时阻止 action head 的梯度流回主干（Physical Intelligence 把这叫 knowledge insulation）；或者只训练一小部分参数（例如 LoRA）。这个问题说明"end-to-end"不是越彻底越好，梯度往哪流、不往哪流是需要设计的。

21LLM 当 planner：不出 action，出 plan 或 code

这一节回答：不训练 VLA，直接拿现成的 LLM 或 VLM 来指挥机器人行不行？SayCan、Code as Policies 和 2026 年的 Gemini 4 做的是同一件事吗？

VLA 把语言模型的 weight 拿来 fine-tune，让它直接输出 action。另一条更早、也一直并行的路线是不动 LLM 的 weight：让它做本来就会的事（推理、写代码、看图回答问题），输出一个机器人系统能执行的中间产物，底层的动作交给别的模块。各种做法的区别只在一个 Q4 的选择：LLM 和机器人之间的接口是什么。

LLM 输出什么谁来执行代表上限在哪
从 skill 列表里选一个预先训练好的一组 skill policySayCan能做的事被 skill 库限死
一步步的语言子任务，并根据反馈重新规划语言条件的 policy 或 VLAInner Monologue；Hi Robot；Gemini Robotics-ER 当 orchestrator底层必须听得懂、做得到这些子任务

SayCan：把"该做什么"和"做得到什么"相乘

LLM 知道"要清理洒了的可乐，应该先去拿海绵"，但它不知道眼前有没有海绵，也不知道这台机器人会不会拿。SayCan 对 skill 库里的每个 skill 算两个分数再相乘，选最高的执行，执行完再问下一步：

\[ k^\star = \arg\max_{k}\;\; \underbrace{p_{\text{LLM}}\big(\ell_k \mid \text{instruction},\ \text{history}\big)}_{\text{say：这一步有没有用}} \;\cdot\; \underbrace{V_k(s)}_{\text{can：现在做不做得成}} \]
\(\ell_k\)第 \(k\) 个 skill 的语言描述，例如"pick up the sponge" \(V_k(s)\)这个 skill 自带的 value function：从当前状态出发它成功的概率，也叫 affordance

这一节最该记住的词：groundingLLM 的知识来自文字，必须有某种机制把它接到眼前的场景和这台机器人的能力上，这叫 grounding。后面所有方法的差别，基本就是 grounding 怎么做：SayCan 用 value function，Code as Policies 用感知 API 的返回值，后来的 VLM 直接看图。

Code as Policies：让 LLM 写程序

在 prompt 里给出可用的 API 和几个例子，LLM 生成一段 Python，解释器直接执行。下面是示意，API 的名字是随手取的：

# 指令：把红色方块放到蓝色碗左边 10 cm 的地方
block = detect_object("red block")      # 感知 API：返回物体的位姿
bowl  = detect_object("blue bowl")
target = bowl.position + np.array([0.0, 0.10, 0.0])   # 用普通的算术做空间推理
pick(block)                             # 控制 API：背后是 grasp、IK、motion planner
place(target)

代码比"从列表里选一个 skill"强在三点。有循环和条件，能写出"每个方块都放进同色的碗"。能做算术，把"左边一点"变成具体的坐标。能定义新函数并复用，等于自己扩充 skill 库。代码还天然可读、可调试，出错时知道错在哪一行。

对应到你熟悉的东西 这是 task and motion planning（TAMP）的结构：上层决定做哪些离散的步骤，下层为每一步求连续的运动。LLM 替掉的是上层那个手写的状态机或 PDDL domain；它调用的 API 仍然是传统的 perception、IK 和 motion planning。所以 code as policy 不是"LLM 在控制机器人"，而是"LLM 在写调度传统模块的那段胶水代码"。

VoxPoser 和 ReKep：让 LLM 写 cost，让 optimizer 求解

几个固定的 API 表达不了"倒水时保持壶嘴对准杯口"这样的连续约束。VoxPoser 让 LLM 写代码去组合 3D 空间里的 value map（哪里该去，哪里要避开），再由 motion planner 在这张图上求轨迹。ReKep 让 VLM 在图像上选出一组 keypoint，把任务写成这些 keypoint 之间的约束函数（用 Python 写的 cost），交给优化器解出 end-effector 的轨迹，执行中不断重解。两者都不需要任何 robot demonstration。用控制的话说：LLM 负责写 cost function，trajectory optimization 负责解。

2025 到 2026：通用模型自己变成了 embodied reasoning 模型

早期的做法是拿通用的 LLM 配外部的检测模型。2025 年起出现了专门为这一层训练的 VLM：Gemini Robotics-ER 能在图像上指出物体的点、给出 bounding box、抓取位姿和轨迹，判断任务的进度和成败，把长任务拆成子任务。2026 年 7 月的 Gemini Robotics ER 2 明确定位成高层 planner：自己不控制电机，把 VLA 或 navigation API 声明成工具来调用。

2026 年下半年，这些能力进了通用模型本身。按 Google 的发布文章，Gemini 4 Argon（2026 年 10 月）zero-shot 控制机械臂的方式是一个多轮的闭环：每一轮先看相机图像，写出调用 robot.grasp(...)、robot.goto(...)、robot.move_until_contact(...) 这类 motion primitive 的代码，执行，再看图检查，抓空了就重试。它还会自己写 MuJoCo 的场景和控制器做 real-to-sim，在仿真里生成数据去 fine-tune VLA；文章报告这样生成的数据把一个真机任务的成功率从 56% 提到了 75%。Gemini 4 Hydrogen（2026 年 11 月）是更快、更便宜的版本，做的是同一个循环："规划任务，写并运行控制代码，不断调整直到完成"。

这就是 code as policy，变化有两处：写代码的模型强了很多，而且循环是闭环的，模型每一轮都看得到自己上一步的结果。这部分是这一页里最新的内容，数字来自官方文章，引用前请核对。

LLM 在训练流程里的其他位置

  • 写 reward。Eureka 让 LLM 生成 reward 的代码，在仿真里并行训练，把训练结果的统计反馈给 LLM 再改，循环几轮；它用这个办法让灵巧手学会了转笔。这是第 15 节"reward 最花人力"的一个回答。

22World model 与 3D 表示

这一节回答：World model 这个词在不同论文里指的是同一个东西吗？除了 2D 图像，机器人还能怎么表示场景？

World model：预测"做了这个动作之后会怎样"

最宽的定义：一个学出来的模型，输入当前的状态（或它的表示）和 action，输出下一个状态。训练它是 self-supervised 的：目标就是数据里的下一帧，不需要任何标注。但这个词在不同的工作里指的东西差别很大：

类型在什么空间里预测主要用途代表
State-space dynamics model物理状态：关节角、速度代替或加速 simulator；提供可微的梯度Robotic World Model；SuperMimic（一个大 MLP，没有 latent）
Latent dynamics modelEncoder 输出的 latent在 latent 里想象轨迹来训练 policy，或在线做 planningDreamer（RSSM，可以粗略看成时序上的 VAE）；TD-MPC2
Video generation model像素，或视频 tokenizer 的 latent生成训练数据；评估 policy；作为预训练目标Genie、Cosmos
Latent prediction（JEPA 类）预训练 encoder 的 feature学 representation；在 feature 空间里做 planningV-JEPA 2

所有 world model 共有一个问题，而且你已经见过它：把模型自己的输出再喂回去，多步之后误差会累积。这和第 06 节 behavior cloning 的 compounding error 是同一个机制。常见的对策也相似：只用短的 rollout；训练时就让模型从自己的预测出发多步展开（SuperMimic 用 8 步的窗口训练，用 32 步的 imagination）；用 value function 概括更远的未来。

对应到你熟悉的东西 World model 加 planning 就是 MPC，只是模型是学的。World model 加 policy gradient 就是在学到的 simulator 里做 RL。对 world model 求导就是 differentiable simulation。Model-based 控制的结构都还在，变的是模型从哪来。

Video model 和 policy 的三种关系

  • 当数据引擎。在机器人数据上 fine-tune 一个 video model，让它按新的指令生成视频，再用 inverse dynamics model 补上 action（第 19 节），得到真机上没采过的轨迹。DreamGen 这样做，把生成的数据叫 neural trajectory。
  • 当 policy 的一部分。先生成"任务完成过程"的视频或下一个子目标的图像，再用 inverse dynamics model 或 goal-conditioned policy 把它变成 action（UniPi、SuSIE）。
  • 当评估器。把 policy 输出的 action 喂给 action-conditioned 的 video model，在生成的视频里看任务有没有完成，代替一部分真机评估（第 23 节）。

3D 表示：把几何结构写进输入

2D 图像的问题是它依赖视角：相机挪一下，所有像素都变了。3D 表示把"世界是三维的"这个假设直接写进输入格式，是一种 inductive bias（第 10 节）。

还有两种把几何写进去的办法，不改输入的格式。Equivariance：把"物体平移或旋转之后，动作也跟着平移或旋转"直接写进网络结构（Transporter Networks、Equivariant Diffusion Policy），pick-and-place 这类任务用很少的 demonstration 就能学会。Object-centric 表示：先用感知模型把场景变成物体的位姿或 keypoint，policy 只看这些低维的量，等于回到了 state-based 的设定。

可以直接拿来用的感知模型

除了端到端的 policy，还有一类系统把感知拆成模块，每个模块用一个现成的 foundation model：分割用 SAM，开放词表的检测用 Grounding DINO，单目深度用 Depth Anything，物体 6D 位姿用 FoundationPose，点的跟踪用 CoTracker。它们输出有明确含义的中间结果（mask、bounding box、位姿），接传统的 planning 和控制。和端到端相比，好处是可调试、不需要 robot demonstration；坏处是模块之间的误差会传递，而且中间表示限制了能表达的任务。

抓取有专门的模型：Contact-GraspNet、AnyGrasp 这类 grasp pose detection 网络从点云直接给出一批 6-DoF 的抓取位姿，是模块化 pick-and-place 系统的标准部件。DUSt3R、VGGT 这类前馈式的 3D 重建模型，可以从几张没有标定的照片直接给出点云和相机位姿。第 21 节的 LLM planner 调用的感知 API，背后就是这一段里的模型。

23评估与部署：从 checkpoint 到真机

这一节回答：一个 policy 训练完，怎么知道它好不好？从 checkpoint 到在真机上稳定地跑，中间还隔着什么？

量什么

最常用的是 success rate。它对长任务太粗，所以常再报 task progress（完成了几个子步骤）和完成时间。一个容易踩的坑：validation loss 不能用来选模型。它量的是在专家的状态上预测 action 的误差（open-loop），而部署是闭环的；第 06 节的 covariate shift 让这两者的相关性很弱。Validation loss 只适合查 overfitting 和 bug，checkpoint 的好坏要闭环跑了才知道。

试验次数少的时候，数字有多不可靠

每次试验是一次成败，成功率的标准误差是：

\[ \mathrm{SE} = \sqrt{\frac{p\,(1-p)}{n}} \]

\(p=0.8\)、\(n=20\) 时 SE 约 0.09，95% 置信区间大约是正负 18 个百分点。所以各跑 20 次得到的"80% 对 90%"不能说明任何问题；要可靠地分辨这两个数，每个方法需要两百次左右。实际评估时还要控制初始条件：物体的位置和朝向事先定好，几个方法在同一天、同一套位置上交替着测，否则光照和硬件状态的变化会混进结果里。

论文里说"泛化到新物体"，通常指前两行。读的时候先问清楚是哪一行。

PART F

讨论

把前面的内容压缩成几条可以带进任何一篇论文的视角，以及一些目前没有答案的问题。

24贯穿始终的六条主线

1 · 几乎一切都是 prediction

语言模型预测下一个 token，MAE 预测被遮住的 patch，diffusion 预测噪声，world model 预测下一个 state，behavior cloning 预测专家的 action，critic 预测未来的 return。目标的差别只在于预测什么、以什么为条件。读一个新方法时，先把它写成"根据 A 预测 B"，大部分神秘感就没了。

2 · Representation 是被目标逼出来的

没有人告诉网络该提取什么 feature。Encoder 学到什么，完全由"为了把 loss 降下去，需要保留哪些信息"决定。所以想要什么样的 representation，就去设计能逼出它的预测任务：想要语义，就让图像去匹配文字；想要几何，就让它预测被遮住的局部；想要对控制有用的信息，就用 action loss。Bottleneck 是在此基础上再加一把力：强迫丢掉一部分。

3 · 一切都取决于训练分布盖没盖住

Domain randomization、data augmentation、DAgger、teleoperation 时故意采纠错动作、cross-embodiment 数据、互联网预训练，这些看起来不相关的做法是同一个动作：扩大训练分布。评价一个 robot learning 系统时，最有用的问题通常不是"模型多大"，而是"部署时会遇到的情况，训练时见过吗"。

4 · 进步常常来自把难问题改写成 supervised learning

Supervised learning 是目前唯一确定能随数据和算力稳定变好的东西。于是很多突破的形式是"找到一个办法，把某个难问题变成它"：distillation 把 RL 的问题变成有标签的问题；diffusion 把"表示任意分布"变成"在每个噪声等级上做 regression"；DAgger 把闭环的问题变成一系列有标签的问题；motion tracking 用数据替掉了手写的 reward。看到一个新方法，可以问：它把哪个难的部分变成了 regression 或 classification？

5 · 结构放在哪里，由数据量决定

关于世界的知识可以放在 architecture 里（CNN 的平移不变、3D 表示）、simulator 里（物理）、reward 里、或者数据里。数据越多，越倾向于少写结构、让模型自己学；数据越少，写进去的结构越值钱。机器人处在数据少的一端，所以 simulator、分层、action chunking 这些人为的结构现在仍然是主力。这条线会随着数据的增长而移动。

6 · 一步算完，还是迭代着算

MLP policy 一次 forward 就出动作，是把所有计算都提前在训练时做完（amortized）。Diffusion 和 flow 的 policy 在推理时迭代几步到几十步，autoregressive 的模型逐个 token 生成，MPC 每个周期解一次优化。迭代换来的是表达能力和对新情况的适应，代价是延迟。分层的 dual-system 结构就是在频率和表达能力之间做的折中：慢的那层可以迭代、可以大，快的那层必须一步到位。

26可以拿来讨论的问题

这些问题目前没有公认的答案。每一条下面是我的初步看法，用来引出讨论，不是结论。

机器人为什么还没有它的"GPT 时刻"？缺的到底是什么？

最直接的回答是数据。语言模型的训练数据是互联网上人类写下的全部文字，量级是万亿个 token，而且天然就是"输入和输出同一种格式"。机器人需要的是带 action 的数据，互联网上没有，只能一小时一小时地采。公开的大规模真机数据集是几百到几千小时的量级；π0 用了一万小时以上；也有公司自报的私有数据达到几十万小时（例如 Generalist AI 的 GEN-0，2025 年底报告 27 万小时）。和互联网文本相比，这仍然少得多，而且每多一个数量级都要靠真金白银的采集。

但数据可能不是唯一的原因。语言是人已经压缩和抽象过的符号；物理世界的 observation 高维、连续、有噪声，而且任务要求闭环、实时、容错率低。也没有一个像"预测下一个 token"那样既简单又包含一切的统一目标。现在的几条路线（遥操作车队、仿真、人的视频、world model 生成数据）都在赌数据这一环，哪一条能走通还不清楚。

压缩得好就等于"理解"了吗？

第 05 节说了精确的那一半：要把数据压得短，模型必须利用数据里的规律。但"利用了统计规律"和"有一个能在分布外正确推理的模型"之间有距离。对机器人来说有一个更具体的版本：一个能生成逼真视频的 world model，是否就知道物理？逼真的画面主要靠纹理和光照，而对控制重要的接触、质量、摩擦在像素里占的比重极小。我倾向于认为，预测目标必须包含 action 的后果，学到的东西才会偏向控制需要的那部分。

Action 应该用离散 token 还是连续的 flow / diffusion？

离散 token 的好处是和语言模型的整套东西兼容：同一个 loss，可以和图文数据无缝混合训练，梯度不会干扰预训练的知识。连续的 head 的好处是精度和速度。两条路线一直在互相靠近：FAST 让 token 路线能处理高频数据；也有工作让主干用 token 的 loss 学、同时用 flow 的 head 来执行。可能最后的答案是"训练时两个都用，推理时用连续的"。更深的问题是：action 有没有一个像 subword 那样自然的"词"？

Vision encoder 应该冻住还是 fine-tune？用哪一种预训练？

冻住能保留预训练带来的鲁棒性，但 encoder 当初丢掉的信息（比如为了语义不变性而丢掉的精确位置）再也拿不回来。Fine-tune 能找回任务需要的信息，但 robot 数据少，容易把泛化能力训掉。OpenVLA 的实验是 fine-tune 更好；把语义型和几何型的两个 encoder 拼起来也是一种回答。这个问题的本质是第 24 节的第 2 条：encoder 的 representation 是被它原来的训练目标逼出来的，而那个目标不是控制。

Sim-to-real RL 能不能像征服 locomotion 一样征服 manipulation？

障碍有三个：接触丰富的操作（尤其是软物体）仿真不准；视觉的 sim-to-real gap 比 dynamics 的大；reward 难写。但每一个都在被推进：更好的接触仿真和 real-to-sim；用 depth 或点云绕开 RGB 的 gap；用 demonstration 或语言模型来生成 reward。灵巧手的手内操作已经是 sim-to-real RL 的成功例子。我的看法是，刚体、短时程、可以用几何描述的技能会先被 RL 拿下，长时程和需要语义的部分仍然靠 imitation，两者通过分层结合。

End-to-end 的大模型，还是分层的系统？接口应该是什么？

纯粹的端到端在机器人上还没有发生：频率的差距（大模型每秒几次，电机控制每秒上千次）本身就强制了分层。真正的问题是层与层之间的接口由谁定。人定的接口（速度命令、keypoint、语言子任务）可解释、各层可以分开训练，但限制了上层能表达的东西。学出来的 latent 接口表达力强，但两层必须一起训练，而且难以调试。一个有用的判断标准：好的接口应该让上层的错误容易被下层纠正，而不是被放大。

World model 是必需的吗？

Model-free 的方法在 locomotion 和很多 manipulation 任务上已经足够好，所以答案显然不是"必需"。World model 的价值在三个地方：样本贵的时候省样本；提供梯度让优化更高效（SuperMimic）；以及作为数据生成器和评估器，绕开真机实验的成本。最后一条可能最重要：现在评估一个 manipulation policy 只能在真机上一次次地试，又慢又有噪声，这直接限制了研究的迭代速度。

怎么评估一个 robot policy？

视觉和语言都有公认的 benchmark，可以在固定的数据上算一个数。机器人的评估要在物理世界里执行，结果依赖具体的硬件、物体、光照，不同实验室之间很难比较，甚至同一个实验室隔一天都不完全可复现。仿真 benchmark 可复现但和真机表现的相关性有限。这个问题比看起来的更根本：没有可靠的评估，就很难判断哪些改进是真的。读论文时，对成功率的数字要比对视觉 benchmark 的数字多一分保留。

Learned controller 没有稳定性证明，这件事该怎么看？

经典控制的保证来自对模型的假设；模型不准时保证也就不成立了，只是失效的方式比较温和。Learning 的"保证"是统计意义上的：在训练分布内成功率很高。两者的弱点互补，所以实际的系统经常叠在一起：learning 负责性能，外面套一层基于模型的限幅、碰撞检测或安全滤波。更长远的问题是能不能让模型知道自己不知道：在分布外的输入上给出低置信度，然后交给保守的控制器。

建议的顺序

每一步都对应一个你在机器人论文里已经见过的词，并且有一个能亲手做的小实验。

  1. 训练一个 MLP。用 PyTorch 拟合一个一维函数，再做 MNIST 分类。目标是亲眼看到 loss 曲线、overfitting，并亲手写一次 backward。对应第 02 到 04 节。
  2. Autoencoder 和 VAE。在 MNIST 上训练，把 latent 设成 2 维并画出来，在 latent space 里插值。对应第 07、08 节。
  3. 从零写一个小 Transformer。Karpathy 的 nanoGPT 是标准的入门材料。目标是能不看资料写出 self-attention。对应第 09、11 节。
  4. Diffusion 或 flow matching。在二维的 toy 数据上训练一个 flow matching 模型，就是把实验 5 里的解析速度场换成一个 MLP。对应第 14 节。
  5. RL。在一个现成的 legged 环境里跑通 PPO，改一项 reward 看行为怎么变。对应第 15 节。
  6. 回到机器人。读 Diffusion Policy 和 ACT 的代码，对照第 19 节把每个模块认出来；再读一篇 VLA（OpenVLA 或 π0），对照第 20 节。
  7. 走一遍完整的 pipeline。用 LeRobot 这类开源框架，下载一个公开数据集，训练 ACT，在仿真里闭环评估，按第 23 节的方法报成功率和置信区间。
  8. 写一次 code as policy。在仿真里准备 detect、pick、place 几个 API，让 LLM 写程序完成桌面任务，看它在哪里失败。对应第 21 节。

读一篇 learning 论文时问的六个问题

  1. 把它写成"根据 A 预测 B"：A 是什么，B 是什么？
  2. B 从哪来？人标的、数据自身、专家、另一个模型，还是只有 reward？
  3. 输出是一个值还是一个分布？如果是分布，用的是哪种输出头？
  4. 输入和输出被表示成什么？有没有 tokenizer、latent、action chunk？
  5. 数据从哪来，有多少？训练分布和部署时会遇到的情况差在哪？
  6. 哪些部分是预训练的、冻住的、从头训练的？梯度流过哪些模块？
