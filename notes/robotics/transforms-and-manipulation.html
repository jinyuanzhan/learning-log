02Rotation matrix 与 SO(3)

所有 3D rotation 组成的集合叫 SO(3)（special orthogonal group）。写成矩阵就是：

SO(3) = { R ∈ ℝ³ˣ³ | RᵀR = I, det(R) = +1 }
  • RᵀR = I：三列互相垂直、长度都是 1（orthonormal）。所以 R⁻¹ = Rᵀ，求 inverse 不用真的去算。
  • det(R) = +1：保持右手系。det = −1 的是 reflection（镜像），不是 rotation。
  • 9 个数，6 个约束（3 个长度 + 3 个垂直），所以只有 3 个 degree of freedom。

列是什么

这是最该记住的一句话：Ra_b 的三列，就是 frame b 的 x、y、z 轴在 frame a 里的坐标。反过来，三行是 frame a 的三个轴在 frame b 里的坐标。

Ra_b = [ x̂b ŷb ẑb ] （每个都写成 a 里的坐标）

验证方法：R · (1,0,0)ᵀ 取出的是第一列，而 (1,0,0) 就是 b 的 x 轴在 b 自己里面的坐标。

同一个矩阵的三种用法

用法怎么读例子
表示 orientationframe b 相对 frame a 怎么摆“末端相对 base 的朝向”
换坐标（passive）点不动，换一个 frame 来描述它：pa = Ra_b pb把相机里看到的点换到 base 里
转动一个向量（active）frame 不动，把向量转到新位置：v′ = R v把夹爪绕 z 转 90°

passive 和 active 用的是同一个矩阵，只是解读不同。容易混的地方是：“把 frame 转 +θ”和“把点转 −θ”在坐标上的效果相同，所以两种解读正好差一个 inverse。写代码时先说清楚你的 R 是 Ra_b 还是 Rb_a，比记 passive / active 更可靠。

组合与基本性质

Ra_c = Ra_b · Rb_c 相邻的下标相消 Rb_a = (Ra_b)ᵀ inverse 就是 transpose，下标对调 R₁R₂ ≠ R₂R₁ 3D rotation 一般不可交换（§08） trace(R) = 1 + 2cos θ θ 是这个 rotation 转过的总角度
  • 绕单个坐标轴的基本 rotation（后面反复用到）：
    Rx(φ) = 1000cφ−sφ0sφcφ Ry(θ) = cθ0sθ010−sθ0cθ Rz(ψ) = cψ−sψ0sψcψ0001
  • SO(3) 是一个 group，不是 vector space：两个 rotation 相乘还是 rotation，但相加、直接取平均都不再是 rotation。
  • 数值误差会让 R 慢慢不再 orthonormal。修正方法：做 SVD，R = UΣVᵀ，取 R ← UVᵀ（若 det 为 −1，把 U 的最后一列取反）。AprilTag 那一页从 H 恢复 R 时用的就是这一步。
为什么需要别的表示法？

rotation matrix 没有 singularity、组合就是矩阵乘法，是“最老实”的表示。但 9 个数只表达 3 个自由度：存储冗余、不能直接插值、放进 optimizer 里要带 6 个约束。所以实际中 Euler angles 用来给人看，quaternion 用来存储和插值，axis-angle 用来做优化和算误差，rotation matrix 用来做计算。

04Euler angles 与 gimbal lock

Euler angles 把一个 rotation 拆成依次绕三个坐标轴的三次转动。三个数，直观，适合给人看和输入。问题全部出在“依次”这两个字上。

先把 convention 问清楚

“Euler angles 是 (30°, 20°, 40°)”这句话本身没有意义，必须同时说明三件事：

  • 轴的顺序：共 12 种。三根轴都不同的 6 种叫 Tait–Bryan angles（如 ZYX，就是 yaw-pitch-roll）；首尾同轴的 6 种叫 proper Euler angles（如 ZYZ，机械臂 wrist 常用）。
  • intrinsic 还是 extrinsic：intrinsic 是每次绕转过之后的 body 轴转；extrinsic 是每次绕固定的 world 轴转。
  • 单位（degree / radian）和每个角的正方向（右手定则）。

一个必须记住的等价关系：intrinsic ZYX 和 extrinsic XYZ 是同一个矩阵。

R = Rz(yaw) · Ry(pitch) · Rx(roll) intrinsic 读法（从左往右）：先绕 z 转 yaw，再绕新的 y 转 pitch，再绕更新的 x 转 roll extrinsic 读法（从右往左）：先绕固定 x 转 roll，再绕固定 y 转 pitch，再绕固定 z 转 yaw

ROS 的 RPY（tf 的 setRPY、URDF 里的 rpy）就是这个：fixed-axis X-Y-Z，矩阵是 RzRyRx。本页的实验台也用它。展开后：

R = cψcθcψsθsφ − sψcφcψsθcφ + sψsφsψcθsψsθsφ + cψcφsψsθcφ − cψsφ−sθcθsφcθcφ ψ = yaw, θ = pitch, φ = roll

从 R 反解

pitch = −asin(R₃₁) yaw = atan2(R₂₁, R₁₁) roll = atan2(R₃₂, R₃₃)

用 atan2 不用 atan，才能拿到正确的象限。asin 的输入先 clamp 到 [−1, 1]，否则数值误差会给出 NaN。

Gimbal lock

看上面矩阵的第一列和第三行：当 pitch = ±90° 时 cθ = 0，R₁₁, R₂₁, R₃₂, R₃₃ 全是 0，两个 atan2 都变成 atan2(0, 0)。此时矩阵里只剩下 roll − yaw（pitch = +90°）或 roll + yaw（pitch = −90°）这一个组合。

几何上：pitch 转了 90° 之后，roll 的转轴（body 的 x 轴）被转到和 yaw 的转轴（world 的 z 轴）共线。三根转轴只张成一个平面，有一个方向的转动表达不出来。回到 §03 的实验台点“gimbal lock”可以直接看到两根虚线重合。

定量地看，Euler angle 的变化率和 angular velocity 之间差一个矩阵，它的三列就是三根转轴：

ω = [ ẑ ŷ′ x̂″ ] · (yaẇ, pitcḣ, rolİ)ᵀ det = −cos(pitch)

pitch = ±90° 时这个矩阵不可逆：要产生某个方向的 ω，需要无穷大的 Euler angle 速率。这和 §16 机械臂的 singularity 是同一件事，三轴相交的 wrist 本质上就是一组机械的 Euler angles。

常见误解

gimbal lock 不是“物体卡住转不动了”。物体本身可以随便转，是 Euler angles 这种参数化在那个姿态附近失效：同一个姿态对应无穷多组角度，角度会突变，微分关系变 singular。任何只用 3 个数表示 rotation 的方法都必然有这样的 singularity，换轴顺序只是把它挪到别处。

其他 pitfalls

  • 不唯一：(ψ, θ, φ) 和 (ψ+π, π−θ, φ+π) 是同一个 rotation。通常把 pitch 限制在 [−90°, 90°] 来消歧。
  • ±180° 跳变：角度从 179° 到 −179° 实际只差 2°。直接相减做控制误差会出大错。
  • 不能逐分量相减或插值：两组 Euler angles 的差不是两个 orientation 之间的 rotation；线性插值走的也不是最短路径（§06 的 SLERP 实验台有对比）。
  • 不同库的默认 convention 不同：scipy 的 from_euler('xyz') 小写是 extrinsic，'XYZ' 大写是 intrinsic；Eigen 的 eulerAngles(2,1,0) 返回范围和你想的可能不一样。换库时用一个已知姿态核对。

什么时候可以放心用：给人显示、UI 输入、姿态变化很小、或者问题本身只有一个角（移动机器人的 heading）。

05Axis-angle、Rodrigues 公式与 exponential map

Euler’s rotation theorem：任何 3D rotation 都等价于绕某一根固定轴 ω̂（单位向量）转一个角度 θ。这就是 axis-angle。把两者乘在一起，r = θ·ω̂，只用 3 个数，叫 rotation vector（OpenCV 的 rvec、cv2.Rodrigues 用的就是它）。

Skew-symmetric matrix

把 cross product 写成矩阵乘法：ω × v = [ω]× v。

[ω]× = 0−ωzωyωz0−ωx−ωyωx0 [ω]×ᵀ = −[ω]×

所有 3×3 skew-symmetric matrix 组成 so(3)（小写），是 SO(3) 的 Lie algebra，可以理解成“所有可能的 angular velocity”。它是一个普通的 3 维 vector space，可以相加、缩放。

Rodrigues 公式（axis-angle → R）

R = I + sin θ · K + (1 − cos θ) · K² 其中 K = [ω̂]×

它其实是 matrix exponential 的闭式解：R = exp(θ·[ω̂]×)。直觉：以恒定 angular velocity ω̂ 转 θ 秒，解微分方程 Ṙ = [ω̂]×R 得到的就是它。这个从 so(3) 到 SO(3) 的映射叫 exponential map。

Log map（R → axis-angle）

θ = acos( (trace(R) − 1) / 2 ) ω̂ = 1/(2 sin θ) · ( R₃₂ − R₂₃, R₁₃ − R₃₁, R₂₁ − R₁₂ )ᵀ

Pitfalls

  • θ ≈ 0：转轴没有定义，公式里除以 sin θ ≈ 0。实现里用 Taylor 展开，或者直接返回 r = 0。
  • θ ≈ π：R − Rᵀ ≈ 0，上面的公式同样失效。改从 (R + I)/2 = ω̂ω̂ᵀ 的对角线里取转轴，或者先转成 quaternion 再取。
  • 不唯一：(ω̂, θ)、(−ω̂, −θ)、(ω̂, θ + 2π) 是同一个 rotation。通常约定 θ ∈ [0, π]。
  • rotation vector 不能相加：exp(r₁)·exp(r₂) ≠ exp(r₁ + r₂)，除非两根轴平行或者角度很小。
  • acos 的输入先 clamp 到 [−1, 1]。

它在哪里最有用

  • Orientation error：控制和 IK 里需要一个 3 维的“朝向误差”。e = log(Rd · Rᵀ) 给出“从当前转到目标”的 rotation vector，方向是转轴、长度是角度，可以直接乘 gain。
  • 在 manifold 上做优化：不直接优化 R 的 9 个数，而是优化一个 3 维的小增量 δ，每步更新 R ← R · exp([δ]×)。没有约束，也没有 singularity（因为 δ 始终很小）。bundle adjustment、SLAM、hand-eye 的非线性 refinement 都这么做。
  • 积分 angular velocity：R(t+Δt) = R(t) · exp([ωbodyΔt]×)。
  • hand-eye calibration：§11 的解法直接用到 log map。

06Quaternion 与 SLERP

unit quaternion 用 4 个数表示 rotation，带一个约束 ‖q‖ = 1。可以把它看成 axis-angle 换了一种存法：

q = (w, x, y, z) = ( cos(θ/2), ω̂ · sin(θ/2) )

注意是 θ/2。这一个“半角”是 double cover 的来源，也是 quaternion 运算能写成乘法的原因。

运算

乘法（Hamilton product） q₁ ⊗ q₂ = ( w₁w₂ − v₁·v₂, w₁v₂ + w₂v₁ + v₁ × v₂ ) 组合 qa_c = qa_b ⊗ qb_c 顺序和 rotation matrix 一样 inverse q⁻¹ = q* = (w, −x, −y, −z) 仅对 unit quaternion 成立 转一个向量 (0, p′) = q ⊗ (0, p) ⊗ q* 两个 rotation 的夹角 θ = 2·acos( |q₁ · q₂| )

Quaternion ↔ rotation matrix

R = 1 − 2(y² + z²)2(xy − wz)2(xz + wy)2(xy + wz)1 − 2(x² + z²)2(yz − wx)2(xz − wy)2(yz + wx)1 − 2(x² + y²)

反方向（R → q）最朴素的写法是 w = ½√(1 + trace R)，然后 x = (R₃₂ − R₂₃)/(4w) 等等。但 θ 接近 180° 时 w ≈ 0，除法数值上不稳定。标准做法（Shepperd’s method）是比较 trace, R₁₁, R₂₂, R₃₃ 哪个最大，先算出 w, x, y, z 中最大的那个，再用它去除别的。实际中直接调库，但面试会问“θ = 180° 时怎么办”。

Double cover：q 和 −q 是同一个 rotation

绕 ω̂ 转 θ 和绕 −ω̂ 转 2π − θ 到达同一个姿态。代进定义，后者正好是 −q。也可以直接看：q p q* 里 q 出现两次，负号抵消。所以每个 rotation 对应 unit sphere S³ 上的两个对跖点。实际影响：

  • 比较：判断两个 quaternion 是否表示同一姿态，要看 |q₁·q₂| ≈ 1，不能逐分量比。
  • 插值：SLERP 之前检查 q₁·q₂ < 0，是的话把其中一个取反，否则会绕远路（下面的实验台可以关掉这个检查看效果）。
  • 连续性：从一串连续变化的 R 里逐帧提取 q，符号可能突然翻转。滤波、求导、画曲线之前要逐帧对齐符号。
  • 求平均、做 loss：直接对分量求平均或算 L2 loss 之前先把符号统一；神经网络回归 quaternion 时常用 1 − |q̂·q| 这类对符号不敏感的 loss。
  • 控制误差：用 qe = qd ⊗ q* 的向量部分做反馈时，若 we < 0 要取反，否则机器人会朝大于 180° 的那一侧转（unwinding）。

其他 pitfalls

  • 存储顺序：数学书和 Eigen 的构造函数是 (w, x, y, z)；ROS message、scipy、Eigen 的 coeffs() 是 (x, y, z, w)。MuJoCo 是 (w, x, y, z)。顺序搞错是最常见的 bug，而且结果“看起来像个 rotation”，不会报错。
  • Hamilton vs JPL：两套乘法 convention（ij = k 还是 ij = −k）。机器人和 ROS 用 Hamilton；部分航天、VIO 文献（如 MSCKF）用 JPL。
  • 忘记 normalize：数值积分或优化后 ‖q‖ 会漂。不是 unit 的 quaternion 转出来的 R 带缩放。每次更新后 normalize。
  • 积分 angular velocity：q̇ = ½ · q ⊗ (0, ωbody)。

插值：SLERP

spherical linear interpolation 沿 S³ 上的大圆弧走，对应绕一根固定轴、以恒定 angular velocity 从 q₀ 转到 q₁，是两个姿态之间最短、最均匀的路径。

slerp(q₀, q₁, t) = [ sin((1−t)Ω) · q₀ + sin(tΩ) · q₁ ] / sin Ω cos Ω = q₀ · q₁

Ω ≈ 0 时分母接近 0，退化成普通线性插值再 normalize（NLERP）。NLERP 路径相同、速度不完全均匀、便宜，游戏和实时系统里很常用。

从 identity 插值到目标姿态（按住拖动换视角）

SLERP：x 轴和 z 轴尖端的轨迹 Euler angles 线性插值的轨迹

读数

粗的 frame 是 SLERP 在 t 时刻的姿态；细的半透明 frame 是 Euler 插值的姿态。两者起点终点相同，中间不同。

试一试：① 拖 t，SLERP 的轨迹是大圆弧，Euler 插值的轨迹是一条歪的曲线，而且速度不均匀。② 勾上“不做 shortest-path 检查”：终点姿态完全一样，但 SLERP 绕了 360° − θ 的远路。③ 把 pitch 调到接近 90°，Euler 插值的轨迹会明显扭曲。

一句话总结 quaternion

优点：没有 gimbal lock，4 个数，组合便宜，normalize 一下就能修正数值漂移，插值简单正确。缺点：不直观，有 double cover，有 unit 约束（放进 optimizer 时仍然要用 §05 的 3 维增量）。

不需要背 12 条两两互转的公式。记住以 rotation matrix（或 quaternion）为中心的 6 条就够了，其余的都先转到中心再转出去：

转换时的检查清单

  • Euler：顺序是什么？intrinsic 还是 extrinsic？degree 还是 radian？
  • Quaternion：(w,x,y,z) 还是 (x,y,z,w)？normalize 了吗？和上一帧符号一致吗？
  • R：是 Ra_b 还是 Rb_a？（差一个 transpose，是最常见的错）
  • R 是测量或估计出来的吗？如果是，先用 SVD 投影回 SO(3) 再转。
  • acos / asin 的输入 clamp 了吗？在 θ = 0、θ = π、pitch = ±90° 这三个特殊点测过吗？
  • 两边的 frame convention 一致吗？camera optical frame 是 z 朝前、x 朝右、y 朝下；ROS 的 body frame 是 x 朝前、y 朝左、z 朝上。两者之间差一个固定的 rotation，漏掉它姿态会差 90°。
  • 有没有混进 left-handed 的系统（Unity、部分图形引擎）？那不是 rotation 能解决的，需要一次 reflection。
万能的验证方法

拿一个不对称的已知姿态（比如 yaw 30°、pitch 20°、roll 40°，三个角都不同且不是 0 / 90°），转过去再转回来，看是否还原；再把它作用在 (1,0,0) 上，看结果是否符合直觉。用 identity 或 90° 这种特殊值测不出 convention 错误。

08Composition order：左乘还是右乘

3D rotation 不可交换，所以 A·B 和 B·A 是两个不同的姿态。面试里真正考的是：给你一个乘积，你能不能说出它在物理上是“先做什么、绕谁的轴做”。

R = A · B 读法一（从左往右，绕 body 轴）：先做 A；再绕 转过之后的新轴 做 B 读法二（从右往左，绕 fixed 轴）：先做 B；再绕 固定不动的 world 轴 做 A

两种读法描述的是同一个矩阵、同一个最终姿态。由此得到一条规则：

右乘（post-multiply）：新的 rotation 是在当前 body frame 里描述的。
左乘（pre-multiply）：新的 rotation 是在 fixed / world frame 里描述的。

对 4×4 的 transform 完全一样。两个实际例子：

  • “夹爪沿自己的 z 轴（approach 方向）前进 5 cm”：Tnew = Tbase_ee · Trans(0, 0, 0.05)，右乘。
  • “夹爪沿 base 的 z 轴竖直抬高 5 cm”：Tnew = Trans(0, 0, 0.05) · Tbase_ee，左乘。

09SE(3) 与 homogeneous transform

rigid body 的 pose = orientation + position，共 6 个 degree of freedom。所有 rigid body transform 组成 SE(3)（special Euclidean group）。把 R 和 t 装进一个 4×4 矩阵，rotation 加 translation 就变成一次矩阵乘法：

Ta_b = Ra_bta_b0 0 01 pa = Ra_b · pb + ta_b ⇔ pa1 = Ta_b pb1
  • Ra_b：b 的三个轴在 a 里的方向。
  • ta_b：b 的原点在 a 里的坐标。（验证：把 b 的原点 pb = 0 代进去，得到 pa = t。）

组合与 inverse

Ta_c = Ta_b · Tb_c = R₁R₂R₁t₂ + t₁01 Tb_a = (Ta_b)⁻¹ = Rᵀ−Rᵀt01
最常见的错误

inverse 的 translation 是 −Rᵀt，不是 −t。直觉：t 是 b 的原点在 a 里的坐标；反过来要的是 a 的原点在 b 里的坐标，所以除了取反，还要用 Rᵀ 把它换到 b 的轴上。

点和方向

homogeneous 坐标的最后一位区分两种东西：点写成 (x, y, z, 1)，会被 translation 影响；方向 / 自由向量（速度、力、法向量、轴）写成 (x, y, z, 0)，只被 R 转动。把 normal 或 velocity 当成点去乘 T，是另一个常见 bug。

再往深一步（知道概念即可）

  • 存储：实际中 pose 常存成 (t, q) 共 7 个数（ROS 的 geometry_msgs/Pose），计算时再转成 4×4。
  • 插值：position 做线性插值，orientation 做 SLERP，分开处理。
  • Twist 与 se(3)：rigid body 的速度是一个 6 维向量 V = (ω, v)，叫 twist。和 SO(3) 一样有 exponential map：T = exp([S]θ)，表示绕一根空间中的 screw axis 边转边平移。Modern Robotics 的 product of exponentials（§12）就建立在它上面。
  • Adjoint：点换 frame 用 T，twist 换 frame 要用 6×6 的 adjoint：Va = Ad(Ta_b) · Vb，其中 Ad(T) = [R, 0; [t]×R, R]。wrench（力和力矩）用它的 transpose。直觉：平移一个 frame 之后，同一个转动在新原点处会多出一项线速度 t × ω。
  • Pose error：位置误差 pd − p 加上朝向误差 log(RdRᵀ)，拼成 6 维。位置和朝向单位不同（米和 radian），加权时要小心。

AX = XB 是怎么来的（eye-in-hand）

把机械臂移到第 i 个姿态，记录两样东西：FK 给出的 Ei = Tbase_ee，以及相机看 target 得到的 Ci = Tcam_target。target 固定在桌上，所以绕一圈 chain 得到的 Tbase_target 每次都一样：

A 和 B 描述的是同一次刚体运动，只是一个在 ee frame 里看、一个在 cam frame 里看。X 就是这两个 frame 之间的换算。eye-to-hand 的推导完全一样，只是不变量换成 Tee_target，得到 A = EjEi⁻¹、B = CjCi⁻¹、X = Tbase_cam。

怎么解

把 4×4 的方程拆成 rotation 和 translation 两部分：

rotation RA RX = RX RB translation (RA − I) · tX = RX tB − tA
  1. 先解 RX。第一个式子改写成 RA = RX RB RXᵀ：A 和 B 是相似的，转角相同，转轴差一个 RX。取 log map，α = log(RA)、β = log(RB)，就有 α = RX β。每一对运动给出一组对应的向量，求把所有 β 对齐到 α 的最佳 rotation。这是标准的 Kabsch / orthogonal Procrustes 问题，用 SVD 一步解出（Park & Martin 的方法）。
  2. 再解 tX。把 RX 代进第二个式子，对 tX 是线性的。把所有运动的方程摞起来，做 linear least squares。
  3. （可选）非线性 refinement。以上面的解为初值，直接最小化所有图像上的 reprojection error，同时优化 X 和 Tbase_target。

其他经典解法：Tsai–Lenz（也是先 R 后 t，最常用的默认方法）、Horaud（quaternion）、Daniilidis（dual quaternion，R 和 t 同时解）。OpenCV 里是一个函数：

    R_gripper2base, t_gripper2base,   # 每个姿态的 T_base_ee（FK）
    R_target2cam,   t_target2cam,     # 每个姿态的 T_cam_target（solvePnP）
    method=cv2.CALIB_HAND_EYE_PARK)
# eye-to-hand：把第一组输入换成 T_ee_base（即 FK 结果取 inverse），输出就是 T_base_cam

需要什么样的数据

  • 至少 2 次相对运动（3 个姿态），且两次运动的转轴不平行。一次运动只给出一对 (α, β)：一个方向对齐了，但绕这个方向还可以任意转，RX 定不下来。同理 (RA − I) 的 rank 只有 2，沿转轴方向的 tX 也定不下来。
  • 纯 translation 的运动对 tX 没有信息。RA = I 时 translation 方程的左边是 0。
  • 转角要大。转角越小，α, β 越短，噪声占比越大。
  • 实际操作：采 15 – 30 个姿态，绕至少两三根不同的轴各转 30° 以上，target 始终完整地在视野里，不要太远也不要太斜。

Manipulation 基础

知道了目标 pose 之后：关节该转到多少（kinematics），怎么不碰撞地过去（motion planning），电机怎么跟上（control）。

12Forward kinematics

机械臂有两个描述它的空间：

  • Joint space（configuration space）：关节角向量 q = (q₁, …, qn)。电机直接控制的是它。
  • Task space（Cartesian / operational space）：end-effector 的 pose x ∈ SE(3)。任务是用它描述的。

Forward kinematics（FK）：已知 q，求 end-effector 的 pose。它就是 §10 的 transform chain，只不过每一环是一个关节：

Tbase_ee(q) = T0_1(q₁) · T1_2(q₂) · … · Tn−1_n(qn) · Tn_ee

FK 永远有解、解唯一、有闭式表达，直接乘就行。难的是反过来（§14）。

Planar arm 的例子

平面上的 2-link arm，link 长度 l₁, l₂，关节角 q₁, q₂（q₂ 是相对上一个 link 的角度）：

x = l₁c₁ + l₂c₁₂ y = l₁s₁ + l₂s₁₂ φ = q₁ + q₂ （末端朝向）

3-link 再加一项 l₃c₁₂₃、l₃s₁₂₃。规律：每个 link 的方向角是它之前所有关节角的和。

几个术语

  • Degree of freedom（DOF）：独立关节数。空间中任意 pose 需要 6 个，所以通用机械臂是 6-DOF。
  • Redundant：DOF 比任务需要的多（7-DOF 的 Franka、iiwa）。同一个末端 pose 对应无穷多组 q，多出来的自由度可以用来避障、避 singularity。
  • Workspace：末端能到达的所有位置是 reachable workspace；能以任意朝向到达的是 dexterous workspace，后者小得多。

Analytical IK：2-link 的推导

目标 (x, y)。base、elbow、末端构成一个三角形，三条边是 l₁、l₂ 和 r = √(x² + y²)。对 elbow 处的角用 law of cosines：

cos q₂ = (x² + y² − l₁² − l₂²) / (2 l₁ l₂) q₂ = ± acos(…) 正负号对应 elbow-down / elbow-up q₁ = atan2(y, x) − atan2( l₂ sin q₂, l₁ + l₂ cos q₂ )

Numerical IK 的 pitfalls

  • 只找到一个解，而且是离初值最近的那个。初值不同，结果不同。连续运动时用当前 q 做初值，保证解连续不跳变；全局求解时用多个随机初值重启（TRAC-IK 的做法）。
  • Local minima：特别是加了 joint limit 之后会卡住。
  • Joint limit：纯 pseudoinverse 不管 limit。做法是 clamp、在 null-space 里推离 limit，或者直接写成带约束的优化问题（SQP）。
  • 解的选择：多个解里选哪个？一般选离当前 q 最近的、离 joint limit 和 singularity 最远的、不碰撞的。

Redundancy 与 null-space

redundant arm 的 J 是“扁”的（行少列多），存在一些关节速度不会让末端动，它们构成 J 的 null-space。(I − J⁺J) 把任意向量投影到 null-space 里：

q̇ = J⁺ ẋ + (I − J⁺J) · q̇₀ 主任务 次要任务：不影响末端

q̇₀ 常取某个目标函数的 gradient：远离 joint limit、增大 manipulability、远离障碍物、保持舒服的姿势。实验台里勾上 null-space 看到的就是这一项。

15Jacobian

Jacobian 是 FK 对关节角的导数，把关节速度映射成末端速度：

ẋ = J(q) · q̇ J = ∂FK/∂q , 完整形式是 6 × n： vω = J q̇

它是 q 的函数：arm 的形状变了，J 就变了。它是 manipulation 里出现频率最高的一个矩阵。

每一列的含义

第 i 列 = 只有关节 i 以单位速度转动时，末端的速度。对 revolute joint，末端绕关节轴 ẑi 做圆周运动：

revolute: Ji = ẑi × (pee − pi)ẑi prismatic: Ji = ẑi0

线速度是 ω × r：垂直于“关节到末端的连线”，大小正比于这段距离。实验台里的彩色箭头就是这些列，可以验证每个箭头都垂直于对应关节到末端的连线。这样逐列写出来的叫 geometric Jacobian。

2-link planar arm 直接对 FK 求偏导也能得到：

J = −l₁s₁ − l₂s₁₂−l₂s₁₂l₁c₁ + l₂c₁₂l₂c₁₂ det(J) = l₁ l₂ sin q₂

补充：如果朝向用 Euler angles 之类的参数表示，对参数求导得到的是 analytic Jacobian，它和 geometric Jacobian 差一个把 Euler rate 换成 ω 的矩阵（§04 那个），并且继承了 Euler angles 的 singularity。

Jacobian 的六个用途

  1. 速度映射：ẋ = J q̇。反过来 q̇ = J⁺ ẋ 叫 resolved-rate control，用来让末端走直线、做 visual servoing、teleoperation。
  2. Numerical IK：§14 的三种迭代都靠它。
  3. 力的映射（statics）：τ = Jᵀ F。末端要对外施加力 F，各关节需要出的 torque 是 JᵀF。推导用 virtual work：关节做的功等于末端做的功，τᵀq̇ = Fᵀẋ = FᵀJq̇ 对任意 q̇ 成立。这是 impedance control（§22）的基础，也可以反过来用关节 torque 估计外力。
  4. Singularity 分析：J 掉 rank 的地方（§16）。
  5. Manipulability：对 J 做 SVD，J = UΣVᵀ。所有满足 ‖q̇‖ = 1 的关节速度，映射到 task space 是一个椭球，主轴方向是 U 的列，半轴长是 singular value σi。长轴方向末端容易动，短轴方向难动。力的椭球正好相反（半轴 1/σi）：容易动的方向不容易出力，难动的方向能出大力。
  6. 误差传播：关节的小误差 δq 造成末端误差 J δq；covariance 传播是 JΣJᵀ。
一个细节

J 是在哪个 frame 里表达的要说清楚：末端速度写在 base frame 里还是 ee frame 里，两者差一个 rotation。另外注意 Modern Robotics 的 space Jacobian 不是“末端速度在 base frame 里的表达”：它给的是 spatial twist，线速度部分是和 base 原点重合的那个点的速度；它和 body Jacobian 之间差一个 adjoint。上面逐列写出的 geometric Jacobian 才是末端点的速度。算误差 e 用的 frame 必须和 J 一致。检查 J 实现对不对的最简单方法：和 finite difference (FK(q + εei) − FK(q))/ε 对比。

16Singularity

Singularity 是 J 掉 rank 的 configuration：J 的列不再张满 task space，末端在某个方向上瞬时无法运动，不管关节怎么转。

会发生什么

  • 丢失一个方向的运动能力。例如 arm 完全伸直时，末端无法沿 arm 的方向再向外或向内动（一阶近似下）。
  • 附近关节速度爆炸。q̇ = J⁻¹ẋ，J 接近 singular 时 J⁻¹ 的元素趋于无穷。让末端以正常速度走一条经过 singularity 附近的直线，某些关节需要转得极快。真机上表现为突然甩动、超速报警停机。
  • IK 的解分支在这里汇合。elbow-up 和 elbow-down 在伸直时变成同一个解；有的 singularity 上有无穷多解。
  • 力的一面：在 singular 方向上，τ = JᵀF = 0。结构本身就能扛住这个方向的力，电机不用出力。人伸直手臂推墙、锁住膝盖站立，利用的就是这一点。

怎么检测

det(J) = 0 只适用于方阵 σmin(J) → 0 最小的 singular value，最直接 w = √det(JJᵀ) = σ₁σ₂···σm Yoshikawa 的 manipulability，椭球的体积 κ = σmax / σmin condition number，越大越接近 singular

实际中不是判断“等于 0”，而是给 σmin 或 w 设一个阈值，低于它就认为太近了。

怎么处理

  • Damped least squares：给求逆加阻尼，singularity 附近牺牲一点跟踪精度换取有界的关节速度。λ 可以随 σmin 变小而自动加大。
  • 在 joint space 里规划和插值：singularity 只在 Cartesian → joint 的换算里出问题。直接插值 q 可以平稳穿过。
  • 规划时避开：把 manipulability 低于阈值的区域当作障碍，或者放进 cost。
  • 用 redundancy：7-DOF arm 在 null-space 里调整姿势，保持 manipulability。
  • 布局上避开：让工作区域落在 workspace 的中部，不要让任务贴着边界或者正好在 base 的正上方。

17Configuration space

Motion planning 的问题：从 qstart 到 qgoal，找一条连续的、不碰撞、不超 joint limit 的 path。关键的抽象是 configuration space（C-space）：以关节角为坐标轴的空间。

  • arm 的一个完整姿态，在 C-space 里只是一个点。
  • workspace 里的障碍物，映射成 C-space 里的一片区域 Cobs：所有会让 arm 的任何部分撞上障碍的 q。其余部分是 Cfree。

Arm 的完整规划流程

  1. 目标 pose 用 IK 换成 goal configuration（可能有多个，都可以当 goal）。
  2. 在 joint space 里用 planner 找一条无碰撞的 path：只有几何，没有时间。
  3. 后处理：shortcut、smoothing。
  4. Time parameterization：在 velocity、acceleration 限制下给 path 配上时间，变成 trajectory。
  5. controller 跟踪这条 trajectory（§20 – §22）。

18RRT 家族

Rapidly-exploring Random Tree：从 start 长一棵树，每次朝一个随机点的方向长一小步，直到碰到 goal。

tree = {q_start}
loop:
    q_rand = 以概率 p 取 q_goal，否则在 C-space 里均匀随机采样      # goal bias
    q_near = tree 里离 q_rand 最近的节点                        # nearest neighbor
    q_new  = 从 q_near 朝 q_rand 走一步，步长不超过 step_size      # steer
    if q_near → q_new 这一段不碰撞:                             # collision check
        把 q_new 加进 tree，parent 设为 q_near
        if q_new 离 q_goal 足够近: 沿 parent 指针回溯，得到 path，结束

为什么它探索得快

树上每个节点“负责”C-space 里离它最近的那片区域（Voronoi region）。树边缘的节点面对着大片空白，Voronoi region 最大，随机点落进去的概率也最大，所以它们最常被选中去延伸。结果是树天然地被拉向还没探索过的地方，这叫 Voronoi bias。下面实验台刚开始的几十步可以清楚看到树先伸向四面八方。

三个参数

  • Step size：太大，在障碍多的地方每次延伸都撞，树长不动；太小，要很多节点才能铺开。
  • Goal bias：通常 5% – 10%。为 0 时只能靠运气碰到 goal；太大时树被障碍挡住仍一味朝 goal 长，失去探索能力。
  • Collision check 的分辨率：一条 edge 是按固定间隔采点检查的。间隔太大可能“穿过”薄的障碍。它也是整个算法最耗时的部分，通常占 90% 以上的时间。

性质

  • probabilistically complete；不 optimal，path 通常绕远而且有很多折角，必须后处理。
  • single-query：每次规划从头建树。不需要预先构造 C-space。对高维有效。
  • narrow passage 是弱点：窄缝的体积在整个 C-space 里占比很小，采样很难落进去。
  • 无解时不会停，只能设超时。

换一个思路：不去“搜索”一条路，而是先随便给一条 trajectory（比如从 start 到 goal 的直线，哪怕它穿过障碍），然后把它当成优化变量，一点点往好的方向推。

Path 和 trajectory

Path 只有几何：q(s), s ∈ [0, 1]。Trajectory 带时间：q(t)，于是有 velocity 和 acceleration。从 path 到 trajectory 的那一步叫 time parameterization，常见的做法：

  • Trapezoidal velocity profile：匀加速 → 匀速 → 匀减速。最简单，acceleration 不连续。
  • Cubic polynomial：4 个系数，满足两端的 position 和 velocity。acceleration 连续但两端不为 0。
  • Quintic polynomial：6 个系数，满足两端的 position、velocity、acceleration。jerk 有界，运动更柔和。
  • Time-optimal parameterization（TOPP-RA、MoveIt 的 TOTG）：沿给定 path，在每个关节的 velocity / acceleration 限制内尽可能快。

实际实现里必须处理的事

  • Integral windup：actuator saturate 时误差消不掉，积分项越积越大；等误差反向后要很久才能“放完”，造成大 overshoot。Anti-windup：saturate 时停止积分（clamping / conditional integration），或者把超出部分反馈回去减小积分（back-calculation），或者直接给积分项设上下限。
  • Derivative kick：reference 突变时 ė 是一个尖峰。改成只对 measurement 求导：用 −Kd ẏ 代替 Kd ė。
  • Noise：求导放大高频 noise。给 D 项加 low-pass filter，或者直接用 velocity sensor / encoder 差分后滤波的速度。
  • Feedforward：已知的东西不要等误差出现再纠正。u = uff + PID(e)，比如 gravity compensation、按期望 acceleration 算出的 torque。feedback 只负责处理模型没覆盖的部分。
  • Sampling rate：离散实现里 loop 频率要远高于系统带宽，dt 要稳定。关节层的 loop 通常是 1 kHz 或更高。
  • Cascaded loops：电机驱动里通常是 position loop → velocity loop → current（torque）loop 三层嵌套，内层比外层快一个量级。
integral, prev_y = 0.0, y0
def pid_step(r, y, dt):
    global integral, prev_y
    e = r - y
    d = -(y - prev_y) / dt                 # derivative on measurement，避免 derivative kick
    u = Kp * e + Ki * integral + Kd * d
    u_sat = clip(u, -u_max, u_max)
    if u == u_sat or e * u < 0:            # anti-windup：saturate 且还在往同方向推时不再积分
        integral += e * dt
    prev_y = y
    return u_sat

22Impedance control

为什么接触任务不能只用 position control

position controller 的目标是不惜代价消除位置误差，gain 很高，等效于一根很硬的弹簧。在自由空间里这很好。但一旦要接触环境（插孔、擦桌子、拧螺丝、开门），环境也很硬：目标位置只要比实际表面深 1 mm，高 stiffness 乘上这 1 mm 就是很大的力；如果还有 I 项，力会一直累加到电机饱和。结果是损坏零件、触发保护停机，或者把东西推飞。而位置误差 1 mm 是很正常的（标定、感知误差都在这个量级）。

反过来，pure force control 在没有接触时没有东西可以“推”，会一直加速。

思路：控制力和运动之间的关系

impedance control 不去单独控制位置或者力，而是规定末端被推离目标时应该怎样回应。让末端表现得像一个连在目标位置上的 mass–spring–damper：

F = K · (xd − x) + D · (ẋd − ẋ) 想要的末端行为：虚拟 spring + damper τ = Jᵀ F + g(q) 映射成关节 torque，并补偿重力
  • 不需要 force sensor：力是通过 Jᵀ 和电机 torque 实现的。但需要 torque-controlled 的机器人，而且关节摩擦要小或者有 joint torque sensor 做补偿。
  • 稳态接触力可以预测：末端被表面挡住时，F = K · (xd − xsurface)。想用 5 N 的力压住桌面，就把目标设在桌面以下 5/K 米处。
  • 各方向可以不同：K 是一个矩阵。插孔时，沿孔的方向硬一点（要推进去），横向软一点（让孔壁把 peg 自然导正）。
  • D 的选择：按 critical damping，D = 2ζ√(K·m)，ζ 取 0.7 – 1。
  • 没有 I 项：I 项会把“被挡住的位置误差”一直累加成越来越大的力，正好破坏了 compliance。

1-D 仿真：质量 m = 1 kg 的末端从 x = 0 出发，目标在 2.5 s 内匀速移到 xd；途中有一面很硬的墙（stiffness 20 000 N/m）

  • Hybrid position / force control：把 task space 的方向分成两组。被环境约束住的方向（如垂直于桌面）做 force control，自由的方向（沿桌面）做 position control，用一个 selection matrix 切换。需要知道接触的几何。

  • Variable impedance：K 随任务阶段变化：自由运动时硬，接近接触时变软。也可以让 learning policy 输出 K。
  • 和 PD 的关系：公式几乎一样。区别在出发点：PD 调 gain 是为了让 tracking error 尽量小；impedance control 的 K、D 是对交互行为的规定，会故意取小，并且依靠模型补偿（重力、惯性）而不是高增益来保证自由空间里的精度。

23面试题与答案

Rotation 与 transform

1. Rotation matrix 的三列代表什么？为什么它的 inverse 等于 transpose？

Ra_b 的三列是 frame b 的 x、y、z 轴在 frame a 里的坐标。三根轴互相垂直且长度为 1，所以 RᵀR 的每个元素是两列的内积：对角线是 1，其余是 0，即 RᵀR = I，于是 R⁻¹ = Rᵀ。几何上，transpose 之后行变成列，得到的是 a 的轴在 b 里的坐标，正好是反方向的 rotation。

2. 一个 3×3 矩阵满足什么条件才是 rotation matrix？测量得到的 R 不满足怎么办？

RᵀR = I 且 det(R) = +1。det 为 −1 的是 reflection。带噪声的估计值通常不严格满足，做 SVD R = UΣVᵀ，取 UVᵀ；如果它的 det 是 −1，把 U 的最后一列取反再乘。这给出 Frobenius norm 意义下最近的 rotation。

3. Gimbal lock 是什么？怎么避免？

用 Euler angles 时，中间那个角转到特定值（ZYX 顺序下是 pitch = ±90°），第一根和第三根转轴变得共线，三个角只能表达两个方向的转动，丢了一个自由度。表现为同一姿态对应无穷多组角度、反解时角度突变、Euler rate 到 angular velocity 的矩阵不可逆。

它是参数化的 singularity，不是物体真的卡住。任何 3 参数表示都有。避免方法：内部计算、存储、插值用 quaternion 或 rotation matrix，只在显示给人看时转成 Euler angles；或者选一个让 singularity 落在工作范围之外的轴顺序。

4. 为什么大家用 quaternion？它有什么缺点？

优点：没有 gimbal lock；只有 4 个数；组合是一次 quaternion 乘法，比矩阵便宜；数值漂移后 normalize 一下就修正了，而修正 rotation matrix 要做 SVD；插值（SLERP）简单且走最短路径。

缺点：不直观；有 double cover（q 和 −q 是同一个 rotation）；有 unit norm 约束，放进 optimizer 时要用 3 维的 local 增量；存储顺序（wxyz / xyzw）和 Hamilton / JPL convention 容易混。

5. q 和 −q 表示同一个 rotation，实际中会带来什么问题？
  • 插值：不检查符号会绕远路。SLERP 前若 q₀·q₁ < 0，把一个取反。
  • 比较和 loss：要用 |q₁·q₂|，不能逐分量相减。
  • 时间序列：逐帧从 R 提取的 q 可能突然变号，滤波或求导前要对齐符号。
  • 平均：先统一符号再平均并 normalize（或者用基于特征向量的方法）。
  • 反馈控制：误差 quaternion 的 w 为负时取反，否则会朝大于 180° 的方向转。
6. 怎么在两个 orientation 之间插值？为什么不直接对 Euler angles 做线性插值？

用 SLERP：[sin((1−t)Ω)q₀ + sin(tΩ)q₁] / sin Ω，其中 cos Ω = q₀·q₁。它等价于绕一根固定轴匀速转过去，是最短路径，angular velocity 恒定。先做 shortest-path 检查；Ω 很小时退化为 lerp 再 normalize。等价的写法是 R(t) = R₀ · exp(t · log(R₀ᵀR₁))。

Euler angles 线性插值的问题：路径不是最短的，转速不均匀，结果依赖轴顺序，经过 gimbal lock 附近时会乱转，还有 ±180° 的跳变。

7. 怎么衡量两个 rotation 差多少？控制里的 orientation error 怎么算？

相对 rotation Re = RdRᵀ，它的转角 θ = acos((trace(Re) − 1)/2) 就是两者的“距离”（geodesic distance）。用 quaternion 是 θ = 2·acos(|q₁·q₂|)。

控制里需要一个 3 维向量：取 e = log(RdRᵀ)，即转轴乘转角；或者用误差 quaternion 的向量部分（小角度时约等于前者的一半）。不能把两组 Euler angles 相减。

8. A·B 和 B·A 有什么区别？左乘和右乘分别是什么意思？

3D rotation 不可交换。R·ΔR（右乘）表示在当前 body frame 里再做一个 ΔR；ΔR·R（左乘）表示在 fixed / world frame 里做 ΔR。例子：夹爪沿自己的 z 轴前进用右乘 T·Trans(0,0,d)；沿 world 的 z 轴上升用左乘 Trans(0,0,d)·T。

由此也得到：intrinsic ZYX 和 extrinsic XYZ 是同一个矩阵 RzRyRx。

9. 写出 SE(3) 的 inverse。为什么 translation 不是简单取负？

T⁻¹ = [Rᵀ, −Rᵀt; 0, 1]。从 pa = R pb + t 解出 pb = Rᵀ(pa − t) = Rᵀpa − Rᵀt。t 是 b 的原点在 a 里的坐标；inverse 需要的是 a 的原点在 b 里的坐标，方向相反并且要换到 b 的轴上表达，所以多一个 Rᵀ。

10. 已知 T_base_cam 和 T_cam_tag，求 T_base_tag。如果已知的是 T_base_tag 和 T_base_cam，求 T_cam_tag 呢？

Tbase_tag = Tbase_cam · Tcam_tag，相邻的 cam 相消。

Tcam_tag = (Tbase_cam)⁻¹ · Tbase_tag = Tcam_base · Tbase_tag。左边的已知量从左边乘 inverse 消掉。检查方法永远是看下标能不能连起来。

11. 相机测到的物体 pose 换到 base frame 之后，位置差了几厘米。你怎么排查？
  1. 把 chain 上每个 transform 的下标写出来，确认顺序和 inverse。
  2. 逐项检查：camera intrinsics（重新标定或看 reprojection error）；tag / 物体的尺寸参数；hand-eye 结果（用它算多个姿态下固定 target 的位置，看散布）；FK（关节零位）。
  3. 看误差的规律：是固定的 offset（多半是 translation 标定或 TCP 定义），还是随距离变大（intrinsics、tag size 或 rotation 标定），还是随机械臂姿态变化（hand-eye 的 rotation 部分或时间同步）。
  4. frame convention：optical frame 和 body frame 是否混用，单位是 m 还是 mm。
12. Axis-angle 和 rotation vector 是什么？exponential map 用在哪？

任何 rotation 等价于绕一根单位轴 ω̂ 转角度 θ。r = θω̂ 是 rotation vector，3 个数、没有约束。Rodrigues 公式 R = I + sinθ·K + (1−cosθ)·K² 就是 exp([r]×)。

用途：① 表示 orientation error；② 优化时作为 R 的 3 维增量，R ← R·exp([δ]×)，避免约束和 singularity；③ 积分 angular velocity。缺点：θ = 0 时轴无定义，θ 接近 π 时提取轴的数值不稳定，不能直接相加来组合。

Hand-eye calibration

13. AX = XB 是怎么来的？A、B、X 各是什么？

以 eye-in-hand 为例：target 固定在桌上，所以对每个姿态 Tbase_target = Tbase_ee,i · X · Tcam_target,i 都相同，X = Tee_cam。取两个姿态令其相等并整理，得 A X = X B，其中 A = Tbase_ee,j⁻¹Tbase_ee,i 是 end-effector 的相对运动（来自 FK），B = Tcam_target,jTcam_target,i⁻¹ 是 camera 的相对运动（来自视觉）。直觉：A 和 B 是同一次刚体运动在两个 frame 里的表达，X 是这两个 frame 之间的固定关系。

14. Hand-eye calibration 至少需要几组数据？对运动有什么要求？

至少 2 次相对运动，也就是 3 个姿态，并且两次运动的转轴不能平行。原因：rotation 部分等价于 α = RXβ（α、β 是 A、B 的转轴乘转角）。一对向量只能确定 RX 到“绕这根轴任意转”的程度，需要两对不平行的向量才能唯一确定。translation 方程 (RA − I)tX = … 的系数矩阵 rank 为 2，同样需要两根不同的轴。纯 translation 的运动对 tX 没有约束。

实际中采 15 – 30 个姿态，绕多根轴、转角尽量大，用 least squares 平均掉噪声。

15. Eye-in-hand 和 eye-to-hand 有什么区别？各自标定的是什么？

Eye-in-hand：相机装在末端，求 Tee_cam，标定时 target 固定在环境里。优点是可以凑近看、精度高、没有手臂遮挡问题；缺点是视野随手动，抓取的最后阶段可能看不到物体。

Eye-to-hand：相机固定在外面，求 Tbase_cam，标定时 target 装在末端。优点是视野固定、能看全局；缺点是手臂可能挡住物体，离得远精度低。两者都是 AX = XB，只是 A 的构造方式不同。

Kinematics

16. FK 和 IK 的区别？IK 为什么难？

FK：关节角 → 末端 pose，把每个关节的 transform 连乘，解唯一、有闭式。IK：末端 pose → 关节角，是解非线性方程组：可能无解（workspace 外、超 joint limit），可能有多个解（6R 最多 8 或 16 个），redundant 时有无穷多个，一般结构没有闭式解，数值解依赖初值、可能卡在 local minimum，在 singularity 附近不稳定。

17. 推一下 2-link planar arm 的 IK。

目标 (x, y)。由 law of cosines：cos q₂ = (x² + y² − l₁² − l₂²)/(2l₁l₂)，q₂ = ±acos(·)，两个符号对应 elbow-up 和 elbow-down。然后 q₁ = atan2(y, x) − atan2(l₂ sin q₂, l₁ + l₂ cos q₂)：第一项是目标的方位角，第二项是 link 1 和“base 到目标连线”之间的夹角。|cos q₂| > 1 时无解。

18. Analytical IK 和 numerical IK 怎么选？

Analytical：快（微秒级）、给出全部解、没有收敛问题；但只适用于特定结构（如 spherical wrist），每种 arm 要单独推导（或用 IKFast 生成）。Numerical：通用，容易加约束和次要目标，能处理 redundant arm；但只给一个解、依赖初值、可能不收敛、慢一些。能用 analytical 的场合（工业 6R、需要枚举所有解来选最优）优先用它；7-DOF 或非标准结构用 numerical。

19. Jacobian 是什么？怎么得到某一列？它有哪些用途？

ẋ = J(q)q̇，是 FK 对 q 的偏导，6×n。第 i 列是关节 i 单独以单位速度运动时末端的 twist：revolute joint 是 [ẑi × (pee − pi); ẑi]，prismatic 是 [ẑi; 0]。

用途：速度映射和 resolved-rate control；numerical IK；力映射 τ = JᵀF；判断 singularity；manipulability 分析；误差和 covariance 传播。

20. τ = Jᵀ F 是怎么来的？

Virtual work / 功率守恒：关节输出的功率等于末端对外输出的功率，τᵀq̇ = Fᵀẋ。代入 ẋ = Jq̇ 得 τᵀq̇ = FᵀJq̇，对任意 q̇ 成立，所以 τ = JᵀF。它说明：想在末端施加某个力，不需要 force sensor，直接算出关节 torque 即可；在 singularity 处某些方向的 F 对应 τ = 0，结构自己扛着。

21. Singularity 是什么？物理上会发生什么？怎么检测和处理？

J 掉 rank 的 configuration。末端在某个方向上瞬时不能动；在附近，要让末端沿那个方向以有限速度运动，关节速度趋于无穷；IK 的不同解分支在这里汇合。典型的有 elbow 伸直（boundary）、wrist 的 joint 4 和 6 共线、wrist center 落在 joint 1 轴线上。

检测：σmin(J)、manipulability √det(JJᵀ)、condition number。处理：damped least squares；在 joint space 里规划；规划时避开低 manipulability 区域；redundant arm 用 null-space 调姿势；把工作区域安排在 workspace 中部。

22. Pseudoinverse、damped least squares、Jacobian transpose 三种 IK 有什么区别？

Pseudoinverse J⁺e：最小二乘意义下的精确解，收敛快（Newton 型），redundant 时取 norm 最小的 Δq；但 singularity 附近 1/σmin 爆炸。

DLS Jᵀ(JJᵀ + λ²I)⁻¹e：每个 singular value 方向上的增益从 1/σ 变成 σ/(σ² + λ²)，σ 大时几乎不变，σ → 0 时趋于 0 而不是无穷。稳定，代价是 singular 方向上收敛慢。

Transpose αJᵀe：gradient descent，不求逆，绝不会爆，计算最便宜；收敛慢。它能用是因为 Jᵀe 是 ½‖e‖² 的负 gradient 方向。

23. Redundant arm 的 null-space 是什么？能用来干什么？

当关节数多于 task 维度时，存在不改变末端的关节运动，即满足 Jq̇ = 0 的 q̇，构成 J 的 null-space。q̇ = J⁺ẋ + (I − J⁺J)q̇₀，第二项把任意的 q̇₀ 投影进 null-space，用来在不影响主任务的前提下做次要任务：避开 joint limit、避开障碍、远离 singularity、保持某个偏好的姿势（像人的 elbow 可以在手不动时摆动）。

Motion planning

24. 什么是 configuration space？为什么要在里面规划？

以所有关节变量为坐标的空间，arm 的一个完整姿态是其中一个点。障碍物映射成 Cobs（所有会碰撞的 configuration）。这样，带形状的机器人的规划问题变成点在 Cfree 里的规划问题，可以用统一的算法处理。难点是 C-space 维度高、Cobs 无法显式表示，所以用 sampling-based 方法，只把 collision checker 当黑盒调用。

25. 讲一下 RRT 的流程。它为什么能快速探索？

从 start 建树。循环：随机采样 qrand（以小概率直接取 goal）；找树上最近的节点 qnear；从它朝 qrand 走一个 step size 得到 qnew；如果这段无碰撞就加入树；qnew 够近 goal 就回溯出 path。

快速探索来自 Voronoi bias：树外围节点的 Voronoi region 大，被随机点选中的概率高，所以树优先向未探索区域延伸。性质：probabilistically complete，不 optimal，single-query。

26. RRT、RRT*、RRT-Connect、PRM 怎么区分？
  • RRT：单棵树，可行但不最优。
  • RRT-Connect：start 和 goal 各一棵树，互相贪心地连接，实际中快很多，是 arm 规划的默认选择。
  • RRT*：加 choose-parent 和 rewire，asymptotically optimal，更慢。Informed RRT* 在找到初解后只在椭球内采样来加速。
  • PRM：预先建 roadmap（graph），multi-query，适合静态环境里反复规划。
27. RRT 出来的 path 又绕又抖，怎么办？

① Shortcut：随机取 path 上两点，直线段无碰撞就替换中间部分，重复多次。② 用 spline 拟合或者做 trajectory optimization，以 RRT 的结果为初值。③ 直接用 RRT* / Informed RRT* 多跑一会儿。④ 最后做 time parameterization，满足 velocity 和 acceleration 限制，才能交给 controller。

28. Sampling-based planner 和 optimization-based planner 各有什么优缺点？

Sampling-based：probabilistically complete，不依赖初值，复杂环境里可靠；但 path 质量差需要后处理，narrow passage 慢，不容易加入 smoothness 之类的目标。

Optimization-based：输出直接平滑，简单环境里很快，容易加各种 cost 和约束；但只做 local 优化，依赖初值，会卡在 local minimum，没有找到解的保证。常见的组合是先 sampling 找可行解，再 optimization 打磨。

29. Path 和 trajectory 有什么区别？

Path 是纯几何的一串 configuration，没有时间。Trajectory 是时间的函数 q(t)，包含 velocity 和 acceleration。planner 通常输出 path，再经过 time parameterization（trapezoidal profile、polynomial、TOPP-RA）得到满足动力学限制的 trajectory，controller 跟踪的是 trajectory。

30. Cubic 和 quintic polynomial trajectory 的区别？

Cubic 有 4 个系数，可以满足起点和终点的 position、velocity 共 4 个边界条件，acceleration 在端点处不为 0，多段拼接时 acceleration 会跳变。Quintic 有 6 个系数，还能指定两端的 acceleration（通常为 0），acceleration 连续、jerk 有界，运动更平滑，对机械的冲击小。

Control

31. PID 三项各自的作用？怎么调？

P 按当前误差出力，决定响应速度，太大振荡；I 累积误差，消除恒定 disturbance 造成的 steady-state error，太大会 overshoot 和 windup；D 按误差变化率出力，提供阻尼、抑制 overshoot，但放大 noise。

手动调：先 P 到快而略振荡，加 D 压住，最后加 I 消除残差。或者 Ziegler–Nichols 找临界 gain 和周期作为起点。有模型时按期望的 natural frequency 和 damping ratio 直接算。

32. Integral windup 是什么？怎么解决？

actuator saturate 时，实际输出小于 controller 要求的值，误差迟迟消不掉，积分项持续增长到很大。等到达目标后，积分项还要靠反向误差慢慢“放掉”，期间输出一直偏大，造成大幅 overshoot 和很长的恢复时间。

解决：saturate 时停止积分（clamping）；back-calculation（把 saturate 前后的差值反馈回去减积分）；给积分项设上下限；误差很大时不启用 I 项。

33. D 项在实际中有什么问题？

① 放大高频 measurement noise，让控制量抖动、电机发热：加 low-pass filter 或用滤波后的速度信号。② Derivative kick：reference 阶跃时误差的导数是尖峰：改成只对 measurement 求导。③ 离散求导对采样周期的抖动敏感。

34. 只用 PD 控制一个受重力的关节，会有什么现象？怎么改进？

会有 steady-state error：平衡时 Kpe = g(q)，所以 e = g(q)/Kp，手臂“垂”一点。改进：加 I 项；或者更好的是加 gravity compensation feedforward，τ = Kpe + Kdė + g(q)，直接用模型抵消重力，没有 I 项的副作用。

35. 为什么接触任务不用纯 position control？讲一下 impedance control，以及它和 admittance control 的区别。

Position control 等效于很硬的弹簧，环境也硬，毫米级的位置误差就会产生很大的接触力，带 I 项还会一直加到饱和。Impedance control 不单独控制位置或力，而是让末端表现得像连在目标上的 spring–damper：F = K(xd − x) + D(ẋd − ẋ)，τ = JᵀF + g(q)。K 小就 compliant，接触力 ≈ K × 位置偏差，是可预测、有界的。

Impedance：测运动、输出力，用在 torque-controlled arm 上，硬接触时稳定。Admittance：测力（F/T sensor）、输出位置指令，用在 position-controlled arm 上，自由空间精度高但硬接触时容易不稳定。

36. 完整讲一遍：相机看到桌上一个带 AprilTag 的方块，机械臂把它抓起来。
  1. 感知：检测 tag 角点，用 intrinsics 解出 Tcam_tag。
  2. Transform chain：Tbase_obj = Tbase_ee·Tee_cam·Tcam_tag·Ttag_obj，其中 Tee_cam 来自 hand-eye calibration，Tbase_ee 来自 FK。
  3. Grasp pose：Tbase_ee* = Tbase_obj·Tobj_grasp，再沿 approach 方向后退一段得到 pre-grasp pose。
  4. IK：把 pre-grasp 和 grasp pose 解成关节角，选离当前姿态近、离 joint limit 和 singularity 远、无碰撞的解。
  5. Motion planning：joint space 里 RRT-Connect 规划到 pre-grasp，shortcut + time parameterization；pre-grasp 到 grasp 走 Cartesian 直线。
  6. Control：关节 controller 跟踪 trajectory；接近和闭合夹爪阶段用 impedance control 或者降低 stiffness，容忍几毫米的位置误差。
  7. 闭环与检查：抓取后确认夹爪开度或力，失败则重新感知。

能主动指出每一步的误差来源（标定、tag 检测、FK、时间同步）会加分。
