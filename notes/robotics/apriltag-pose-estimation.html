AprilTag 位姿估计笔记

相机看到一个 tag，就能算出它在三维空间中的位置和朝向。这份笔记把这件事从头推到尾：每个公式都说明变量的含义、单位和来源，并配一个可以拖动的实验台，页面上的数字全部由它实时算出。

01全局图景

AprilTag 是贴在物体上的黑白方块图案。相机拍到它，可以得到两样东西：

  • ID：这是哪一个 tag。由内部的黑白格子编码。
  • 位姿：tag 相对相机的位置和朝向，共 6 个数。位置 t 是 3 个数，说明 tag 中心在哪里。朝向 R 有 3 个自由度，说明 tag 怎么转的。

整个计算是一条流水线，后面每一节讲其中一步：

  1. 在图像中找到 tag 的四个角点，读出它们的像素坐标。
  2. 用四组对应点列方程，解出单应矩阵 H（用 SVD）。
  3. 用内参 K 拆开 H，得到 R 和 t。
  4. 用 H 读出内部格子的黑白，得到 ID。
  5. 把相机到 tag 的位姿，沿变换链传回机械臂基座。

有三个概念贯穿始终，先分清楚：

概念它是什么什么时候变从哪里来
相机坐标系原点在光心，Z 轴朝前，X 朝右，Y 朝下相机移动时约定
内参 K相机自身的属性：一条光线落在哪个像素不变（换镜头或改分辨率才变）相机标定
外参 [R | t]两个坐标系之间的刚体关系，这里是 tag 相对相机tag 或相机一动就变AprilTag 实时算出

值得亲手试的几件事

  • 只动焦距：tag 和相机都没动，外参不变。图像平面离光心变远，图像里的 tag 变大。内参只管光线怎么变成像素。
  • 动上下或左右平移：H 的第三列跟着变。这一列就是 tag 中心的像素坐标。
  • 只旋转：H 的第三列不变，因为 tag 绕自己的中心转，中心没有移动。前两列在变。
  • 把所有旋转归零：H 的第三行前两个数是 0，图像里是正方形。一倾斜，这两个数不再为 0，正方形变成梯形。透视效果藏在这两个数里。
  • 加像素噪声并拉远：反推的位姿开始偏离真值，角度比位置偏得更多。

03坐标系与外参

同一个点，在不同坐标系里有不同的坐标。tag 的左上角在 tag 自己的坐标系里永远是 (−0.025, −0.025, 0)，但在相机坐标系里的坐标取决于 tag 摆在哪里。外参就是换算规则：

Pc = R · Ptag + t
符号含义单位例子
Ptag点在 tag 坐标系中的坐标。原点在 tag 中心，X 朝右，Y 朝下，Z 垂直纸面朝里米(0.025, 0, 0)
R3×3 旋转矩阵。它的三列 r1 r2 r3 是 tag 的 X、Y、Z 轴在相机坐标系中的方向无正对相机时是单位矩阵
ttag 中心在相机坐标系中的坐标米(0.08, 0, 0.40)
Pc同一个点在相机坐标系中的坐标米(0.105, 0, 0.40)

表中的例子是 tag 正对相机的情形：R 是单位矩阵，所以 Pc = (0.025, 0, 0) + (0.08, 0, 0.40)。

怎样读 R看列。第一列回答"tag 的 X 轴现在指向相机的哪个方向"。例如 r1 = (0, 1, 0) 表示 tag 的 X 轴指向相机的 Y 方向（朝下），也就是 tag 在平面内转了 90°。

4×4 的写法

把 R 和 t 拼成一个 4×4 矩阵 T，换坐标系就变成一次矩阵乘法。多个变换首尾相接时，直接连乘即可。第 11 节会用到。

Tcam_tag = Rt0 0 01 下标读作"tag 在 cam 坐标系中的位姿"

04相机模型与内参 K

针孔相机的成像只有一条规则：物体上的点、光心、像点，三者在一条直线上。从侧面看是一对相似三角形。

成像分两步。

第一步：除以深度，得到归一化坐标

x = Xc / Zc， y = Yc / Zc

(x, y) 没有单位。它只描述光线的方向，等价于"这条光线在 Z = 1 的平面上打在哪里"。它与相机的焦距和分辨率无关。

第二步：用 K 把归一化坐标变成像素

u = fx · x + cx， v = fy · y + cy K = fx0cx0fycy001
符号含义单位实验台中的值
fx, fy焦距，用像素衡量。等于物理焦距除以单个像素的宽度（或高度）。数值越大，视野越窄，物体在图像中越大像素400, 400
cx, cy主点：光轴打在图像上的像素位置，通常接近图像中心。因为像素坐标的原点在左上角，所以要加这个偏移像素160, 120
u, v像素坐标。u 向右，v 向下像素见下例

数字例子：点在相机坐标系中是 (0.08, 0, 0.40)。归一化坐标 x = 0.08 / 0.40 = 0.2，y = 0。像素 u = 400 × 0.2 + 160 = 240，v = 400 × 0 + 120 = 120。

K 是归一化吗？方向反了一步。K 把归一化坐标变成像素。K⁻¹ 把像素变回归一化坐标，所以"归一化"对应的是 K⁻¹。它的作用是把相机的个体差异（焦距、分辨率）去掉，只留下光线方向。

K⁻¹ 我们知道吗？知道。K 来自相机标定：用棋盘格拍几十张照片后由 OpenCV 算出，或由相机驱动直接提供（如 ROS 的 camera_info），课程项目通常直接给定。有了 K，K⁻¹ 可以直接写出：

K⁻¹ = 1/fx0−cx/fx01/fy−cy/fy001 即 x = (u − cx) / fx， y = (v − cy) / fy

注意一个不可逆的地方：除以 Zc 之后，深度丢失了。一个像素只能还原成一条光线，无法知道点在光线上多远。AprilTag 能恢复深度，靠的是已知 tag 的真实边长。

05完整投影方程

把第 3 节的换坐标系和第 4 节的成像合在一起，就是那条看起来很抽象的式子：

s · uv1 = K · r11r12r13txr21r22r23tyr31r32r33tz · XYZ1

从右往左读，正好是成像的顺序：

部分含义单位
[X, Y, Z, 1]ᵀ点在 tag 坐标系中的坐标。末尾的 1 是为了让"加 t"也能写成矩阵乘法（齐次坐标）米
[R | t]外参，3×4。乘完得到点在相机坐标系中的坐标 (Xc, Yc, Zc)R 无单位，t 是米
K内参，3×3。乘完得到 (fx·Xc + cx·Zc, fy·Yc + cy·Zc, Zc)像素
s就是深度 Zc。把右边三个数都除以第三个数，才得到 (u, v, 1)米
[u, v, 1]ᵀ像素坐标的齐次形式像素

"除以第三个数"这一步很重要。它意味着右边整体乘以任何非零常数，得到的像素都不变。这个性质在下一节变成"H 只有 8 个自由度"。

06单应矩阵 H

tag 是一张平面。把 tag 坐标系建在这张平面上，所有点的 Z = 0。代入投影方程，r3 那一列永远乘以 0，可以直接删掉：

s · uv1 = K · r1r2t · XY1 = H · XY1

H = K · [r1 r2 t] 是一个 3×3 矩阵。它把 tag 平面上的点 (X, Y)（米）直接映射到图像上的像素 (u, v)。

H 的每一列是什么

H 的列等于含义怎么验证
第 1 列K · r1tag 的 X 轴方向，被 K 包了一层在实验台里做面内旋转，前两列变
第 2 列K · r2tag 的 Y 轴方向，被 K 包了一层同上
第 3 列K · t代入 (X, Y) = (0, 0) 得到的正是这一列，所以它是 tag 中心的像素（h33 归一后）只平移时变，只旋转时不变

H 为什么不包含 tag 的 Z 轴方向？因为 tag 上没有任何一个点离开过 Z = 0 的平面。r3 始终乘以 0，它不影响任何一个像素，图像里也就没有关于它的直接信息。但信息并没有丢失：旋转矩阵的三列互相垂直且构成右手系，所以 r3 = r1 × r2，知道前两列就能算出第三列。

为什么是 8 个未知数

H 有 9 个元素。但 H 和 2·H 算出的像素完全相同，因为最后要除以第三个分量。整体尺度没有意义，所以有效的未知数是 8 个。习惯上把 h33 归一为 1，或者规定 9 个元素的平方和为 1。

求 H 有什么用

  • 恢复位姿：R 和 t 无法直接测量，但 H 只用四组对应点就能解出，而它里面正好装着 r1、r2、t。它是位姿的"加密版"，K 是钥匙。
  • 解码 ID：知道 H，就能算出 tag 内部任何一点落在图像的哪里，从而去读黑白格子。

07四个角点解 H

先分清楚哪些量已知，哪些未知。这是整个推导的关键。

量状态为什么例子
X, Y已知角点在 tag 自己坐标系中的坐标。tag 是你打印的，边长是你量的。拍照之前就知道，与相机无关边长 5 cm 时，四个角是 (±0.025, ±0.025)
u, v已知检测算法在图像里找到角点，直接读出像素坐标实验台里的红点
h11 … h33未知它描述 tag 怎么摆放，这正是要求的实验台里的 H

换一个说法：你知道物体的真实形状（X、Y），也看到了它在照片中的样子（u、v），唯一不知道的是它怎么摆的。

一个点给出两个方程

把 H · [X, Y, 1]ᵀ 展开，再除以第三个分量：

u = (h11X + h12Y + h13) / (h31X + h32Y + h33)

把分母乘到左边，再全部移到一侧：

h11X + h12Y + h13 − u·h31X − u·h32Y − u·h33 = 0

式中 X、Y、u 是具体的数字，未知的只有 9 个 h。所以这是关于 h 的线性方程，可以写成"一行系数乘以 h 等于 0"。对 v 做同样的事，再得一行：

XY1000−uX−uY−u000XY1−vX−vY−v · h = 0

其中 h = [h11, h12, h13, h21, h22, h23, h31, h32, h33]ᵀ，是把 H 按行排成的一列。

四个点叠起来

每个角点 2 行，4 个角点共 8 行，得到 8×9 的矩阵 A，方程是 A · h = 0。8 个方程正好对应 8 个自由度，所以最少需要 4 个点。下面是实验台当前状态下真实的 A：

每两行来自一个角点。前三列和中间三列填的是 X、Y、1（米），后三列混入了像素坐标。拖动实验台，后三列随之变化。

h = 0 永远满足这个方程，但没有意义。我们要的是非零解，这需要 SVD。

08SVD 复习

奇异值分解（SVD）说的是：任何矩阵都可以拆成三个简单矩阵的乘积。

A = U · Σ · Vᵀ
符号形状（A 是 m×n）性质含义
Vᵀn×n正交矩阵：各列互相垂直，长度为 1把输入旋转到一组特殊的方向上
Σm×n只有对角线上有数，即奇异值 σ1 ≥ σ2 ≥ … ≥ 0沿每个方向分别缩放
Um×m正交矩阵把结果旋转到输出的方向上

几何上，任何线性变换都等于"旋转，沿坐标轴缩放，再旋转"。V 的每一列是一个输入方向，对应的奇异值说明 A 把这个方向拉伸了多少倍。

一个小例子：A = [[2, 0], [0, 0.1]]。它把 x 方向拉长 2 倍，把 y 方向压到 0.1 倍。所有长度为 1 的向量里，(1, 0) 被拉得最长，(0, 1) 被压得最短。一般的矩阵也是这样，只是这两个特殊方向不再沿坐标轴，而是 V 的各列。

用途一：解 A · h = 0

为了排除 h = 0，规定 ‖h‖ = 1（反正 H 的整体尺度没有意义）。问题变成：在所有长度为 1 的向量里，找一个让 ‖A·h‖ 最小的。

答案是 V 的最后一列，即最小奇异值对应的方向。推导只有三行：

  1. ‖A·h‖ = ‖U·Σ·Vᵀ·h‖ = ‖Σ·Vᵀ·h‖。旋转不改变长度，所以 U 可以去掉。
  2. 令 y = Vᵀ·h。旋转不改变长度，所以 ‖y‖ = 1。于是 ‖A·h‖² = σ1²y1² + σ2²y2² + … + σn²yn²。
  3. 要让这个和最小，就把全部权重放在最小的 σn 上：y = (0, …, 0, 1)。对应的 h = V·y 就是 V 的最后一列。

实验台当前 A 的奇异值如下。严格地说 8×9 的矩阵只有 8 个奇异值；A 只有 8 行，所以 9 维的输入空间里必然有一个方向被它压成 0（null space，V 的第 9 列），这里把它记成 σ9 = 0（数值上是极小的数）。这个方向就是我们要的 h。

高亮的是最小奇异值。它对应的 V 的那一列，除以最后一个元素后重排成 3×3，就是实验台里显示的 H。

正好 4 个点时，最小奇异值恰好为 0，解是精确的。如果用更多的点（比如标定棋盘格），方程多于未知数，最小奇异值不再是 0，这时 V 的最后一列是最小二乘意义下的最优解。两种情况用同一段代码。

用途二：把矩阵拉回成旋转矩阵

像素有噪声时，下一节算出的 r1 和 r2 不会严格垂直，拼出的矩阵 R̃ 不是合法的旋转矩阵。对它做 SVD，R̃ = U·Σ·Vᵀ，然后把 Σ 换成单位矩阵：

R = U · Vᵀ

合法的旋转矩阵没有缩放，奇异值应该全是 1。把"缩放"部分丢掉，只留"旋转"部分，得到的就是离 R̃ 最近的旋转矩阵。最后检查行列式：若为 −1，说明得到的是镜像，把 U 的最后一列取反。

09从 H 恢复位姿

已知 H = λ · K · [r1 r2 t]，其中 λ 是那个没有意义的整体尺度。分五步把它拆开。每一步下面的数字来自实验台的当前状态。

1

去掉 K。计算 M = K⁻¹ · H。它的三列记为 m1、m2、m3，理论上等于 λ·r1、λ·r2、λ·t。

2

定尺度。旋转矩阵的每一列长度都是 1，所以 ‖m1‖ 和 ‖m2‖ 都应该等于 λ。取两者的平均，减小噪声影响。若算出的 tz 为负，说明 tag 跑到了相机后面，把 λ 取反。

3

取出 r1、r2、t。三列各除以 λ。

4

补上 r3。r3 = r1 × r2（叉乘）。这就是第 6 节说的"Z 轴方向没有丢"。

5

正交化。检查 r1 · r2，它应该是 0。有噪声时不是，用 SVD 拉回最近的旋转矩阵（第 8 节用途二）。

点实验台的"上次截图的例子"，可以复现这组数字：第 1 列 (0, 1000, 0) 乘以 K⁻¹ 得 (0, 2.5, 0)，所以 λ = 2.5，r1 = (0, 1, 0)，t = (0.08, 0, 0.40)。

为什么 t 带真实尺度（米）？因为输入的角点坐标 (X, Y) 是以米为单位的。H 把米映射到像素，拆出来的 t 自然是米。推论：tag 边长填错多少倍，t 就错多少倍，而 R 不受影响。

完整代码

import numpy as np

def homography(tag_xy, pix_uv):          # 两个 4×2 数组：米，像素
    A = []
    for (X, Y), (u, v) in zip(tag_xy, pix_uv):
        A.append([X, Y, 1, 0, 0, 0, -u*X, -u*Y, -u])
        A.append([0, 0, 0, X, Y, 1, -v*X, -v*Y, -v])
    _, _, Vt = np.linalg.svd(np.array(A))
    H = Vt[-1].reshape(3, 3)             # 最小奇异值对应的方向
    return H / H[2, 2]

def pose_from_H(H, K):
    M = np.linalg.inv(K) @ H             # = λ·[r1 r2 t]
    lam = (np.linalg.norm(M[:, 0]) + np.linalg.norm(M[:, 1])) / 2
    if M[2, 2] / lam < 0:                # tag 必须在相机前方
        lam = -lam
    r1, r2, t = M[:, 0] / lam, M[:, 1] / lam, M[:, 2] / lam
    R = np.column_stack([r1, r2, np.cross(r1, r2)])
    U, _, Vt = np.linalg.svd(R)          # 拉回最近的旋转矩阵
    R = U @ np.diag([1, 1, np.linalg.det(U @ Vt)]) @ Vt
    return R, t

实际使用的库（apriltag、pupil-apriltags）在这之后还会做一次迭代优化，让四个角点的重投影误差最小。你只需提供 fx, fy, cx, cy 和 tag 边长。

10解码 tag 的 ID

四个角点只用来求 H。tag 内部的黑白格子用来确认"这确实是一个 tag"，并读出它是哪一个。

  1. 把 tag 内部划成网格。用 H 把每个格子的中心 (X, Y) 映射到像素，在那里读图像是黑还是白，得到一串比特。实验台右图里的格子就是这样贴上去的。
  2. 把这串比特与码本逐一比较，数有几位不同（汉明距离）。差得足够少就认为匹配成功。
  3. 因为不知道 tag 转了多少，要按 0°、90°、180°、270° 四种朝向各比一次。匹配上的那个朝向同时确定了哪个角点是"左上角"。

以常用的 tag36h11 为例：36 表示 6×6 共 36 位数据，h11 表示任意两个合法码字之间至少有 11 位不同。所以即使读错 5 位，仍然能唯一确定是哪个 tag，自然场景里碰巧出现合法码字的概率也极低。

11Pick and place 变换链

把 tag 贴在方块顶面，相机就能得到方块的位姿和编号，不需要训练检测网络。但 AprilTag 给的是 tag 相对相机的位姿，机械臂需要的是方块相对基座的位姿。中间用变换链连起来：

Tbase_block = Tbase_ee · Tee_cam · Tcam_tag · Ttag_block
变换来源是否变化
Tbase_ee读关节角，用正运动学计算机械臂每动一次都变
Tee_cam手眼标定，测一次常数（相机固定在末端上）

12局限与调试清单

方法本身的局限

  • 角度比位置噪声大。角点差一个像素，对平移影响很小，对旋转影响明显。误差随距离增大而增大。用实验台的"远距离加噪声"可以看到。
  • 平面位姿歧义。tag 较远或接近正对相机时，存在两个重投影误差几乎相同的解，倾斜方向可能"翻转"。靠近一些，或让 tag 在图像中更大，可以缓解。
  • 不耐遮挡。边框被挡住一块就检测不到。运动模糊和强反光也会导致失败。
