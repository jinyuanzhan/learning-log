PART A

Heuristic search

在一张 graph 上找从 start 到 goal 的 path。BFS、DFS、Dijkstra、A* 四个算法共用一个骨架，学会骨架再看区别，比一个一个背要容易得多。

02搜索的骨架

问题

  • 一张 graph：一堆 node，node 之间有 edge。仓库的地面切成 grid 之后，每个 cell 是一个 node，上下左右相邻的两个 cell 之间有一条 edge。
  • 每条 edge 有一个 cost：走这一步的代价，可以是距离、时间或者能耗。
  • 给一个 start 和一个 goal，找一条从 start 到 goal 的 path。通常要求总 cost 最小，这样的 path 叫 optimal。

四个算法都在做同一件事

从 start 开始，一点一点往外探索。过程中每个 node 记两样东西：

  • g(n)：目前已知的、从 start 走到 n 的最小 cost。
  • parent(n)：是从哪个 node 走到 n 的。找到 goal 之后，沿着 parent 一路往回走，就得到整条 path。

另外维护两个集合：

  • OPEN：已经发现、但还没处理的 node。也叫 frontier。
  • CLOSED：已经处理完的 node。

“处理”一个 node 有个专门的词，叫 expand：把它从 OPEN 里取出来，查看它的每一个邻居。

function Search(start, goal):
    g[start] ← 0
    OPEN ← {start};  CLOSED ← {}
    while OPEN 非空:
        n ← 从 OPEN 里取出一个 node              # 四个算法只有这一行不同
        if n == goal: return 沿 parent 回溯出的 path
        if n in CLOSED: continue                 # 同一个 node 可能被放进 OPEN 好几次，只处理第一次
        CLOSED.add(n)
        for m in neighbors(n):                   # 这几行就是 expand
            new_g ← g[n] + cost(n, m)
            if m 没被发现过，或者 new_g < g[m]:   # 找到了一条更便宜的走法
                g[m] ← new_g;  parent[m] ← n
                把 m 放进 OPEN
    return FAIL

为什么需要 CLOSED：一个 node 可能进 OPEN 两次

CLOSED.add(n) 是在 node 被取出来时做的，不是放进去时。一个 node 在 OPEN 里排队的这段时间不在 CLOSED 里，如果这期间找到一条去它的更便宜的路，入口的 new_g < g[m] 会让它再进一次 OPEN。等旧的那份被取出来时，它已经处理过了，if n in CLOSED: continue 就是把这份过期的跳过。

  • BFS 一圈一圈往外扩，离 start 近的 node 总是先被处理，所以一个 node 第一次被发现时走的就已经是最短的路。之后从别的方向再发现它，new_g 不可能更小，不会再放进去。
  • DFS 先绕远路，经过 C、D、E 到了 B，这时 g = 4。之后从 A 走过来，发现到 B 只要 2 步，于是 B 又进了 OPEN。B 第二次被取出来时已经 expand 过了，被跳过。去掉这一行，B 会被 expand 两次，一共 7 次而不是 6 次。这也说明了 DFS 为什么不保证最短：它先钻到底，第一次碰到一个 node 时往往绕了远路。
  • S 不会再被放进去：g[S] = 0，任何走回 S 的 new_g 都至少是 1，入口的 if 永远挡住它。

去掉哪个 if 会怎样只去掉出口的 if n in CLOSED：结果仍然对，只是重复 expand。去掉入口的 new_g < g[m]：parent 会被更差的路覆盖，比如 parent[S] 被改成 A，回溯 path 时会死循环。BFS 和 DFS 也可以只用一个 if：放进 OPEN 时就标记 visited，一个 node 只会进一次 OPEN。Dijkstra 和 A* 不行，必须等 node 被取出来，才能确定它的 g 已经最小。

区别只在“取哪一个”

算法从 OPEN 里取哪一个OPEN 的数据结构保证什么
BFS最早放进去的queue，先进先出步数最少的 path
DFS最晚放进去的stack，后进先出只保证找到一条 path，不保证短
Dijkstrag 最小的priority queue，通常是 min-heapcost 最小的 path，要求 edge cost 不是负数
A*g + h 最小的priority queuecost 最小的 path，要求 h 不高估（骨架里 CLOSED 直接 skip 的写法还要求 h consistent，见 05）

Dijkstra 和 A* 这种“每次取某个评分最好的 node”的做法，统称 best-first search。后面 CBS 的 high level 用的也是它，只是搜索的对象从 cell 换成了别的东西。

03BFS 与 DFS

BFS：breadth-first search，广度优先

OPEN 是一个 queue，谁先进来谁先被 expand。效果是：先处理离 start 1 步的所有 node，再处理 2 步的，再处理 3 步的，像水波一样一圈一圈往外扩。

  • 保证：第一次碰到 goal 时，用的步数一定是最少的。因为所有步数更少的 node 都已经被处理过了。
  • 前提：每一步的 cost 都相同。如果有的 cell 走起来更贵，步数最少就不等于 cost 最小，这时要用 Dijkstra。
  • 复杂度：时间 O(V + E)，V 是 node 数，E 是 edge 数。每个 node 进一次 queue，每条 edge 看一次。空间也是 O(V)，因为要存整个 frontier。
  • 简化：BFS 里一个 node 第一次被发现时的步数就是最终答案，所以骨架里“new_g < g[m]”那个判断用不上，只要判断 m 有没有被发现过。

DFS：depth-first search，深度优先

OPEN 是一个 stack，谁最后进来谁先被 expand。效果是：沿着一条路一直往深处走，走到死胡同再退回最近的岔路口，换一条路继续。也可以直接用递归来写。

  • 保证：graph 有限时，只要 goal 能到达就一定能找到。但找到的 path 通常很绕，不是最短的。
  • 优点：省内存。只需要记住当前这条路，空间是 O(深度)，而 BFS 要记住整个 frontier。
  • 复杂度：时间 O(V + E)。

用 DFS 找环

DFS 最常见的用途之一是判断一张有向图里有没有环。给每个 node 涂三种颜色：白色是还没访问，灰色是正在访问（它还在当前这条路上），黑色是已经访问完。DFS 过程中如果碰到一个灰色的 node，说明绕回了当前这条路上，也就是有环。

function HasCycle(n):
    color[n] ← GRAY                      # 正在这条路上
    for m in neighbors(n):
        if color[m] == GRAY: return true  # 绕回来了，有环
        if color[m] == WHITE and HasCycle(m): return true
    color[n] ← BLACK                     # 这个 node 往下的路都查完了
    return false

和 multi-agent 的关系BFS：从每个 goal 出发做一次反向 BFS，就得到每个 cell 到这个 goal 的真实距离，这是 MAPF 里最常用的 heuristic。DFS：多个 robot 互相等待时，把“谁在等谁”画成一张图，用上面的办法找环，有环就是 deadlock。

04Dijkstra

BFS 只数步数。当每条 edge 的 cost 不一样时，要找的是 cost 最小的 path，这就是 Dijkstra 解决的问题。

思路

OPEN 换成 priority queue，每次 expand g 最小的 node，也就是目前离 start 最近的那个。其他和骨架完全一样。

Pseudo-code

function Dijkstra(start, goal):
    g[start] ← 0
    OPEN ← min-heap，按 g 排序；放入 start   # 和骨架唯一的区别
    CLOSED ← {}
    while OPEN 非空:
        n ← pop g 最小的                     # 离 start 最近的
        if n == goal: return 沿 parent 回溯出的 path
        if n in CLOSED: continue              # 过期的旧记录
        CLOSED.add(n)                         # g[n] 已经是最终答案
        for m in neighbors(n):
            new_g ← g[n] + cost(n, m)
            if m 没被发现过，或者 new_g < g[m]:   # relax
                g[m] ← new_g;  parent[m] ← n
                push m，key = new_g
    return FAIL

和 05 节的 A* 对照：两段代码只有 push 时的 key 不一样。Dijkstra 用 new_g，A* 用 new_g + h(m)。下面手推的例子就是按这段代码一行一行走的。

手推一个例子

步expand 谁发生了什么OPEN 里的 node 和 g
0开始S:0
1S，g = 0发现 A，g = 1。发现 B，g = 4A:1　B:4
2A，g = 1经过 A 到 B 只要 1 + 2 = 3，比 4 小，更新 B。发现 G，g = 1 + 6 = 7B:3　G:7
3B，g = 3经过 B 到 G 只要 3 + 1 = 4，比 7 小，更新 GG:4
4G，g = 4到达 goal。沿 parent 回溯：G、B、A、S

同一张图上，BFS 会返回 S、A、G：只走 2 步，但 cost 是 7。步数最少不等于 cost 最小。

第 2、3 步里“发现更便宜的走法就更新 g 和 parent”这个动作，教科书上叫 relax 一条 edge。它就是骨架里的那个 if。

为什么是对的

关键的一点：一个 node 被 expand 的那一刻，它的 g 就已经是最终答案了。理由是，假设 n 是 OPEN 里 g 最小的。任何其他通往 n 的路，都要先经过 OPEN 里的另一个 node，而那个 node 的 g 已经不比 n 小，再往后走 cost 只会增加。所以不可能有更便宜的路到 n。

这个理由用到了“再往后走 cost 只会增加”，所以 Dijkstra 要求 edge cost 不能是负数。

要记住的

  • 复杂度：用 binary heap 时是 O((V + E) log V)。
  • 和 BFS 的关系：所有 edge 的 cost 都是 1 时，Dijkstra 的行为和 BFS 一样。BFS 是 Dijkstra 的特例。
  • 缺点：它不知道 goal 在哪，朝四面八方均匀地扩。goal 明明在右边，它也会把左边同样距离的 node 全部 expand 一遍。A* 解决的就是这个问题。
  • 副产品：如果不在碰到 goal 时停下，而是一直跑到 OPEN 为空，就得到 start 到所有 node 的最短距离。这叫 single-source shortest path。

05A*

思路

Dijkstra 只看“已经走了多远”，也就是 g。A* 再加一项“估计还要走多远”，记作 h(n)，然后按两者之和排序：

f(n) = g(n) + h(n) g(n)：从 start 到 n 已经花掉的 cost h(n)：从 n 到 goal 还要花多少的估计，叫 heuristic 每次从 OPEN 里取 f 最小的 node

f(n) 的含义是“经过 n 的 path，总 cost 大概是多少”。按 f 排序之后，朝着 goal 方向的 node 会排在前面，背离 goal 的 node 会排在后面，于是少 expand 很多没用的 node。

在 4-connected grid 上，最常用的 heuristic 是 Manhattan distance：|r − rgoal| + |c − cgoal|，也就是不考虑障碍物时要走的步数。

Pseudo-code

function AStar(start, goal):
    g[start] ← 0
    OPEN ← priority queue，按 f = g + h 排序；放入 start
    CLOSED ← {}
    while OPEN 非空:
        n ← pop f 最小的
        if n == goal: return 沿 parent 回溯出的 path
        if n in CLOSED: continue
        CLOSED.add(n)
        for m in neighbors(n):
            new_g ← g[n] + cost(n, m)
            if m 没被发现过，或者 new_g < g[m]:
                g[m] ← new_g;  parent[m] ← n
                push m，f = new_g + h(m)        # 和 Dijkstra 只差这一处：多加了 h(m)
    return FAIL

把 h 换成 0，A* 就退化成 Dijkstra。

为什么还是 optimal

只要 h 从不高估真实的剩余 cost，f(n) 就是“经过 n 的任何 path 至少要花多少”的一个 lower bound。A* 按 lower bound 从小到大处理 node。goal 被 pop 出来的那一刻，OPEN 里其他所有 node 的 lower bound 都不比它小，所以不可能再有更便宜的 path。

Admissible 和 consistent

  • admissible：h(n) 永远不高估真实的剩余 cost。满足它，A* 返回的 path 就是 optimal 的，前提是允许 reopen（或者不用 CLOSED）。
  • consistent：对每条 edge (n, n′) 都有 h(n) ≤ cost(n, n′) + h(n′)，并且 h(goal) = 0。直观上是 heuristic 满足三角不等式。满足它，每个 node 只需要 expand 一次。
  • consistent 的 heuristic 一定 admissible，反过来不一定。只 admissible 不 consistent 时，已经进了 CLOSED 的 node 可能要重新拿出来处理，这叫 reopen。
  • 上面的 pseudo-code 对 CLOSED 里的 node 直接 skip，不 reopen。这种写法要 h consistent 才保证 optimal；h 只 admissible 时，要么把 skip 改成 reopen，要么可能返回次优的 path。grid 上的 Manhattan distance 和 true distance 都 consistent，所以这一页的例子不受影响。

Heuristic 越准，expand 越少

heuristic性质效果
h = 0admissible，但没有任何信息就是 Dijkstra，朝四面八方扩
Manhattan distance在 4-connected grid 上 consistent没有障碍物时非常准。障碍物多的时候估得太低，A* 会钻进死胡同

true distance 要先花一次完整搜索的时间来算。它在 MAPF 里很划算，因为地图是固定的，每个 goal 算一次，之后成百上千次搜索都能复用。

常见追问

问题答案
f 相同的 node 先 pop 哪个？先 pop g 大的。g 大说明离 goal 更近，能少 expand 很多 node。这叫 tie-breaking。
weighted A* 是什么？f = g + w·h，其中 w > 1。更相信 heuristic，搜索更贪心、更快。返回的 path cost 不超过 optimal 的 w 倍，这种有上界的次优叫 bounded-suboptimal。
A* 的复杂度？最坏情况和 Dijkstra 一样。实际 expand 多少 node，取决于 heuristic 有多准。
A*、Dijkstra、BFS 的关系？h = 0 的 A* 是 Dijkstra。edge cost 全是 1 的 Dijkstra 是 BFS。
地图变了怎么办？最简单是重新搜一次。有专门的增量算法，比如 D* Lite，只修补受影响的部分。知道名字就够。

面试怎么说“A* is Dijkstra plus a heuristic. It expands nodes in order of f = g + h, where g is the cost so far and h estimates the remaining cost. If h never overestimates, the first time the goal is popped the path is optimal. On a grid I’d use Manhattan distance, or precompute true distances with a backward BFS from the goal when there are many obstacles.”

06实验台：六种搜索

S 是 start，G 是 goal。拖动滑块，看每种算法先 expand 谁、后 expand 谁。下面的表格是同一张地图上六种算法的结果。

建议按这个顺序看。空地：依次点 BFS、Dijkstra、A*，比较 expand 的 node 数，再点 DFS 看它找到的 path 有多绕。U 形墙：比较两种 heuristic 的 A*。泥地：看 BFS 为什么不是 optimal，再看 weighted A* 用什么换来了速度。

从实验台能读出的结论

  • BFS 和 Dijkstra 在 cost 全是 1 的地图上，expand 的 node 数和 path 的 cost 完全一样。
  • A* 找到的 path 和 Dijkstra 的 cost 相同，但 expand 的 node 少得多。空地上是 13 对 111。
  • heuristic 越准越省。U 形墙上，Manhattan distance 的 A* expand 49 个 node，true distance 的 A* 只要 19 个。
  • BFS 不看 cost。泥地上它找到的 path 只有 12 步，cost 却是 24，而 optimal 是 20。
  • DFS 很快就能找到一条 path，但很绕。空地上它的 path 有 38 步，是最短的三倍多。
  • weighted A* 在泥地上比 A* 少 expand 一半的 node，代价是 path 的 cost 从 20 变成了 24。
可以直接运行的 Python：BFS、DFS、Dijkstra、A*
import heapq
from collections import deque

def neighbors(grid, cell):
    r, c = cell
    for nr, nc in ((r - 1, c), (r, c + 1), (r + 1, c), (r, c - 1)):
        if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]) and grid[nr][nc] != '#':
            yield (nr, nc)

def step_cost(grid, cell):                      # 走进这个 cell 的 cost：'~' 是泥地，cost 5；其他是 1
    return 5 if grid[cell[0]][cell[1]] == '~' else 1

def backtrack(parent, goal):                    # 沿 parent 从 goal 走回 start，再反过来
    path, node = [], goal
    while node is not None:
        path.append(node)
        node = parent[node]
    return path[::-1]

def bfs(grid, start, goal):
    parent = {start: None}                      # 被发现过的 node 都在 parent 里
    queue = deque([start])                      # OPEN 是 queue：先进先出
    while queue:
        n = queue.popleft()
        if n == goal:
            return backtrack(parent, goal)
        for m in neighbors(grid, n):
            if m not in parent:                 # 只看有没有被发现过，不比较 cost
                parent[m] = n
                queue.append(m)
    return None

def dfs(grid, start, goal):
    parent = {}
    stack = [(start, None)]                     # OPEN 是 stack：后进先出
    while stack:
        n, p = stack.pop()
        if n in parent:                         # 已经处理过
            continue
        parent[n] = p
        if n == goal:
            return backtrack(parent, goal)
        for m in neighbors(grid, n):
            if m not in parent:
                stack.append((m, n))
    return None

def dijkstra(grid, start, goal):
    g = {start: 0}
    parent = {start: None}
    open_list = [(0, start)]                    # OPEN 是 min-heap，按 g 排序
    closed = set()
    while open_list:
        _, n = heapq.heappop(open_list)
        if n == goal:
            return backtrack(parent, goal)
        if n in closed:                         # 同一个 node 可能被 push 多次，只处理第一次
            continue
        closed.add(n)
        for m in neighbors(grid, n):
            new_g = g[n] + step_cost(grid, m)
            if m not in g or new_g < g[m]:      # 第一次发现，或者找到了更便宜的走法
                g[m] = new_g
                parent[m] = n
                heapq.heappush(open_list, (new_g, m))
    return None

def astar(grid, start, goal):
    h = lambda cell: abs(cell[0] - goal[0]) + abs(cell[1] - goal[1])    # Manhattan distance
    g = {start: 0}
    parent = {start: None}
    open_list = [(h(start), start)]             # 按 f = g + h 排序
    closed = set()
    while open_list:
        _, n = heapq.heappop(open_list)
        if n == goal:
            return backtrack(parent, goal)
        if n in closed:
            continue
        closed.add(n)
        for m in neighbors(grid, n):
            new_g = g[n] + step_cost(grid, m)
            if m not in g or new_g < g[m]:
                g[m] = new_g
                parent[m] = n
                heapq.heappush(open_list, (new_g + h(m), m))   # 和 Dijkstra 只差这一行：多加了 h(m)
    return None

def path_cost(grid, path):
    return sum(step_cost(grid, cell) for cell in path[1:])

Multi-agent pathfinding

多个 robot 同时规划，简称 MAPF。它不是一套全新的算法，而是把上面的单 agent 搜索反复调用、再加上处理冲突的办法。

Robotics motion planning

前面的搜索都在 grid 上。当 robot 是机械臂，或者空间是连续的、维度很高时，grid 就不够用了。这一部分讲最基础的一套思路。

08Configuration space

configuration 是能完整描述 robot 姿态的一组数。所有可能的 configuration 组成的空间叫 configuration space，简称 C-space。

robotconfigurationC-space 的维度

这样定义的好处是：不管 robot 的形状多复杂，它在 C-space 里都只是一个点。障碍物也要搬进 C-space：所有会让 robot 撞上东西的 configuration 构成 C-obstacle，剩下的叫 free space。于是 motion planning 变成同一个问题：在 free space 里找一条从 start 到 goal 的曲线。

为什么不能直接用 A*

把 C-space 切成 grid 再跑 A* 是可以的，这叫 search-based planning，低维时很好用。但 cell 的数量随维度指数增长：6 个关节、每个关节按 10° 切成 36 份，就有 366 ≈ 22 亿个 cell。这叫 curse of dimensionality。

09Sampling-based planning：PRM 与 RRT

核心想法：不去枚举整个空间，而是随机采一些点，只对这些点和它们之间的连线做 collision check。

PRM：probabilistic roadmap

  1. 在 C-space 里随机采 N 个点，丢掉落在障碍物里的。
  2. 每个点和它附近的几个点连线。连线不撞障碍物，就留下来当一条 edge。这样得到一张 graph，叫 roadmap。
  3. 查询时，把 start 和 goal 各连到 roadmap 上最近的点，然后在 roadmap 上跑 A* 或 Dijkstra。

roadmap 建一次可以反复用，这叫 multi-query。环境固定、要规划很多次的时候很合适。

RRT：rapidly-exploring random tree

只回答一次查询时，不必把整个空间都铺上 roadmap。RRT 从 start 长出一棵 tree，一直长到碰到 goal。

function RRT(start, goal):
    tree ← {start}
    repeat:
        q_rand ← 随机采一个点                    # 以一个小概率直接取 goal，叫 goal bias
        q_near ← tree 上离 q_rand 最近的 node
        q_new  ← 从 q_near 朝 q_rand 走一小步
        if q_near 到 q_new 这一段不撞:           # collision check
            把 q_new 加进 tree，parent 是 q_near
            if q_new 离 goal 足够近: return 沿 parent 回溯出的 path

“朝随机点走一小步”这个动作有一个好性质：tree 会自动往还没探索过的大片空白里长，所以叫 rapidly-exploring。

性质

  • probabilistically complete：只要有解，采样足够多就一定能找到。但它没法告诉你“无解”。
  • 不 optimal：找到的 path 弯弯曲曲，通常要做后处理。
  • 结果是随机的：同一个问题跑两次，path 不一样，花的时间也不一样。
  • 怕窄通道：随机采样很难恰好采进一条窄缝里，这叫 narrow passage problem。
  • 时间花在哪：大部分花在 collision check 上，而不是搜索本身。

RRT*

RRT* 在 RRT 上加了两步，让 path 随着采样增多越来越接近 optimal，这叫 asymptotically optimal。

  • 选最好的 parent：q_new 不一定接在最近的 node 上，而是在附近的一圈 node 里，选让 q_new 的 cost 最小的那个。
  • rewire：q_new 加进来之后，看附近的 node 改成经过 q_new 会不会更便宜，会就把它们的 parent 改成 q_new。

面试怎么说“For a high-dimensional robot like an arm I’d use a sampling-based planner. RRT grows a tree from the start: sample a random configuration, find the nearest tree node, step toward the sample, and keep the new node if the motion is collision-free. It’s probabilistically complete but not optimal, so I’d either post-process the path with shortcutting or use RRT*, which rewires the tree and converges to the optimal path.”

11从 path 到 trajectory

path 只是几何上的一条线：经过哪些点。trajectory 还带时间：每个时刻在哪、速度多少。planner 给出 path 之后，通常还要经过这几步才能交给 robot 执行：

  1. shortcut 或 smoothing。去掉多余的拐弯。实验台里用的是最简单的一种：从当前点直接连到能看见的最远的点。
  2. time parameterization。给 path 配上速度。要满足最大速度和最大加速度的限制。最常见的是梯形速度曲线：先加速，再匀速，最后减速。
  3. kinematic constraints。差速底盘和汽车都不能横着走。这时规划的 state 要包含朝向，变成 (x, y, θ)，每一步只能走几种固定的动作。对应的算法有 state lattice 和 Hybrid A*，知道名字就够。
  4. 执行时的修正。传感器发现了新的障碍物，就要局部 replan。

和 MAPF 的关系MAPF 假设每一步刚好花一个单位时间。真实的 robot 加速、减速、转弯都要时间，所以实际系统要么在规划时用更细的模型，要么在执行层处理这些偏差。

PART D

Task allocation 与 operations research

前面回答的是“怎么走”。这一部分回答“谁去做哪件事”“按什么顺序做”“货放多少、放在哪”。这些问题属于 operations research，简称 OR。

12Assignment problem 与 Hungarian algorithm

问题

n 个 robot，n 个 task。robot i 做 task j 的代价是 cij，所有代价排成一个 cost matrix。每个 robot 做一个 task，每个 task 给一个 robot，要让总 cost 最小。这叫 assignment problem。

cost 通常是 robot 到 task 的行驶时间，可以再加上 deadline 和拥堵的修正。

为什么不能枚举，也不能 greedy

  • 枚举：一共有 n! 种分配。4 个 robot 只有 24 种，20 个就是 2.4 × 1018 种。
  • greedy：每次挑剩下的里面 cost 最小的一对。很快，但不是 optimal。最便宜的格子被先抢走之后，后面的 robot 可能只剩下很贵的选择。

Hungarian algorithm 的思路

它基于一个观察：把某一行的每个数都减去同一个值，哪种分配最好不会变。因为不管怎么分配，这个 robot 总要做一个 task，总 cost 都少了同样的数。对列也一样。

于是可以不断地减，让 matrix 里出现尽量多的 0，同时保证没有负数。如果最后能选出 n 个互不同行、互不同列的 0，那么这组分配在新 matrix 里的总 cost 是 0，不可能更小，所以它就是 optimal。

  1. 行约减。每一行减去这一行的最小值。
  2. 列约减。每一列减去这一列的最小值。
  3. 用最少的线盖住所有的 0。线可以是整行或整列。如果需要 n 条线，说明已经能选出一组完整的分配，结束。
  4. 调整。如果不到 n 条：找出没被盖住的数里最小的那个，记作 δ。没被盖住的数都减 δ，被两条线同时盖住的数加 δ。然后回到第 3 步。

先看右边：橙色框是 greedy 选的，绿色是 optimal。然后在左边一步一步点，看 matrix 怎么变。点随机可以换一个 matrix 再看一遍。

要记住的

  • 结果是 optimal 的，复杂度 O(n³)。几百个 robot 也只要毫秒到秒级。
  • robot 和 task 数量不一样：补上虚拟的行或列，cost 填 0，变成方阵。
  • 要最大化而不是最小化：把所有 cost 取负号。
  • 实际写代码不用自己实现：
import numpy as np
from scipy.optimize import linear_sum_assignment

C = np.array([[5, 7, 9, 1],
              [5, 3, 1, 9],
              [1, 7, 2, 6],
              [1, 9, 4, 2]])
rows, cols = linear_sum_assignment(C)     # cols[i] 是分给 robot i 的 task
print(cols, C[rows, cols].sum())          # [3 1 2 0] 7
  • 它的局限：一个 robot 只能拿一个 task。如果一个 robot 要连着做好几个 task，顺序也要优化，问题就变成了下一节的 TSP 和 VRP。

面试怎么说“I’d model task allocation as an assignment problem: build a cost matrix where entry (i, j) is the travel time for robot i to reach task j, then solve it with the Hungarian algorithm, which gives the optimal one-to-one matching in O(n³). Greedy nearest-robot is faster but can be arbitrarily worse, because taking the cheapest pair first may leave another robot with a very expensive task.”

13TSP：traveling salesman problem

问题

给 n 个点和两两之间的距离。从一个点出发，每个点恰好去一次，最后回到出发点，要让总路程最短。这样的一圈叫 tour。

在仓库里它对应：一个 robot 这一趟要去 n 个货位取货，按什么顺序走最省。

为什么难

不同的 tour 有 (n − 1)! / 2 种。10 个点是 18 万种，20 个点是 6 × 1016 种。TSP 是 NP-hard 的，目前没有已知的多项式时间算法能保证找到 optimal。

和上一节对比很有意思：assignment problem 有 n! 种可能，却能在 O(n³) 内精确解出来。TSP 看上去差不多，却是 NP-hard。可能性的多少并不决定问题的难度。

两类办法

办法做法保证代价
精确：Held-Karpdynamic programming。记住“已经去过哪些点、现在在哪个点”时的最短路程optimalO(n² · 2ⁿ)，只能做到 20 个点左右
精确：ILP solver写成整数规划交给 solver，见下一节optimal能做到上百个点，但时间不稳定
heuristic：nearest neighbor每次去最近的、还没去过的点没有保证，通常比 optimal 长两成左右O(n²)
heuristic：2-opt从一个现成的 tour 出发，反复做小改动，能变短就接受只保证 local optimum每一轮 O(n²)

2-opt

拆掉 tour 里的两条 edge，把中间那一段倒过来再接上。如果总长度变短了，就保留这次改动。一直做到没有任何改动能让 tour 变短为止。

直观上，它在做的事情是解开交叉：平面上两条 edge 如果交叉，把它们换成不交叉的接法一定更短。

这种“从一个解出发，不断做小改动”的办法叫 local search。它停下来时的解叫 local optimum：附近没有更好的了，但不一定是全局最好的。

滑块在 0 的位置是 nearest neighbor 的结果，往右每一格是一次 2-opt 交换。点集 1 上 2-opt 正好到达 optimal，点集 2 上它停在了一个 local optimum。勾上“叠加显示 optimal tour”可以对比。

面试怎么说“If one robot has to visit several locations in a trip, ordering them is a TSP, which is NP-hard. For a handful of stops I can solve it exactly with dynamic programming. At larger sizes I’d build a tour with nearest neighbor and improve it with 2-opt local search, which is fast and usually within a few percent of optimal.”

14LP、ILP 与 VRP

OR 里处理问题的标准流程是：先把问题写成数学模型，再交给通用的 solver。模型有三个部分：

  • decision variable：要决定的量。
  • objective：要最小化或最大化的式子。
  • constraint：必须满足的条件。

LP：linear programming

objective 和 constraint 都是变量的线性式子，变量可以取小数。

maximize 3x + 2y subject to x + y ≤ 4 x + 3y ≤ 6 x ≥ 0, y ≥ 0

满足所有 constraint 的点构成一个多边形，这里的四个顶点是 (0,0)、(4,0)、(3,1)、(0,2)，对应的 objective 是 0、12、11、4。最优解是 (4,0)，objective 等于 12。LP 的最优解总能在顶点上取到，这是 simplex method 的出发点。LP 可以高效地求解，几十万个变量也没问题。

ILP：integer linear programming

在 LP 的基础上，要求一部分变量必须是整数，最常见的是只能取 0 或 1。“选不选”“分不分给它”这类决定都要用 0-1 变量。加上整数要求之后，问题一般就变成 NP-hard 了。

solver 的基本办法叫 branch and bound：先去掉整数要求解一次 LP，得到一个 bound。如果某个变量解出来是小数，比如 0.4，就分成“它等于 0”和“它等于 1”两支，分别再解。某一支的 bound 已经比手上最好的整数解还差，这一支就整个剪掉。

把 assignment problem 写成 ILP

变量 x_ij ∈ {0, 1} # robot i 是否做 task j minimize Σ c_ij · x_ij subject to 对每个 robot i： Σ_j x_ij = 1 # 每个 robot 恰好一个 task 对每个 task j： Σ_i x_ij = 1 # 每个 task 恰好一个 robot

assignment problem 是个幸运的例外：即使去掉整数要求，解出来的 x 也自动是 0 或 1。所以它其实是一个 LP，这也是它能被高效解出来的原因。

VRP：vehicle routing problem

TSP 是一辆车跑一圈。VRP 是多辆车从仓库出发，每个客户恰好被一辆车服务一次，同时要决定哪辆车去哪些客户、各自按什么顺序。常见的附加条件有车的容量和客户的时间窗。它包含了 TSP，所以也是 NP-hard 的。

一个 robot 一趟能带好几个 case、每个 case 有 deadline 的时候，问题就是一个 VRP。实际做法是用 heuristic 加 local search，或者直接用现成的 solver，比如 Google 的 OR-Tools。

遇到一个新问题时怎么选

问题模型常用做法

一个 robot 要去多个点，定顺序TSP点少时精确解；点多时 nearest neighbor 加 2-opt

15Inventory management 基础

inventory management 回答三个问题：每种货备多少，什么时候补，放在哪。

备多少：EOQ

EOQ 是 economic order quantity 的缩写：每次订多少最划算。两种成本在互相拉扯：

  • ordering cost：每下一次订单的固定成本，记作 S。一次订得多，订的次数就少，这项成本低。
  • holding cost：一件货存一年的成本，记作 H。一次订得多，平均库存就高，这项成本高。
年需求量 D，每次订 Q 件： ordering cost = (D / Q) · S # 一年订 D/Q 次 holding cost = (Q / 2) · H # 平均库存是 Q/2 两项之和最小时： Q* = √(2·D·S / H)

例子：一年卖 5000 件，每次下单的成本是 100，一件货存一年的成本是 4。那么 Q* = √(2 × 5000 × 100 / 4) = 500 件。一年订 10 次，ordering cost 是 1000，holding cost 也是 1000。在最优点上这两项正好相等。

什么时候补：reorder point 和 safety stock

从下单到货送来需要一段时间，叫 lead time。库存降到某个水平就要下单，这个水平叫 reorder point。因为需求有波动，还要多备一点防止断货，多备的部分叫 safety stock。

reorder point = 平均日需求 × lead time + safety stock safety stock = z · σ · √(lead time) # σ 是日需求的标准差，z 由 service level 决定

例子：平均每天卖 20 件，标准差是 5，lead time 是 5 天，要求 95% 的 service level，对应 z = 1.645。safety stock = 1.645 × 5 × √5 ≈ 18 件。reorder point = 20 × 5 + 18 = 118 件。

哪些货更重要：ABC analysis

按出货量把货分成三类。A 类大约占品种数的 20%，却贡献 80% 左右的出货量。B 类居中。C 类品种很多，出货很少。管理的精力和最好的位置优先给 A 类。

放在哪：slotting

slotting 是决定每种货放在哪个货位。基本原则是出货快的放在离出口近的地方，让总的搬运距离最短。把货分配到货位，本身就是一个 assignment problem。

和 robot 调度的关系货放在哪，直接决定了 robot 要跑多远、哪些通道会堵。如果把所有出货快的货都放在同一条通道里，距离上最优，但 robot 会在那里排队。所以存储位置、task allocation 和 path planning 是连在一起的。Symbotic 的公开 blog 里也提到，他们的软件要同时决定每个 case 存在哪、由哪个 robot 去取、走哪条路。

Heuristic search

BFS、DFS、Dijkstra、A* 的区别是什么？

它们是同一个骨架，区别只在每次从 OPEN 里取哪个 node。BFS 取最早放进去的，用 queue。DFS 取最晚放进去的，用 stack。Dijkstra 取 g 最小的。A* 取 g + h 最小的。后两个都用 priority queue。

BFS 什么时候找到的不是最短路？

edge 的 cost 不全相同的时候。BFS 保证的是步数最少，不是 cost 最小。cost 不一样时要用 Dijkstra 或 A*。

DFS 和 BFS 各适合做什么？

BFS 适合 unit-cost 的最短路，以及算每个 node 到某一点的距离。DFS 省内存，适合判断能不能到达、找环、把所有可能性穷举一遍。DFS 找到的 path 不保证短。

Dijkstra 为什么要求 edge cost 不是负数？

它的正确性依赖一个事实：一个 node 被 expand 时，g 已经是最终值，因为其他的路都要经过 g 更大的 node，再往后只会更贵。有负的 edge 时，“再往后只会更贵”不成立，已经 expand 的 node 的 g 之后可能还会变小。

A* 和 Dijkstra 差在哪？A* 什么时候退化成 Dijkstra？

只差排序的依据：Dijkstra 按 g，A* 按 f = g + h。h 是到 goal 剩余 cost 的估计。h 恒等于 0 时，A* 就是 Dijkstra。

A* 为什么是 optimal 的？需要什么条件？

需要 h 是 admissible 的，也就是从不高估。这样 f 是经过这个 node 的 path 的 cost 的 lower bound。A* 按 f 从小到大处理，goal 被 pop 出来时，其他 node 的 lower bound 都不比它小，所以不会有更便宜的 path。追问：如果实现里用了 CLOSED 并且不 reopen，还需要 h consistent。

admissible 和 consistent 有什么区别？

admissible 是 h 从不高估，保证 optimal（允许 reopen 时）。consistent 是 h(n) ≤ cost(n, n′) + h(n′)，保证每个 node 只需要 expand 一次。consistent 一定 admissible，反过来不一定。

grid 上有很多障碍物时，怎么得到比 Manhattan distance 更好的 heuristic？

从 goal 反向跑一次 BFS，cost 不同时跑 Dijkstra，得到每个 cell 到 goal 的真实最短距离，存成表。它考虑了障碍物，仍然 admissible 而且 consistent。地图固定时每个 goal 只算一次。

weighted A* 是什么？什么时候用？

f = g + w·h，w 大于 1。它更相信 heuristic，expand 的 node 更少，但 path 的 cost 最多可能是 optimal 的 w 倍。时间预算很紧、能接受一点次优的时候用。

Multi-agent 与 motion planning

单 agent 的搜索算法在 MAPF 里分别用在哪？

BFS 用来预计算每个 goal 的 true-distance heuristic。A* 加上时间维变成 space-time A*，给单个 agent 规划。best-first search 用在 CBS 的 high level。DFS 用来在 wait-for graph 上找环，检测 deadlock。

为什么不能把所有 agent 合成一个大 state 来跑 A*？

state 的数量是 cell 数的 k 次方，每个 state 的后继有 5 的 k 次方个，都随 agent 数指数增长。所以要先各自规划，再处理 conflict。

什么是 configuration space？

能完整描述 robot 姿态的一组数叫 configuration，所有 configuration 组成的空间就是 C-space。robot 在里面是一个点，障碍物变成 C-obstacle，motion planning 就是在 free space 里找一条曲线。

什么时候用 A*，什么时候用 RRT？

维度低、能切成 grid 的时候用 A*，比如平面上的移动 robot。它在给定分辨率下 optimal。维度高的时候 grid 的 cell 数指数爆炸，用 sampling-based 的方法，比如机械臂用 RRT。

讲一下 RRT 的步骤和它的性质。

随机采一个点；找 tree 上最近的 node；从它朝采样点走一小步；这一段不撞就把新点加进 tree；新点离 goal 够近就结束。它是 probabilistically complete 的，不 optimal，结果是随机的，在窄通道里很慢。

RRT* 比 RRT 多了什么？

两步。新点在附近的 node 里选 cost 最小的当 parent，而不是直接接最近的。新点加进来之后做 rewire：附近的 node 如果改成经过新点更便宜，就改它们的 parent。这样 path 会随采样增多趋向 optimal。

PRM 和 RRT 的区别？

PRM 先在整个空间里建一张 roadmap，之后每次查询都在这张图上跑 A*，适合环境固定、要查询很多次的情况。RRT 每次从 start 长一棵 tree，只回答这一次查询。

path 和 trajectory 有什么区别？

path 只有几何：经过哪些点。trajectory 还有时间：每个时刻在哪、速度多少。从 path 到 trajectory 要做 smoothing 和 time parameterization，并且满足速度、加速度的限制。

Task allocation 与 OR

怎么给一群 robot 分配 task？

建一个 cost matrix，每个格子是这个 robot 做这个 task 的代价，一般是行驶时间，可以加上 deadline 和拥堵的修正。一对一分配用 Hungarian algorithm，得到 optimal 解，复杂度 O(n³)。greedy 更快，但不保证 optimal。

greedy 分配为什么不是 optimal？举个例子。

两个 robot、两个 task，cost 是 R1 做 T1 为 1、做 T2 为 2，R2 做 T1 为 2、做 T2 为 10。greedy 先选 R1 做 T1，R2 只能做 T2，总共 11。optimal 是 R1 做 T2、R2 做 T1，总共 4。

Hungarian algorithm 的核心思想是什么？

一行或一列同时减去一个数，不改变哪种分配最好。所以不断地减，让 matrix 在保持非负的前提下出现足够多的 0。能选出 n 个互不同行同列的 0 时，这组分配的 cost 是 0，就是 optimal。

TSP 是什么？怎么解？

每个点去一次再回到起点，要总路程最短。它是 NP-hard 的。点很少时用 dynamic programming 精确解，复杂度 O(n² · 2ⁿ)。点多时用 heuristic：先用 nearest neighbor 造一个 tour，再用 2-opt 做 local search 改进。

2-opt 是怎么工作的？它保证什么？

拆掉 tour 里的两条 edge，把中间那段倒过来接上，变短就保留，一直做到没有能改进的交换为止。它只保证 local optimum，不保证全局 optimal。

assignment problem 和 TSP 都有阶乘那么多种可能，为什么一个容易一个难？

可能性的数量不决定难度。assignment problem 有很好的结构：写成 LP 之后解自动是整数，所以能在多项式时间内精确解出来。TSP 没有这样的结构，是 NP-hard 的。

LP 和 ILP 的区别？

LP 的变量可以取小数，能高效求解。ILP 要求一部分变量是整数，一般是 NP-hard 的，solver 用 branch and bound 来解。“选不选”这类决定要用 0-1 变量，所以调度问题大多是 ILP。

EOQ 在权衡什么？

ordering cost 和 holding cost。一次订得多，下单次数少，但平均库存高。EOQ 是让两项之和最小的订货量，公式是 √(2DS / H)。在这个点上两项成本正好相等。

存储位置和 robot 调度有什么关系？

货放在哪决定了 robot 要跑多远、哪些通道会堵。出货快的货放得近可以缩短距离，但全挤在一起会造成拥堵。所以 slotting、task allocation 和 path planning 要一起考虑。
