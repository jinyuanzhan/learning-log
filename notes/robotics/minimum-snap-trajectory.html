Minimum Snap 轨迹生成

Path planner 给出一串 waypoints，minimum snap 把它变成一条光滑、带时间的 trajectory：任意时刻在哪、速度多少、加速度多少。这一页从零讲清这个算法，并交代它前后的 pipeline。

前置知识只需要：多项式求导、矩阵乘法、"带等式约束的二次优化可以解一个线性方程组"。相关页面：从 path 到 trajectory，MAPF 基础。

01全局：minimum snap 在哪一步

内容
输入waypoints w₀ … wₘ；每段的时长 T₁ … Tₘ；起点、终点的状态（通常静止）
输出每段、每个维度一个 7 次多项式。代入任意 t，就得到 p(t)、v(t)、a(t)、j(t)
目标经过所有 waypoints，并且尽量"平滑"：snap（位置的 4 阶导数）的平方积分最小
PART A

Minimum snap 算法本身

02–06 是算法主体，07 的实验台可以边读边拖。

02要解决什么问题

为什么不能直接用折线

Front end 给出的 waypoints 连起来是一条折线。在拐角处，速度方向瞬间改变，加速度是无穷大，真实的机器人做不到。所以需要一条光滑曲线穿过这些点。

曲线用什么表示

用分段多项式：每两个相邻 waypoint 之间一段，每段是一个关于时间的多项式。x、y、z 三个维度互相独立，各自单独求解，下面只讲 1D。

第 j 段，局部时间 t ∈ [0, Tⱼ]： pⱼ(t) = c₀ + c₁t + c₂t² + … + c₇t⁷

多项式的好处：求导、积分都有解析式，所以"平滑程度"能写成系数的二次函数，整个问题变成一个 QP。

"平滑"怎么量化

取位置的某一阶导数，平方后对时间积分。这一阶导数越小、越平缓，轨迹越平滑。Minimum snap 选的是第 4 阶。

03为什么是 snap，为什么是 7 次多项式

阶名称对 quadrotor 意味着什么
0position在哪
1velocity多快
2acceleration推力的大小和方向（决定姿态）
3jerk角速度
4snap角加速度，也就是电机力矩

Quadrotor 的推力 ∝ acceleration，往上每求一次导，就离电机更近一层。最小化 snap 就是让电机指令最平滑。这个对应关系来自 differential flatness，见 10。

多项式次数由优化目标决定：最小化第 k 阶导数时，最优解是 2k−1 次多项式（变分法的 Euler–Lagrange 方程给出 x⁽²ᵏ⁾ = 0）。

目标k多项式次数每段系数常用于
minimum acceleration23（cubic spline）4简单平滑
minimum jerk356地面机器人、机械臂
minimum snap478quadrotor

框架完全一样，换 k 就换了算法。下面都用 k = 4。

04Time allocation：时间必须事先给定

Minimum snap 有一个前提：每段用多长时间 Tᵢ 必须先给出来。优化器只求多项式的系数，也就是曲线的形状，不求时间。给每段分配时长这一步叫 time allocation。

为什么不一起优化？时间进入多项式的方式是 t⁷ 这类高次项，cost 对 T 不是二次的。固定 T 之后问题才是 QP，可以一步解出。

方法做法
距离 / 平均速度Tᵢ = Lᵢ / v_avg，最简单
Trapezoidal 估计按 v_max、a_max 算每段加速、匀速、减速的时间，更准
上游直接给定CBS 已经规定每个 timestep 在哪，Tᵢ = tᵢ₊₁ − tᵢ（见 11）
时间也优化外层对 T 做 gradient descent。Mellinger & Kumar 2011 固定总时间 ΣTᵢ，只在各段之间重新分配；Richter, Bry, Roy 2013 把总时间放进 cost，取 J + k_T·ΣTᵢ。新方法如 MINCO 同时优化空间和时间

直觉T 整体变大，轨迹变慢、更保守；整体变小，会超速。T 之间的比例还会改变形状：某段时间给得太少，轨迹会在相邻段绕远路"补时间"。实验台里切换"均匀 1s"和"按距离"就能看到。

05写成 QP：变量、cost、约束

变量

m 段，每段 8 个系数，所以每个维度有 8m 个未知数，排成向量 c。

Cost：J = cᵀQc

p⁽⁴⁾(t) 是系数 c 的线性函数，平方再积分就是 c 的二次函数。对单独一段：

J = ∫₀ᵀ (p⁽⁴⁾(t))² dt = cᵀ Q c Q[i][j] = i!/(i−4)! · j!/(j−4)! · T^(i+j−7) / (i+j−7) （i, j ≥ 4） Q[i][j] = 0 （i 或 j < 4）

c₀…c₃ 不影响 snap，所以 Q 的前 4 行 4 列都是 0。整体的 Q 是各段的 Q 沿对角线拼起来的 block diagonal。

约束：Ac = b

位置约束条数
起点p = w₀，v = a = j = 0（或给定初始状态）4
终点p = wₘ，v = a = j = 04
普通中间点前一段终点 = 后一段起点 = wᵢ；v、a、j 前后相等，但取多少不规定2 + 3
停止点（如 CBS wait）p = wᵢ；两侧 v = a = j = 02 + 6

每个约束都是"某段在某时刻的某阶导数"，等于 basis(t, r) · c，其中 basis(t, r)[k] = k!/(k−r)! · t^(k−r)。所以都是关于 c 的线性方程。

数一数自由度，看清优化器到底在选什么两段（3 个 waypoint）：未知数 16，约束 4 + 4 + 5 = 13，剩 3 个自由度，正好是中间点的 v、a、j。一般地，自由度 = 3(m−1)。优化器做的事，就是替每个中间点挑一组最平滑的 v、a、j。如果中间点设成停止点，v、a、j 被固定为 0，自由度变成 0，轨迹完全由约束决定。

完整形式

min cᵀ Q c s.t. A c = b （必有） G c ≤ h （可选：corridor、速度上限，见 08）

06求解

方法 A：KKT 线性方程（只有等式约束）

带等式约束的二次优化，用 Lagrange 乘子 λ，最优条件是一个线性方程组：

⎡ 2Q Aᵀ ⎤ ⎡ c ⎤ ⎡ 0 ⎤ ⎣ A 0 ⎦ ⎣ λ ⎦ = ⎣ b ⎦

解一次线性方程就得到 c，不需要 QP solver。实验台和 Python 实现都用这个方法。

方法 B：闭式解（Richter, Bry, Roy）

把变量从"系数 c"换成"每个端点的 p、v、a、j"，记为 d。两者是线性映射 d = Mc。

  1. 把 d 分成固定的 d_F（waypoint 位置、起终点状态）和自由的 d_P（中间点的 v、a、j）。相邻段共享端点，连续性自动满足。
  2. cost 写成 J = [d_F; d_P]ᵀ R [d_F; d_P]。
  3. 对 d_P 求导并令其为 0：d_P* = −R_PP⁻¹ R_FPᵀ d_F。

未知数更少，数值上更稳定，是工程上的常用写法。

方法 C：QP solver（有不等式约束）

加了 corridor 或速度上限之后，没有闭式解，用 OSQP 这类 QP solver。

数值技巧T 较大时 T⁷ 很大，矩阵会 ill-conditioned。常见做法是每段用归一化时间 τ = t/T ∈ [0, 1] 表示多项式，求导时再乘上 1/Tʳ。实验台就是这样实现的。

08检查与修正

解出来以后，按 dt 采样检查两件事。

问题 1：超速、加速度超限

Time scaling：所有 Tᵢ 乘以同一个 α > 1。路径形状不变，速度变为 1/α 倍，加速度变为 1/α² 倍。

α = max( v_peak / v_max , √(a_peak / a_max) )

问题 2：碰撞

多项式不会沿直线走，拐角会切弯、会 overshoot，可能碰到障碍物。

方法做法保证
插入中间点在碰撞那段的中点加一个 waypoint，重新求解，迭代到无碰撞（Richter et al.）实用，无严格保证
采样点约束在若干时刻约束位置落在 safe corridor 内（不等式约束）采样点之间可能漏
Bernstein / Bézier改用 Bézier 曲线表示。曲线一定在 control points 的 convex hull 内，只要约束 control points 在 corridor 里，整条曲线都在里面严格保证，仍然是 QP
PART B

前后的 pipeline

Minimum snap 的输入从哪来，输出交给谁。

09之前：front end 和 waypoint 后处理

  • Front end：A*、JPS、RRT*、CBS 等，只保证几何上无碰撞，不考虑动力学。见 Planning 基础。
  • 剪枝：合并共线点，用 line-of-sight 去掉多余拐点。grid 上的 A* 每格一个点，直接喂进去会得到一条抖动的曲线。点少，轨迹才平滑。
  • Safe corridor（可选）：沿路径生成一串凸多边形或 box，表示允许的空间，给 08 的不等式约束用。
  • MAPF 例外：wait 点和 timestep 有意义，不能随便删，见 11。

10之后：differential flatness、feedforward 和 controller

无人机的 12 维状态、4 个输入、角速度和完整动力学，单独整理在 无人机动力学，有三个可视化实验台。

Differential flatness

如果能找到一组 flat outputs y，使系统的全部状态和输入都能写成 y 及其有限阶导数的代数函数，系统就是 differentially flat。它带来两个结论：

  1. 只规划 flat outputs 就够了。只要 y(t) 足够光滑，就一定能被实现（不考虑输入上限）。所以 minimum snap 只需规划几条多项式，不用处理完整动力学。
  2. Feedforward 直接代公式算，不需要积分或解微分方程。

完整定义、数学本质（参数化掉 ODE 约束、积分器链）和更多例子见 无人机动力学 08。

采样 p、v、a、j 对任何系统都能做；"用它们直接算出状态和输入"这一步才需要 flatness。

Quadrotor：flat outputs = (x, y, z, ψ)

推力方向 z_B = (a + g·e₃) / ‖a + g·e₃‖ ← acceleration 推力大小 f = m·‖a + g·e₃‖ 姿态 x_C = [cos ψ, sin ψ, 0] y_B = (z_B × x_C) / ‖z_B × x_C‖, x_B = y_B × z_B 角速度 h_ω = (m/f)·( ȷ − (z_B·ȷ)·z_B ) ← jerk p = −h_ω·y_B, q = h_ω·x_B, r ≈ ψ̇·(e₃·z_B) 角加速度 / 力矩 ← snap

奇异点：a = −g（自由落体）时推力为 0，姿态无定义。

r 这一项是 Mellinger & Kumar 原论文的写法，只有机身水平时才精确。按这里的 x_C 构造，精确式是 r = (ψ̇·(y_B·y_C) + p·(z_B·x_C)) / (x_B·x_C)，其中 y_C = [−sin ψ, cos ψ, 0]。机身倾斜越大、姿态变化越快，近似式的误差越大。

差速底盘：flat outputs = (x, y)

θ = atan2(ẏ, ẋ) v = √(ẋ² + ẏ²) ω = (ẋ·ÿ − ẏ·ẍ) / (ẋ² + ẏ²)

奇异点：v = 0 时 θ、ω 无定义，正好是停止点和 CBS 的 wait。做法是保持上一时刻的 θ，原地转向单独规划一段 θ(t)。

系统不 flat 怎么办

系统Flat?
Quadrotor、差速底盘、kinematic bicycle（后轴中心）、全驱动机械臂✅
带轮胎侧滑的 dynamic bicycle、很多欠驱动系统一般 ❌

不 flat 时：只把 p(t) 当 reference 交给 feedback 去追（不保证跟得上），或者改用带完整动力学的 trajectory optimization（direct collocation、iLQR），或者用 MPC。

这些方法各自在做什么映射、为什么并存、最后怎样落到电机上，见 无人机动力学 12。

Controller

按控制频率采样轨迹，PID + feedforward、geometric SE(3) controller 或 MPC 去跟踪。环境变化时 receding horizon 重规划：以当前的 p、v、a 作为新起点约束。

为什么 flatness 已经算出了输入，还需要 tracking controller，并有实验台对比开环和 feedback，见 无人机动力学 10。

SE(3) geometric controller 的原理、和 Euler angle PID 的区别，见 无人机动力学 11。

11用在 CBS / MAPF

CBS 给出 time-indexed waypoints，每个 timestep dt 走一格或原地 wait。接到 minimum snap 上：

  1. Time allocation 直接照抄 CBS：Tᵢ = tᵢ₊₁ − tᵢ。共线的几步可以合成一段，时长相加。
  2. Wait 点设成停止点：到达和离开时刻加 v = a = j = 0，期间 p(t) 保持不变，时长 k·dt（格子出现 k+1 次，就停 k 步）。停止点两侧互不影响，轨迹自然被切成几块。
  3. 到达、离开 wait 点的时刻和 CBS 完全一致，collision-free 的保证保留。

坑：把 wait 写成重复 waypoint例如 [0, 2, 2, 4] 直接丢进 minimum snap。中间点只要求连续，机器人带着速度进入 wait 点，多项式会冲出去再绕回来。实测这段的位置在 1.75 到 2.25 之间来回，偏离 ±0.25 格，可能撞上正在经过的另一个机器人。实验台的 "CBS wait" 预设就是这个例子。

  • 超速时所有机器人用同一个 α。整体慢放，相对时空关系不变，仍然无碰撞；只放慢一台会破坏这一点。
  • 执行时 wait 是同步点：等对方离开冲突格子再出发，而不是等时钟到点（Action Dependency Graph 的思路）。
  • 想更平滑：把 wait 时间并进相邻段的 Tᵢ，让机器人减速而不是停住。但中间时刻的位置会变，必须重新做多机碰撞检查，冲突处退回停止点。

12Python 实现（KKT 解法，已跑通）

min_snap_1d：约 50 行
import numpy as np
from math import factorial

N = 8   # 7 次多项式，8 个系数
R = 4   # 最小化 4 阶导数 (snap)

def basis(t, r):
    """p^(r)(t) = basis(t, r) @ c"""
    b = np.zeros(N)
    for k in range(r, N):
        b[k] = factorial(k) / factorial(k - r) * t ** (k - r)
    return b

def q_matrix(T):
    Q = np.zeros((N, N))
    for i in range(R, N):
        for j in range(R, N):
            ci, cj = factorial(i) / factorial(i - R), factorial(j) / factorial(j - R)
            Q[i, j] = ci * cj * T ** (i + j - 2*R + 1) / (i + j - 2*R + 1)
    return Q

def min_snap_1d(wps, Ts, stops=()):
    """wps: m+1 个 waypoint；Ts: m 段时长；stops: 停止点的索引（如 CBS wait）"""
    m, n = len(Ts), N * len(Ts)
    Q = np.zeros((n, n))
    for s, T in enumerate(Ts):
        Q[s*N:(s+1)*N, s*N:(s+1)*N] = q_matrix(T)

    A, b = [], []
    def add(terms, rhs):
        row = np.zeros(n)
        for s, v in terms:
            row[s*N:(s+1)*N] += v
        A.append(row); b.append(rhs)

    # 起点、终点：位置固定，v = a = j = 0
    add([(0, basis(0, 0))], wps[0])
    add([(m-1, basis(Ts[-1], 0))], wps[-1])
    for r in range(1, R):
        add([(0, basis(0, r))], 0.0)
        add([(m-1, basis(Ts[-1], r))], 0.0)

    # 中间点
    for i in range(1, m):
        T = Ts[i-1]
        add([(i-1, basis(T, 0))], wps[i])          # 前一段终点 = w_i
        add([(i,   basis(0, 0))], wps[i])          # 后一段起点 = w_i
        for r in range(1, R):
            if i in stops:                         # 停止点：两侧 v = a = j = 0
                add([(i-1, basis(T, r))], 0.0)
                add([(i,   basis(0, r))], 0.0)
            else:                                  # 普通点：导数连续
                add([(i-1, basis(T, r)), (i, -basis(0, r))], 0.0)

    A, b = np.array(A), np.array(b)
    K = np.block([[2*Q, A.T], [A, np.zeros((len(b), len(b)))]])   # KKT
    sol = np.linalg.solve(K, np.concatenate([np.zeros(n), b]))
    return sol[:n].reshape(m, N)

# 2D：x、y 各调用一次，Ts 相同
coefs = min_snap_1d(wps=[0, 2, 4], Ts=[2, 2], stops={1})
输入结果
[0, 2, 4]，不停经过 x = 2 时速度 ≈ 2.19，直接穿过
[0, 2, 4]，stops={1}在 x = 2 速度 = 0，准时停住
[0, 2, 2, 4]，重复 waypoint"等待"段位置在 1.75 ~ 2.25 之间晃，overshoot

13面试题

为什么最小化 snap，而不是 jerk 或 acceleration？

Quadrotor 是 differentially flat 的：推力对应 acceleration，角速度对应 jerk，角加速度也就是电机力矩对应 snap。最小化 snap 让电机指令最平滑。地面机器人一般用 minimum jerk 或 minimum acceleration，框架相同。

为什么用 7 次多项式？

最小化第 k 阶导数平方积分，Euler–Lagrange 方程给出 x⁽²ᵏ⁾ = 0，最优解是 2k−1 次多项式。k = 4 时是 7 次，每段 8 个系数。

Time allocation 怎么定？对结果有什么影响？

必须事先给定，固定 T 之后问题才是 QP。常用距离除以平均速度，或者按梯形速度估计；CBS 场景直接用 timestep。T 整体决定快慢，T 之间的比例决定形状，分配不当会让轨迹绕远路。进阶做法是外层对 T 做梯度下降。

怎么求解？需要 QP solver 吗？

只有等式约束时不需要：解 KKT 线性方程，或者用 Richter 的闭式解 d_P* = −R_PP⁻¹ R_FPᵀ d_F，优化的其实只是中间点的 v、a、j。加了 corridor 或速度上限这类不等式约束才需要 QP solver。

轨迹超速或者撞到障碍物怎么办？

超速：所有 T 乘以同一个 α，速度变 1/α，加速度变 1/α²。碰撞：在出问题的段中点插一个 waypoint 重新解；或者加 safe corridor 约束，用 Bézier 表示时，约束 control points 就能保证整条曲线在 corridor 内。

CBS 给的 waypoints 里有 wait，minimum snap 怎么处理？

把 wait 点设成停止点：到达和离开时加 v = a = j = 0，期间位置不变，时长是 k·dt；移动段的 time allocation 直接用 CBS 的 timestep。这样时间和 CBS 完全一致，collision-free 保留。不能把重复 waypoint 直接丢进去，否则会 overshoot。

Minimum snap 只能用在 differentially flat 的系统上吗？

多项式规划和采样对任何系统都能做。但"只规划位置就保证可实现"和"直接代数算出姿态和推力"依赖 flatness。系统不 flat 时，只能把轨迹当 reference 用 feedback 去追，或者改用带完整动力学的 trajectory optimization 或 MPC。
